# T51a Learning

1. shfmt formatting is not always whitespace-only at the token level: it removes redundant line-continuation backslashes and expands semicolon-compressed commands while preserving shell semantics. Therefore `git diff -w` can be nonempty even for exact formatter output.
2. Plain `bash -n` does not parse Bats `@test` syntax. When local Bats execution is forbidden, a clean shfmt parse is the appropriate static syntax evidence for `.bats` files.
3. In zsh, `status` is a read-only special parameter; validation loops should use a task-specific name such as `syntax_rc`.

Apply these findings to future repo-wide shell formatting gates and validation task templates.
