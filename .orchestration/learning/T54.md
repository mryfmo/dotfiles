# T54 Learning

1. The recovery hook already performs one blocking drain before packet construction; recording after construction must use `spool_event()` only, leaving settlement to a later drain.
2. `normalize_hook_payload()` is the smallest safe admission point because it reuses redaction, the existing 240-character summary cap, bounded canonical detail encoding, UUID/timestamp generation, and hashing.
3. The existing integrity mechanism hashes the stored canonical `detail_json`. It cannot preserve a hash of the uncapped raw packet without widening the normalization contract, so T54 documents and tests stored-detail hashing.
4. Recording after `build_recovery_context()` prevents self-recursion naturally. No event filtering or recovery special case is needed; a later recovery sees the prior event through normal recent-activity selection.

Apply these findings to future model-visible audit events and recovery-hook changes.
