# T56b Learning

1. A recurring lifecycle hook cannot derive a logical-session baseline from its invocation clock; every refire moves the comparison boundary and makes prior mid-session changes invisible.
2. The stable public identity is `session_id`. Persist its first observed epoch and ignore the event `source` for baseline selection so startup/resume/clear/compact share one comparison window.
3. Hashing the public identifier before using it as a filename gives one file per session without allowing path traversal or leaking raw session IDs into directory entries.
4. A dedicated user-private state directory, restrictive modes, a file lock, bounded seven-day pruning, a bounded payload, and silent hook-local failure containment preserve the existing five-second non-blocking contract.
5. Reusing the existing `check --since` path is smaller and safer than duplicating staleness detection for hooks; it also pins doctor/operator behavior unchanged.
6. Fake-HOME executable tests should use an already-resolved absolute interpreter when ambient `python3` is a mise shim, otherwise tool trust evaluation can fail before the product runs.

Apply these findings to future hooks that refire within one logical session: derive durable state from the event's stable public ID, not the callback timestamp.
