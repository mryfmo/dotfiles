# T58 Learning

1. A manifest is necessary but not sufficient deletion authority: fixed removable roots prevent a tampered recorded path from turning an intended inverse into arbitrary filesystem deletion.
2. Every recorded path must be preflighted before the first `rm`; checking inline can otherwise create partial removal when a later path is unsafe.
3. Realpath-normalizing parent components while preserving the final path component is the small safe rule that blocks intermediate-symlink escapes but removes a recorded final symlink rather than following it.
4. Installed plugin owners do not share one inverse vocabulary: Claude uses `uninstall`, Codex uses `remove`, Crit currently has no uninstall, and shared configuration must be excluded from Crit's guarded data fallback.
5. Doctor needs a three-way distinction: source/allowlist means silent ACCOUNTED, manifest-only means actionable STALE, and unowned means ORPHAN/manual review. A two-class model would either hide stale entries or falsely call them unmanaged.
6. In zsh, lowercase `path` is the array backing uppercase `PATH`; validation loops must use task-specific names such as `artifact_path` or later commands disappear from lookup.

Apply these findings to T59 repair planning and T61 E2E-3'; keep the live install → remove → doctor-clean cycle out of unit/fake-HOME scope.
