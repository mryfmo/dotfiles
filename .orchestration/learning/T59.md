# T59 Learning

1. GNU make already exports command-line variables such as `make doctor REPAIR=1` to recipe processes; a propagation test is smaller and more truthful than redundant Makefile plumbing.
2. Repairability must be narrower than installability: only a manifest-present step with a missing recorded path is broken. Missing optional step records and version differences belong to install/upgrade flows, not doctor.
3. An existing `BASH_SOURCE` main guard makes a function-oriented updater safely sourceable, but the caller still needs a fixed function whitelist, strict argument reconstruction, and the same mise PATH setup.
4. Parsing the checker's already-rendered, pinned findings into actions preserves the no-REPAIR output contract and ensures repair cannot act on an undetected target.
5. One initial scan plus one convergence scan is enough: repeated reconciliation loops hide non-idempotent repairs and weaken termination guarantees.
6. WARN classification is a useful hard boundary. Filtering WARN before action mapping keeps T58 STALE/ORPHAN output visible while making automatic removal structurally unavailable.

Apply these findings to T61 E2E-3': intentionally remove one managed file, run `make doctor REPAIR=1`, prove one targeted action and a clean second scan, then restore/verify the live environment.
