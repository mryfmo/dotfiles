# T59b Learning

1. An action can be structurally mapped yet operationally absent: if a headless subprocess prompts for a TTY and returns nonzero, no repaired line appears and the convergence scan sees the original drift.
2. Source-derived single-target repairs can safely use `chezmoi apply --force` because the normal read-only scan first identifies the exact target; forcing a broad tree would violate the least-disruptive contract.
3. One shared command prefix prevents flag drift across missing-tree and ordinary missing/content mappings without adding a repair abstraction.
4. Legacy runtime tolerance must distinguish exact files from directory prefixes. A separate equality set avoids accidentally tolerating `messages.db.backup` or descendants.
5. A realistic executable-prefix fixture catches both deployed-name mapping and restored execute mode, which a mocked failure-string-only test misses.
6. Live E2E remains necessary after unit-level reconciliation work: T59's mock convergence could not expose chezmoi's deleted-target TTY behavior or historical on-disk layout residue.

Apply these findings to future repair actions: validate the real headless command behavior, keep force scoped to one detected target, and express file exceptions as exact equality rather than prefix patterns.
