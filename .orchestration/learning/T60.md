# T60 Learning

1. Backward-compatible protocol growth is clearest when optional fields are documented after an unchanged required-field block, not inserted into that block.
2. The useful boundary is persistence outside the repository working tree, not merely “a write”: allowed source/artifact edits remain ordinary task outputs rather than effects.
3. Short effect IDs stay auditable only when the report binds each ID to one concrete reverse-map form: installed-manifest step, explicit removal procedure, or irreversible rationale.
4. Acceptance verification closes the declaration loop; worker reporting alone cannot establish that a claimed inverse actually exists.
5. `effects=none` is a useful report-level dogfood declaration, but the optional RESULT field remains required only for tasks that actually created persistent external effects.

Apply this contract to T61 acceptance and future AGMSG task/result templates without changing existing v1 required fields.
