# T62 Learning

## Triage

1. The stored fingerprint file is an envelope (`version`, `gitCommitHash`, `generatedAt`, `files`), while the auto-update prompt's illustrative patch snippet assumes a flat dictionary. Reusing core `loadFingerprints`, `buildFingerprintStore`, and `saveFingerprints` preserves the real schema and avoids truncation.
2. Deterministic ignore filtering materially changes the decision: 31 changed source paths became 28 after the built-in `vendor/` exclusion. Classifying before filtering would analyze vendored code contrary to the baseline scan.
3. Merge arithmetic is a useful loss detector for generated graphs. Exact equality (`old - pruned + fresh = merged`) caught the full 55-node/101-edge replacement boundary without needing a second semantic review.
4. `meta.analyzedFiles` corresponds to unique analyzed file paths, not the number of file-level node IDs; one file may contribute multiple file-level schema/table/resource nodes.
5. Core `validateGraph` returns a Zod safe-parse result with `success`, not `valid`.

## Decision

Keep this learning task-local. The reusable fingerprint preservation rule is already documented by the Understand-Anything 2.9.4 auto-update prompt, so no new project rule or learn-index entry is promoted.
