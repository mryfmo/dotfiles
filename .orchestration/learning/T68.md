# T68 learning triage

## Signals

- A sequential RPC worker can correlate id-less `agent_end` safely by allowing
  one active prompt and requiring its matching successful response first.
- The bridge boundary should own task transport and liveness only; composing a
  worker RESULT in the bridge would erase worker authorship and error context.
- Hook-oriented inbox cooldown/identity defaults need explicit bridge-only
  controls at known turn boundaries, not a second database reader or sleep poll.

- Decision fact: recorded in CompactionDB as project decision UUID

- Implementation: the bridge, Pi registration seam, exact boundary checks, and
  fake RPC/bus cases pin these invariants.
- Rule/skill promotion: not proposed. The short Pi orchestration paragraph and
  repository tests are the narrow durable homes for this behavior.
