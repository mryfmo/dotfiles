# Learning: dotfiles-T128-v0-main-tests-a01

Candidates only; nothing promoted.

1. `mktemp -d` on macOS ignores `$TMPDIR` and uses `/var/folders/...`, which the Claude Code sandbox denies. A script that may run in a sandboxed seat passes a template: `mktemp -d "${TMPDIR:-/tmp}/<name>.XXXXXX"` (Linux honours it too). Validated: the scenario tests failed with `mkdtemp failed ... Operation not permitted` until the template was added.
2. Bash 3.2 (macOS `/bin/bash`, which `bash` resolves to on this host) treats an empty array expansion (`"${a[@]}"`, `${a[*]}`) as unbound under `set -u`; `${#a[@]}` is fine. A newline-separated string read with `while IFS= read -r` avoids it. Validated with `/bin/bash -c 'set -u; a=(); echo "${a[*]}"'` → `a[*]: unbound variable`.
3. `make unit-test` runs plain `uv run python` with no PyYAML, so a unit test of PyYAML-backed code calls it through `uv run --no-project --with pyyaml` as a subprocess, as the scripts do. Validated: the in-process form errored 10 times under `make unit-test`'s interpreter.
4. A job that runs main's `tests/unit` needs every tool the `test` job installs for them: the first main-tests run failed five modules on a missing `chezmoi` (jq and zsh were already there). Rule candidate for V1+: the tool list main's modules need lives in one place both jobs read.
5. The Codex Bot reviewed every recent task PR opened ready (#312, #314, #315 within about 7 minutes); this task opens a draft, which the connector may not review.
6. A harness that runs trusted tests over an untrusted tree must keep that tree off the import path of the runner itself: `python -m unittest` from the tree's root puts the root first on `sys.path`, and any directory on `PYTHONPATH` the tree can write to (here `tests/unit`, kept by an overlay that only replaces files) can shadow `unittest`. Replace the directory wholesale, run with `python -P`, and pass `uv --no-config`. Validated: a planted `unittest.py` with `raise SystemExit(0)` made `python -m unittest test_t` exit 0 without running the test; `python -P` ran it and failed.
7. uv executes every candidate interpreter it discovers, including a `.venv/bin/python` in the working directory, even under `uv run --no-project`, `--with` and `--isolated`; only an explicit `--python <absolute path>` (here resolved with `cd / && uv python find --no-config`) skips the probe. Validated with a planted interpreter that appends to a marker file (validation §R). Rule candidate: any uv call over an untrusted tree passes `--python`.
8. A command substitution inside `[ ... ]` does not trip `set -e`, so a helper that fails there reads as empty output. Assign first (`x="$(helper)"`), then test. Validated: the round-0 harness reported "no script change" when uv could not fetch PyYAML.
