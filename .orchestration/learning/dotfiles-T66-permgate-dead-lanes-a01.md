# dotfiles-T66-permgate-dead-lanes-a01 — learning triage

1. **A schema bump fails closed during a split deploy.** The new permgate rejects the schema-2 live policy (`layer: config-error`, empty stdout → native prompt) until `chezmoi apply` installs both files. That is the intended fail-closed direction. Any validation command that omits `PERMGATE_POLICY_PATH` measures the live policy, not the change. Candidate rule: permgate smoke checks in task files pass `PERMGATE_POLICY_PATH=home/dot_agents/permgate-policy.yaml`. Status: candidate.
2. **Dead-lane deletion has hidden test pins.** `tests/install/common/lifecycle.bats` grep-pinned classifier fields that only CI bats exercises, and `home/dot_config/codex/AGENTS.md` was the Codex mirror of the Claude rule sentence. Grepping the whole tree for the deleted keys and env names (`llm_enabled`, model IDs, `PERMGATE_CODEX_COMMAND`, `classif`) before dispatch would have put both in `allowed_files`. This extends the existing "ground allowed_files by grepping" playbook step to deletions.
3. **Sandboxed `pgrep -f` matches its own command line.** The pattern is part of the sandbox wrapper's argv, so use `pgrep -af '[c]rit _serve'`. A sandboxed pgrep also cannot see processes outside its pid namespace; run the Crit-server check unsandboxed.
4. **Built-in removal check:** a `bash -c "$1"` helper wrapper is refused even when it removes nothing, so capture validation output with inline `{ …; } >> file` blocks.
