# M-20261014-02

- **Evidence:** the token read `eaac8e4bd03cda1542730977f3a9bd78dba49eb6e0d2f7be2d7baf73a0d8f1c9`; the pre-amendment copy on origin/main hashes to `eaac8e4bd03cda154273097736944b3762581f872d5f5fbcdca67650b43236ea` (the first 24 hex digits agree, the rest was typed). `scripts/orchestrator/dispatch.sh` recomputes `<name>_sha256` from `<name>_file=` but checks a `previous_<name>_sha256` only as 64 lowercase hex, so nothing would have stopped the token; the line itself never left, because `dispatch.sh` refused its sixth argument (the a05 acceptance record is not the review task's record) before sending, and the orchestrator's `echo "seat dispatched"` printed anyway. The only in-line check was `grep -c 'eaac8e4bd03cda1542730977'`, which matched the typed prefix. The correction PING (01:20:24Z) therefore reached the seat before any TASK; the TASK was re-sent after 01:21Z with the token computed from `git show origin/main`.
- **Detection and why not earlier:** the previous-hash field has no file sibling in the line grammar, so nothing recomputed it; the orchestrator remembered the prefix from a RESULT line on the bus and completed it from memory, the exact act run-not-recall forbids.
- **Root cause:** a line field with no recomputation path was filled by hand inside a long composite command instead of from `git show origin/main:<file> | shasum -a 256` in the same script.
- **Should have been:** `PREV=$(git show origin/main:"$T" | shasum -a 256 | cut -c1-64)` in the dispatch command, and dispatch.sh refusing a `previous_<name>_sha256` that differs from the hash of origin/main's copy of `<name>_file` (a line whose `<name>_file` has no copy on main carries no previous token).
