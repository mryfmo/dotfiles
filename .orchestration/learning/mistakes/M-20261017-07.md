# M-20261017-07

- **Evidence:** `.agents/worklog/orchestrator-glue/386-chain2.log` and `386-chain3.log` (the `json.decoder.JSONDecodeError` traceback from `fill_sweep.py` line 57, then `sweep gaps: 6`); the comments file `dotfiles-T128-chain-review-scripts-followup-a04-pr-comments.json` at 23 bytes, `od -c` showing `033 [ 1 ; 3 7 m [ 033 [ m ...` around an empty array; `env` in the orchestrator's shell: `CLICOLOR_FORCE=1`, `FORCE_COLOR=1`.
- **Detection and why not earlier:** the chain's prep step runs `gh api ... > file` and then `fill_sweep.py ... || true`, so the parser's crash was swallowed and the symptom appeared two steps later as sweep gaps that looked like missing dispositions; chain 1 (the previous session, a shell without the forcing variables) had filled the same six items, so the gap count, not the parser, was suspected first. The first fix set `NO_COLOR=1`; gh computes `colorEnabled = CLICOLOR_FORCE forced || (not disabled && tty)`, so a forced color beats `NO_COLOR` and the third run failed the same way.
- **Root cause:** a shell that forces color for humans (`CLICOLOR_FORCE=1`, `FORCE_COLOR=1`) is also the shell the orchestrator's glue runs gh from, and gh colors JSON when forced even without a terminal; nothing in the glue or the tracked orchestrator scripts pins the color variables, and the fill step hides its parser's exit status.
- **Should have been:** every script that parses a tool's output exports `CLICOLOR_FORCE=0 FORCE_COLOR=0 NO_COLOR=1` at its top (the chain's entry so every child inherits it), and a parse failure stops the chain with the parser's message instead of `|| true`.
- **Corrections:** C-62: the glue's `integrate-pr.sh` and `integrate-prep.sh` export the three variables (applied 12:5xZ, chain 4 of #386 runs with it); the tracked scripts of plan 023 PR F4 (`integrate-seat.sh`, `result-precheck.sh`) export them from their first line and fail on a parser error (F4 amendment 1); the existing tracked chain scripts inherit them from `integrate-seat.sh` once it is their caller.
