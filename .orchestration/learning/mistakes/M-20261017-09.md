# M-20261017-09

- **Evidence:** the aside directories `.agents/worklog/orchestrator-glue/ff-aside-144743`, `-144744` (the good copies, 59 lines for the a04 record) and `-144745` (27 lines, the committed version); the chain logs `392-chain1.log`, `394-chain1.log`, `389-chain1.log`, `387-chain1.log`, `390-chain1.log`, `378-chain4.log`, `375-chain7.log`, each starting with the ff step at 14:47:4xZ; the comparison run of 16:5xZ (68 files with any difference against any aside copy, nine of them against the last pre-race copy).
- **Detection and why not earlier:** the helper prints `kept newer local: <file>` when it copies an aside copy back, and the losing run's copy was the committed version, so the log read like a success; the boundary-20 masking and validation check secrets and shape, not content; the records are read by humans and auditors only at integration time. a007 noticed because its owner task said "the record is the source" and the record had no section.
- **Root cause:** `ff-main-safe.sh` is not reentrant: its aside directory is keyed by the second, its `git checkout -- <modified>` restores the committed version while a concurrent run is still copying aside, and the concurrent run then copies the committed version back over the good one. The parallel chains (D-parallel-chains) made it concurrent for the first time.
- **Should have been:** one fast-forward at a time (a lock), a unique aside directory per run, and a check that nothing shrank (a file whose line count falls between the aside copy and the result is an error, not a `kept newer local`); the parallel-chains decision should have listed the shared state each chain touches (the main checkout's records, the review worktree) before running seven at once.
- **Corrections:** C-64: the glue helper takes a `mkdir` lock and a `mktemp` aside directory (applied 2026-10-17 16:5xZ); the nine files are restored from the pre-race aside copies by the prefix rule (every line of both versions kept, the block's dispatch lists merged) and the fix commit goes on the boundary-21 branch; the tracked form (the lock, the shrink check and the shared-state list in the parallel procedure) is a row for the F4 lineage's owner task, since `integrate-seat.sh` is where the fast-forward will live.
