# U104 A brief that judges an open-ended input names its closing mechanism before round 1 (plan P-11, handoff R1)

GOAL
Thirteen `treadmill` and `premise` rows in `decisions.tsv` share one shape: a hand-written parser, supervisor or heuristic over an open-ended input, passed by a fresh auditor once per round until the mechanism changed to an AST walk, one strict parser module, an exact-form allowlist, or removal. The change always came after three or more rounds and never at brief time (handoff `02-audit-treadmill-analysis.md`). This unit makes the brief name the mechanism before the first TASK, as a script, so it runs on every brief.

SCOPE
One branch `feat/brief-closure-check` from `origin/main`. May write: new `scripts/orchestrator/brief-check.py`; new `tests/unit/test_brief_check.py`; `home/dot_agents/skills/hcom-orchestration/SKILL.md` step 1 only (one sentence); `scripts/orchestrator/README.md` (one new row or short subsection for the script). Nothing else. Read `handoff/03-remediation-spec.md` R1 in the store for the full spec and `briefs/U46-dead-uninstall-functions-removed.md` as the brief grammar.

CHANGE
1. `brief-check.py` (shebang `#!/usr/bin/env -S uv run --no-project python -I`, or plain `python3 -I` if the repository's other orchestrator Python uses that; match `regime-ci.py`) reads one brief file and exits 0, 1 or 2. Exit 2 on usage or an unreadable file (never read as clean). Exit 1 when the text of the GOAL, CHANGE or CONTEXT sections holds any trigger term as a whole word, case-insensitive, and the brief has no `CLOSURE` section, or has one whose body does not name exactly one of the four mechanisms `ast`, `parser-module`, `allowlist`, `remove` (a name may be followed by a colon and free text on the same line). The trigger terms are one table in the script, a tuple of rows (term, one-line reason), so a later unit adds a row: shell, tokenize, tokenizer, parse, parser, regex, hook, worktree, config, path, process, signal, supervisor, curl, wget, heredoc, quote. Exit 0 otherwise. The decision prints one line naming the section and the term that fired, or `closure: <mechanism>`.
2. Sections are recognised as the brief grammar writes them: a line that is exactly the upper-case section name (GOAL, SCOPE, CHANGE, CONTEXT, ACCEPTANCE, VERIFY, TIMEBOX, FORBIDDEN, REPORT, STANDING, CLOSURE), body until the next such line.
3. Tests: each trigger term alone (in GOAL) makes a brief without CLOSURE exit 1; a term inside SCOPE or FORBIDDEN alone does not; a brief with each of the four mechanisms exits 0; a CLOSURE naming two mechanisms, or an unknown word, or empty, exits 1; a brief with no trigger term and no CLOSURE exits 0; an unreadable file exits 2; a brief with no sections at all exits 1 with a message. Tests invoke the script as a subprocess with `-I`.
4. SKILL step 1 gains this sentence after the sentence that names the brief file: "Run `scripts/orchestrator/brief-check.py briefs/U<n>-<slug>.md` and send no TASK while it exits non-zero; a brief whose unit judges an open-ended input names the closing mechanism in a `CLOSURE` section (`ast`, `parser-module`, `allowlist` or `remove`)." Check whether a unit test pins the SKILL text (`grep -rn "hcom-orchestration" tests/unit/`) and update that test in the same commit if it does.
5. The README gains a subsection "brief-check.py" under the orchestrator section that exists, five lines at most.

ACCEPTANCE
1. The tests pass. 2. The script run over every file in `.orchestration/orchestrate/regime-cutover/briefs/*.md` prints `<file> <exit code>` per file in the PR body under Verification (most existing briefs will exit 1; that table is evidence the rule would have fired, not something to fix). 3. The PR body Contract states the closed-world property: a brief passes only by naming exactly one mechanism or by holding no trigger term.
