# U105 Every shfmt JSON walker proves on each run that the parser still produces the nodes it reads (plan P-23)

GOAL
`shfmt --to-json` has no stability statement for its typed JSON and the wire format changed in 3.6.0 and 3.14.0 (mvdan/sh CHANGELOG, read 2026-10-28). The repository's AST walkers read fields with `.get()`, so a renamed or restructured field after a shfmt bump yields no nodes and therefore no findings, and the lint passes silently. That is a producer read without checking it produced what the reader expects (standing order 21) inside the fix for the hand-written-parser class.

SCOPE
One branch `feat/shfmt-json-contract` from `origin/main`. May write: new `scripts/ci/shfmt_json_contract.py` (an importable module and a CLI), new `tests/fixtures/shfmt-json/contract.sh` (and any sibling fixture files you need under that directory), new `tests/unit/test_shfmt_json_contract.py`, and every existing walker over `shfmt --to-json` output so it calls the contract first. Find the walkers with `grep -rln -- '--to-json' scripts/ home/ tests/unit/ | sort`; expected at least `scripts/ci/masked-dirname-check.sh` (its embedded Python), the enforce-uv hook (U76) and `scripts/lint-comparisons.py` (U62). If a walker lives in a chezmoi-managed file under `home/`, edit the source there and run the generator so any pinned copy regenerates. Nothing else.

CHANGE
1. The module parses `contract.sh`, one fixture that holds every node kind the walkers read (at least: a `CmdSubst` nested inside another, backquotes, a `DblQuoted` and a `SglQuoted` part, a `Lit` with a backslash, a quoted heredoc delimiter and an unquoted one, a `Redirect` with `2>`, a `Pipeline`, a `FuncDecl`, an `ArithmExp`, a `ProcSubst`), with the pinned shfmt (`scripts/ci/pinned-tool-version.sh home/dot_mise/config.toml shfmt` is the version check the repository uses) and `-ln bash --to-json`. It asserts the exact `Type` strings and the field names each walker reads, as one table in the module (node type, fields), and exits 2 with the first mismatch named on any difference. The table is the single source: each walker imports or reads it, no walker keeps its own field names.
2. Each walker calls the contract before its walk, counts the nodes of each kind it reads, and exits 2 when a run over a non-empty file set visited zero nodes of a kind the fixture produced (so "no findings" is distinguishable from "saw nothing"). `exit 2` is "could not judge", never "clean".
3. The two heredoc caveats recorded in `scripts/ci/masked-dirname-check.sh` lines 14 to 19 (ANSI-C escaped delimiter, partly quoted delimiter) become fixtures with their expected exit status in the test.
4. The test captures the JSON of the fixture once (as a file under the fixtures directory, regenerated by a documented command in the test), and asserts that replacing `"Type"` with `"type"` in that capture makes the contract fail, and that a fixture with one known nested substitution yields exactly one finding at the expected line from `masked-dirname-check.sh`.

ACCEPTANCE
1. `make shellcheck` (or the repository's lint target that runs the checker) is unchanged for a clean tree: zero findings, exit 0. 2. The contract test passes and its negative case fails as described. 3. The PR body Contract says: every walker refuses (exit 2) when the parser output does not match the pinned node table, and when it saw no node of a kind the fixture produced.

TIMEBOX
90 minutes.

FORBIDDEN
No regular expression over shell text in any walker. No fallback to "no findings" when parsing fails. No change to what any walker reports on a conforming tree.
