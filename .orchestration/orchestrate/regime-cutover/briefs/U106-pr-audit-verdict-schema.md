# U106 The audit lever reads its verdict as JSON through `--output-schema`, not from a free-text last line (plan P-24)

GOAL
Codex CLI documents `--output-schema <file>` ("request a final response that conforms to a JSON Schema") together with `-o/--output-last-message` for non-interactive runs (https://developers.openai.com/codex/noninteractive, read 2026-10-28), and codex-cli 0.164.0 on this host has the flag (measured). `pr-audit.sh` today asks the model to end with exactly one line `Verdict: correct|incorrect|blocked` and parses that line by hand. The verdict, its findings and what was reproduced become structured data the ledger row is written from.

SCOPE
One branch `feat/pr-audit-verdict-schema` from `origin/main`. May write: `scripts/orchestrator/pr-audit.sh`; a new schema file beside it, `scripts/orchestrator/pr-audit-verdict.schema.json` (if the lever must find it at run time from `~/.local/bin/common`, read how the lever locates its manifest, `lever_self_check`, and either embed the schema in the script as a heredoc written to the run directory or install the schema through the generator the same way the lever is; embedding is simpler and preferred); the lever's tests (`grep -rln pr-audit tests/unit/` to find them, including any fake codex fixture); `docs/*.md` only where the `Verdict:` line is described; and the regenerated files `home/dot_agents/agent-config.yaml`, `scripts/generated-agent-outputs.json`, `home/dot_local/bin/common/executable_pr-audit.sh` through `uv run --no-project --with pyyaml scripts/generate-agent-configs.py` (never by hand). Also pass `--ignore-user-config` and `--ignore-rules` on the `codex exec` line if and only if a dry run on this host shows codex-cli 0.164.0 accepts them (`codex exec --help` lists both, measured 2026-10-28) and the run still selects the `audit` permission profile from the scratch `CODEX_HOME` (the self-check at the top of the lever must still find `default_permissions = "audit"`; if `--ignore-user-config` would skip the scratch config, do not pass it and say so in the report).

CHANGE
1. Schema (draft 2020-12 or what the vendor example uses): an object with `verdict` (enum `correct`, `incorrect`, `blocked`), `findings` (array of objects with `priority` enum P0..P3, `confidence` enum high/medium/low, `path` string, `line` integer or null, `rationale` string, all required), `reproduced` (array of strings), `notes` (string, optional), `additionalProperties: false`, `required` for the three main keys.
2. The lever writes the schema to the run directory, passes `--output-schema <that file>` and keeps `-o <verdict file>`. After the run it parses the verdict file with `python3 -I -c` (or `jq` if the lever already requires jq; check) and refuses (exit 1, naming the file) on invalid JSON, a missing key, an unknown verdict value, or a finding without the required keys. The decision rule "any P0, P1 or P2 finding means incorrect" is applied by the lever from the data, and a mismatch between `verdict` and the findings is a refusal, never silently corrected.
3. The lever prints the same two stdout lines it prints today (the verdict file path and `Verdict: <value>`), so `pr-audit.sh` callers are unchanged, and writes a human-readable `verdict.md` beside the JSON (the findings as a list, then `Verdict: <value>`) so the store's `verdicts/U<n>-<sha8>.md` convention keeps working. The prompt text that asked for the last-line format is replaced by one that names the schema fields.
4. Tests: the existing fake codex fixture gains modes that write (a) a conforming file, (b) a file with `verdict: correct` and one P2 finding, (c) invalid JSON, (d) an unknown enum value, (e) nothing; assert exit codes and the stdout lines. Keep every existing test passing.

ACCEPTANCE
1. The lever's test module passes. 2. `cmp scripts/orchestrator/pr-audit.sh home/dot_local/bin/common/executable_pr-audit.sh` reports no difference and the manifest pin matches (generator `--check` clean). 3. The PR body Contract states that the verdict is accepted only from a schema-conforming file and that a verdict contradicting its findings is refused. 4. ShellCheck 0.11.0, shfmt and the dirname check pass on the lever.
