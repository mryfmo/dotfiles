# U112 Every producer read in the levers goes through one fail-closed reader library, and a lint refuses a command substitution outside the accepted grammar (plan P-21, research 01 section 2)

GOAL
Standing order 21 (a producer's status is read, a failed read is never an absence, every such decision has a failure-injection test) is text today. ShellCheck's `check-extra-masked-returns` never flags a plain `x=$(producer)`, never looks at a file redirection, exempts `echo`, `dirname`, `basename`, `printf`, `set` and `shopt`, and sees nothing when a producer exits 0 on a partial failure (`git ls-files` with an unreadable directory warns, exits 0 and drops entries; `git config -f` on an unreadable file exits 1 with only a warning, the same status as "unset"; measured on git 2.56.0, research 01 sections 1.2 and 2.3). One reader with three outcomes exists, `read_config` in `scripts/orchestrator/records-sync.sh:313-322`, and it does not look at stderr. `inherit_errexit` does not exist on bash 3.2, which is `/bin/bash` and the `bash` on PATH on this host while four of the five levers start with `#!/usr/bin/env bash` (plan section 1 item 4), so the rule cannot rest on it. This unit makes the rule checkable: one library of readers that each map a producer to exactly three outcomes and name the file or key, one shfmt JSON lint over the grammar of command substitutions with a table of status-blind producers as data, and a test that every reader has a failure-injection test (plan D2, P-21; research 01 section 2.5).

2. The lint `scripts/ci/producer-status-check.sh`, in the shape of `scripts/ci/masked-dirname-check.sh` (a bash wrapper, the walk as embedded Python under `python3 -I`, `sys.path` pointing at `scripts/ci`): it runs `shfmt_json_contract.verified_trees()` before any file is read, walks the contract fixtures with its own traversal and exits 2 when that walk visited no `CmdSubst` and no `Assign` there, parses each listed file with `shfmt -ln bash --to-json`, and refuses (exit 2, the list never read as clean) on no file, an unreadable or unparsable file, a missing shfmt or python3, a contract mismatch, or a malformed table row. Findings are `file:line: <rule>: <message>`, exit 1. The rules, each one closed set:
   a. Grammar of command substitutions. A `CmdSubst` node (`$(…)` or backquotes) is accepted only when it is the whole value of an `Assign` of a `CallExpr` that has no `Args` (the `Word`'s only part, or the only part of a `DblQuoted` that is the `Word`'s only part), and that statement is either the `Cond` of an `IfClause` or `WhileClause` (negated or not), or the `X` of a `BinaryCmd` whose `Op` is `||` and whose `Y` is not a call of `true`, `:` or `false`. Every other position is a finding at the line where the substitution opens: an argument, a `DeclClause` (`local`, `export`, `declare`, `readonly`), a redirect target, a heredoc body, a `[[ ]]`, an arithmetic expansion, a `for` word list, a `case` word, the whole value of a plain assignment whose statement is none of the two positions, and a substitution nested inside another (which `masked-dirname-check.sh` also reports).
   b. Status-blind producers. `scripts/ci/status-blind-producers.tsv` has a header and the columns `words`, `measured`, `source`; the initial rows are `git ls-files`, `git config -f` (also `--file`), `find` and `ls`, each with the measured behaviour and the research section (01 sections 1.1, 1.2, 2.4). A `CallExpr` whose leading argument words are bare `Lit`s matching a row must carry a `Redirect` with `Op` `>` and `N` `2` to a word that is neither `/dev/null` nor a descriptor, and a later statement of the same `Stmts` list must be a `TestClause` of the form `[[ ! -s <that word> ]]` (the words compared by their parts, not by text); a statement whose command word is `read_listing` satisfies the rule by construction. Anything else is a finding naming the row.
   c. Prologue. A file whose top-level statements do not run `set -euo pipefail` (that exact `CallExpr`) before the first statement holding a `CmdSubst` is a finding at line 1 naming the expected statement; `pr-audit.sh:133-137` passes (its `if` holds no substitution). The `shopt -s inherit_errexit` half of research 01 section 2.5 CHANGE (2) is not adopted: plan section 1 item 4 and D2.
   d. `read` from a file. A `CallExpr` whose command word is `read` and that carries its own `Redirect` with `Op` `<` is a finding naming `read_file` (`while … read …; done < file` has the redirect on the loop and is not matched).
   e. Exemption and enforcement. `# producer-status: allow <reason>` on the statement's line exempts that statement from rules a, b and d; an allow comment with no reason is itself a finding. The enforced file set is a test, not a Makefile target (as `tests/unit/test_lint_comparisons.py::test_the_changed_files_are_clean_against_the_baseline` enforces `lint-comparisons.py`): `tests/unit/test_producer_status_check.py` runs the lint over the library and the five levers and asserts exit 0 with no output.
