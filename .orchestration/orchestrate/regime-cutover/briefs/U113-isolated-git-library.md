# U113 One isolated git for every lever, and a lint that refuses any other git call (plan P-22, research 01 section 1)

GOAL
Git documents no single switch that removes all configuration from a command: `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM` and `GIT_ATTR_NOSYSTEM` are per-level switches, `GIT_CONFIG_PARAMETERS` and `GIT_CONFIG_COUNT` override the repository from the environment, and the repository level has no off switch at all (doc and measured, research 01 sections 1.1 and 1.5). The repository answers that with four hand-made wrappers carrying four flag sets, each hardened by its own audit rounds: `git_plain` and `git_scratch` (`scripts/orchestrator/records-sync.sh:184-199`), `git_safe` and `git_tree` (`scripts/orchestrator/pr-audit.sh:263-277`), the `git()` function of `hcom-seat` (lines 1061-1064) and `GIT_C` in `scripts/lint-comparisons.py:88-89`. None is complete (research 01 section 1.4 item 4), and beside them bare `git` runs in `pr-merge.sh:206-211`, `pr-threads-check.sh:157-171` and `:237`, `pr-body-edit.sh:148-149`, and the audit fetch at `pr-audit.sh:863-865`, which sets no global-config switch, so a `url.<base>.insteadOf` in the operator's global config would redirect where the audited head is fetched from (inferred from reading the line, not measured). That is root cause RC1 in the small: "the set of flags that isolates git" is an open-ended input judged by hand four times. This unit makes it one function with one data list, one environment scrub, and a lint that refuses any other `git` word in the levers (plan D3, P-22; research 01 section 1.6).
