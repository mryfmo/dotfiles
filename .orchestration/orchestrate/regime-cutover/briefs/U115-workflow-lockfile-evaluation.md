# U115 Evaluate the GitHub Actions workflow lockfile against the SHA pins and triage Dependabot #548 and #549, delivered as one records-only evaluation file (plan P-35, research V4-4)

GOAL
Every `uses:` in the eleven workflows is a full commit SHA with a version comment (`tests/unit/test_workflow_security.py:133-143`, `test_external_actions_use_full_commit_shas`); six distinct actions are pinned this way (research `03-ci-reliability.md` section 2.4). The pins cover the direct references only: what `actions/checkout` or `codecov/codecov-action` themselves `uses:` is pinned by nothing the repository controls. GitHub's workflow dependency lockfile (`.github/workflows/actions.lock`, generated by the `gh actions-lock` extension, public preview since 2026-10-14) records `ref`, `commit`, `owner_id` and `repo_id` per dependency including transitive ones, and the secure-use reference says it "supersedes SHA pinning for repositories that adopt it". The extension is not installed on this host (`gh extension list` on 2026-10-29 shows `gh poi` only). Dependabot #548 (astral-sh/setup-uv 10.2.0 to 10.3.2, six call sites) and #549 (jdx/mise-action 4.3.0 to 5.2.2, a major, five call sites) have been open since 2026-10-25T10:18Z and are listed as untriaged in `handoff/04-open-items.md` row Deps. `decisions.tsv` holds no `plan-P-35` row. This unit measures the lockfile against this repository and reads both PRs, and writes the result as one file the coordinator decides from. The owner never closes, comments on, approves, merges, reruns or edits either PR; the coordinator records the triage.

SCOPE
One branch `records/workflow-lockfile-evaluation` from `origin/main`. May write exactly one file: `.orchestration/orchestrate/regime-cutover/handoff/evaluations/U115-workflow-lockfile.md` (the directory `handoff/evaluations/` is created by this unit).
