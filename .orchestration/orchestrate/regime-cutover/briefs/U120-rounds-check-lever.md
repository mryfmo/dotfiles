CHANGE
1. Data shape first. The store has `ledger.tsv` (`ts unit pr head_sha verdict verifier evidence`, tab-separated, header row) and `decisions.tsv` (`ts phase decision why evidence result`). An audit row is one whose verdict is `correct` or `incorrect`. A mechanism row for unit U<n> is a decisions row whose phase is `mechanism-change` and whose decision text starts with `U<n> ` or `U<n>:` and whose result contains exactly one of the tokens `ast`, `parser-module`, `allowlist`, `remove`, `residual`. Model this as two small frozen dataclasses and one function `verdict_for(unit) -> Allowed | Refused(reason)`; no scattered conditionals.
2. `rounds-check.py <store> <unit>` (also `--all <store>`): exit 0 when the next audit is allowed, 1 with a one-line reason when it is not, 2 on an unreadable or malformed store (a missing file, a row with the wrong column count, a header mismatch) naming the file and line. Allowed when: fewer than three audit rows for the unit; or the count of `incorrect` audit rows after the unit's latest mechanism row (or after the start when none) is below two and, when the total audit rows are three or more, at least one mechanism row exists. Refused reasons name the unit, the counts, and the row the coordinator must write (`decisions.tsv phase=mechanism-change decision="U<n> ..." result names one of ast|parser-module|allowlist|remove|residual`). With `--all`, every unit in the ledger is checked and the exit is 1 if any is refused, printing one line per refused unit. Standing order 39: an `incorrect` row whose evidence does not start with `class=<word>` is a malformed row only for rows with ts after 2026-10-30T00:00:00Z (older rows are exempt by date), so the check does not fail on history.
3. `pr-audit.sh --records <store>`: when the PR body carries a `Program-Unit: regime-cutover/U<n>` line, `--records` is required (refuse with exit 2 and a message naming the flag when absent) and the lever runs `rounds-check.py <store> U<n>` before anything else; a non-zero exit refuses the audit with exit 3 and the check's reason on stderr, nothing written. A PR body without the line keeps today's behaviour. The lever's own status reading of the check follows standing order 21 (a check that cannot run is a refusal, never "allowed").
4. `.github/workflows/regime.yml`: one step on the records PRs (the branch pattern the workflow already recognises for `records/sync-*`, read the file) that runs `rounds-check.py --all .orchestration/orchestrate/regime-cutover` on the PR head and fails the check on exit 1 or 2. Bound the step with `timeout-minutes` as the other steps are.
5. SKILL.md Gates paragraph: replace the three-strike sentence with the two-strike rule of standing order 36 and name the script and the analysis-only round; AGENTS.md Audit: one sentence at the end of the section.
6.
