# U166 the worker-root probe names the process that opened its sentinel

GOAL
`tests/unit/trusted_exec_contract.py`'s `WorkerRoot` records a read of its FIFO sentinel as `<input> opened for reading` and nothing more. On 2026-11-04 `test_metadata_reads_and_other_files_are_not_reads_of_the_input` failed twice on the `test (ubuntu-24.04, server)` cell with that line (main's own run 41761381776 at 30e94d9b, job 126349627448, 02:38:48Z; run 41762642788 at ac4af099, job 126353647080, 02:50:04Z), both on runner image 20261028.624, with the same content green on image 20261021.618 and on the next run of that cell; the test's compliant consumer opens nothing, so some process outside the consumer step opened the sentinel, and the record cannot say which. After this unit the record names the reader when the host can tell: on Linux the pid, `comm`, parent pid and the first 200 characters of the command line of every process holding the sentinel open at the moment the write-open succeeded (read from `/proc` before the probe closes its writer, while a blocked reader still holds the descriptor), or the count of processes whose descriptors this user cannot read when none of the readable ones holds it; on a host without `/proc`, `reader not identified (no /proc)`. The next occurrence is a diagnosis instead of a count.

SCOPE
One branch `fix/worker-root-probe-names-the-reader` from `origin/main`. May write: `tests/unit/trusted_exec_contract.py` (the `WorkerRoot` class only: its docstring, `_attempt`, and one new helper), `tests/unit/test_trusted_exec_contract.py` (one new test method and nothing else). No other file.

CONTEXT
`WorkerRoot._attempt` (`tests/unit/trusted_exec_contract.py:214-242`) opens the sentinel `O_WRONLY | O_NONBLOCK`; success means a reader holds it, and line 228 appends `f"{self.input} opened for reading"` to `self.reads` before line 230 closes the descriptor (which gives the reader EOF). `assert_untouched` (`:272-292`) prefixes each entry with `read ` and raises `worker root: ` + the joined entries; three tests match the message by `assertRaisesRegex(AssertionError, "worker root: read ")` (`test_trusted_exec_contract.py:459,463,515`) and one by `"worker root: read .*; wrote .*; created "` (`:247`), so the new words go after `opened for reading` and the prefix stays byte-equal. The docstring (`:124-152`) says what the probe detects and its residual list; it states that macOS scanners read fresh regular files and none opens a FIFO, which the two runs contradict for Linux. On Linux `os.stat("/proc/<pid>/fd/<n>")` follows the descriptor to the open file, so `(st_dev, st_ino)` equal to the sentinel's identifies a holder without parsing the link text; `os.listdir("/proc/<pid>/fd")` raises `PermissionError` for another user's process and `FileNotFoundError` for one that exited mid-scan, and both are expected. The probe runs in the test process, so a reader that is a thread of this process shows as `os.getpid()` with the interpreter's `comm`. `tests/unit/test_trusted_exec_contract.py:456-464` already drives a subprocess reader (`/bin/cat`) and an in-thread reader against fresh probes and asserts the `worker root: read ` form.

CHANGE
1. One helper on `WorkerRoot`, `_holders(self) -> str`: on a host with `/proc`, scan every numeric entry of `/proc`, and for each readable `fd` directory, every descriptor whose `os.stat` `(st_dev, st_ino)` equals the sentinel's (cache the sentinel's pair in `__init__` beside `_identity`, from `os.lstat`); return `by pid <pid> (<comm>, ppid <ppid>: <cmdline>)` for each holder joined by `, `, `comm` from `/proc/<pid>/comm` stripped, `ppid` from the `PPid:` line of `/proc/<pid>/status`, `cmdline` from `/proc/<pid>/cmdline` with NUL replaced by a space and cut at 200 characters, each read tolerating `FileNotFoundError` and `PermissionError` (an unreadable field reads `?`); when no readable process holds it, return `by no process whose descriptors this user can read (<n> unreadable)`; without `/proc`, return `reader not identified (no /proc)`. Nothing in the helper opens the sentinel or any FIFO (it stats descriptors of other processes; `os.stat` on a `/proc` fd link of a FIFO does not open the FIFO).
2. `_attempt`: line 228 becomes `self.reads.append(f"{self.input} opened for reading {self._holders()}")`, evaluated before the `finally` closes the writer so a blocked reader still holds its descriptor during the scan.
3. The docstring: one sentence after the access-time paragraph stating that a recorded read names its holders from `/proc` on Linux and why (the two 2026-11-04 runs on the ubuntu-24.04 server cell saw a reader outside the consumer step); the sentence `none opens a FIFO` is softened to what was measured (none did on macOS; on 2026-11-04 something on a Linux runner did).
4. One new test in `TrustedExecContractTest`, `test_a_recorded_read_names_its_holder`: a fresh probe consumed by `run(["/bin/cat", str(probe.input)], ALLOWED_ENV)`, then `assert_untouched` raises; on Linux the message matches `opened for reading by pid \d+ \(cat, ppid \d+: /bin/cat ` and the pid is not `os.getpid()`; a second fresh probe consumed by `in_thread(lambda: Path(probe.input).read_bytes())` names `os.getpid()`; on a host without `/proc` the message ends with `reader not identified (no /proc)` (skip nothing; assert the form the host produces).
