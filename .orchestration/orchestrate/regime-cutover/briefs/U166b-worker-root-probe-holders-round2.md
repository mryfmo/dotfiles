# U166b the holder scan survives a pid that exits mid-scan and its tests prove the two guarantees (round 2 of U166)

First, weight 20 (f10 s2), `tests/unit/test_trusted_exec_contract.py:473`: the PR body's threat table marks "exit tolerance" and "the scan opens no FIFO" closed, but the one new test proves neither, and a scan mutated to open the sentinel for reading still passes it. Second, weight 4 (f1 s4), filed, `tests/unit/trusted_exec_contract.py:234`: a pid that exits between the `fd` listing and its field reads can raise `ProcessLookupError` (ESRCH) from a `/proc` read, which `_holders` does not catch, so `_attempt` aborts before it records the detected read. After this unit `_holders` tolerates every `OSError` of a `/proc` read (the entry is counted or skipped, never raised), its `/proc` root is a class attribute a test can point at a scratch tree, and three tests prove, through that scratch tree, that a holder is named, that a pid whose fields vanish mid-scan is tolerated and the read still recorded, and that the scan leaves the sentinel with no reader (a write-open after the scan gets ENXIO) and opens no FIFO (a FIFO planted as a `/proc` descriptor target is never opened: a write-open on that planted FIFO during and after the scan gets ENXIO too).

CONTEXT
Measured 2026-11-04 on the round-1 head 78eea03c. `WorkerRoot._holders(self, writer)` (`tests/unit/trusted_exec_contract.py`, after `_not_sentinel`) returns `reader not identified (no /proc)` when `/proc` is not a directory, else walks `os.listdir("/proc")`, lists each numeric entry's `fd` (tolerating `PermissionError`, counted, and `FileNotFoundError`, skipped), stats each descriptor link (tolerating `OSError`) and compares `(st_dev, st_ino)` with `self._dev_ino`, then reads `status`, `cmdline` and `comm` through a nested `field()` that tolerates only `FileNotFoundError` and `PermissionError`; `ProcessLookupError` (ESRCH, raised by a `/proc/<pid>/...` read of an exiting pid, and `OSError` subclasses such as `IsADirectoryError` for a malformed tree) escape and abort `_attempt` at its line `self.reads.append(f"{self.input} opened for reading {self._holders(fd)}")`, which runs before the `finally` that closes the writer. The round-1 test `test_a_recorded_read_names_its_holder` drives `/bin/cat` and an in-thread reader against real probes and asserts the message's form for this host (macOS has no `/proc`, so here it asserts only `reader not identified (no /proc)`), which is why the Linux branch has no failing selector on this host. A scratch tree makes the Linux branch testable everywhere: a directory holding `<pid>/fd/<n>` symlinks to the sentinel (or to a planted FIFO), `<pid>/comm`, `<pid>/status` with a `PPid:` line, `<pid>/cmdline` with NUL separators; `os.stat` of such a symlink follows it to the sentinel and reports the sentinel's `(st_dev, st_ino)` without opening it, the same identity the Linux kernel's magic links report. A FIFO opened for reading by anyone makes a non-blocking write-open succeed; with no reader it fails with ENXIO (`_open_writer` already encodes this), so "the scan opened no FIFO" is observable: during the scan (from a thread) and after it, `_open_writer()` on the sentinel and on a planted FIFO returns None.

CHANGE
1. `WorkerRoot.PROC_ROOT = "/proc"` as a class attribute; `_holders` reads `type(self).PROC_ROOT` (so a test subclass or an instance attribute can point it at a scratch tree), and the "no /proc" message names the root it looked for only when it is `/proc` (keep the exact string `reader not identified (no /proc)` for the real root).
2. `_holders`: every `/proc` read tolerates `OSError` as a class: `os.listdir(<root>)` failing is "no /proc"; a pid's `fd` listing failing with `PermissionError` counts as unreadable and any other `OSError` skips the pid; each descriptor `os.stat` failing skips the descriptor; each field read (`comm`, `status`, `cmdline`) failing with any `OSError` reads `?`. A holder whose fields vanish is still named by its pid with `?` fields. The record form and the three messages of round 1 stay byte-equal.
