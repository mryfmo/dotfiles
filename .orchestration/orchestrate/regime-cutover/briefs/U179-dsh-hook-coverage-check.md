# U179 the DSH hook-coverage check: one test pins, event by event and matcher by matcher, which of the kit's Claude hooks the dsh-hooks-claude-code bridge at the pinned tag would run, and names the first hook whose coverage changes

GOAL
ADR-006 and the M-14 unit (U172, merged as cd64232a) mount `@deepseek-ai/dsh-hooks-claude-code` in the rendered thak profile so that the kit's Claude hooks gate DSH when it runs as the Router; whether the bridge covers this repository's hook set was named an acceptance condition of ADR-009 (R-52 s3) and never measured. The coordinator measured it on 2026-11-05 against the pinned tag (CONTEXT): the bridge runs seven Claude Code events and ignores the other twenty-three, `PermissionRequest` among them; its tool matchers compare Claude Code tool names as exact strings against DSH's model-visible tool names, which are lower-case (`bash`, `edit`, `write`); so of the kit's five hook groups, two are on an unsupported event or match no DSH tool by name, one is match-all, and one depends on a session-source value the catalog does not show. After this unit one test, `tests/unit/test_dsh_hook_coverage.py`, holds that measurement as an exact-form table keyed on the asset pin and fails by name when anything that feeds it moves: a new hook group in the kit's settings, a matcher whose DSH coverage changes, a dsh pin bump (the table must be re-measured against the new tag's `config.ts` and tool catalog), or a mount whose `configPath` no longer names the deployed Claude settings. The test changes no hook, no rendered file and no behaviour; the coverage result itself goes into the store as a decisions row written by the coordinator, and a fix of the coverage (DSH-side matchers) is a later unit after the M-21 spike shows the bridge's payloads.

SCOPE
One branch `feat/dsh-hook-coverage` from `origin/main` (ff6803b7 or newer; take the base the coordinator names). May write: `tests/unit/test_dsh_hook_coverage.py` (new). Nothing else: not the settings template, not the hooks, not the manifest, not the generator, not the rendered profile, no lever.

1. It accepts either a settings object with a `hooks` key or a bare event map; only `type: command` hooks run (others are returned as skipped); `matcher` is discarded for `UserPromptSubmit` and `Stop`. The package README lists the unsupported events, `PermissionRequest`, `PreCompact`, `SessionEnd`, `Notification`, `Setup` and eighteen more.
