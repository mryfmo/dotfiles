# U180 a carried row reads the change, not the blob: the digest lever hashes each changed path's own hunks without line numbers or blob ids, a body fix at a carried head holds as a fixed row, and a note after the carried digest is admitted

GOAL
Three records corrections and three avoidable audit rounds on 2026-11-04 came from the grammar of two levers, not from the units. (1) `audit-carry.py` hashes the raw records of the three-dot diff, the old and new blob ids and modes per changed path (`scripts/orchestrator/audit-carry.py:627`, `:694-700`), so a merge of `main` that touches any file the pull request also touches changes the digest even when the pull request's own hunks are byte-identical; U150 paid rounds 7, 8 and 9 that way (`ledger.tsv` rows 2026-11-04T02:50:59Z, 03:29:36Z, 03:59:32Z, each "the head being the merge of main"), each round an audit, a sweep and a CI run of about an hour. (2) `pr-merge.sh` `require_dispositions` (`:563`, `:652-655`) skips every `fixed` row with "says fixed in <sha>, which is not this head; merge the head that fixed it", so a body-only finding closed by a body edit at an empty commit whose row is `carried` has no form, and U174 had to write a `residual` row for a finding that was fixed (`decisions.tsv` 2026-11-04T07:08:35Z; U148 took an empty commit and a fourth audit for the same reason, `decisions.tsv` 2026-11-04T02:30:22Z). (3) `carried_evidence_re` (`pr-merge.sh:390`) requires whitespace or the end of the field after the 64-hex digest, so the receipt form the README names with a note after it, `carried <a> <b> <digest>; verdicts/...`, is refused and a row had to be rewritten (`decisions.tsv` 2026-11-04T07:04:58Z; the U132 rows of 2026-11-01 had the same shape). After this unit: the digest is a function of each changed path's status, modes and its own hunk lines (the `-` and `+` lines byte-exact, the `@@` positions and the `index` blob ids left out), so a merge of `main` that moves lines but changes none of the pull request's own lines is carried, and one that changes any of them, by one byte or one space inside a line, is not; a `fixed` row whose reference is the head being merged holds when that head's newest ledger row is a `carried` row of the audited head (the only way a fix can exist at a carried head is the body); and a note after the carried digest is admitted when it starts with `;`, `,`, `.` or `)`. Every lever rule stays an exact-form check and every change carries a test that fails on today's lever.
