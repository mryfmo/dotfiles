# U188 disk-gc reads each worktree path whole from git's NUL-terminated listing, names a worktree's lock by its own admin directory, and removes a directory only when it is the root of a worktree of that repository

GOAL
The first milestone sweep (U152, `sweeps/U152-c92078d0/findings.json`, the lead `disk-gc:worktree-porcelain-path-field-split`, carried through run-30) names a defect of a destructive lever: `home/dot_local/bin/common/executable_disk-gc` reads `git worktree list --porcelain` through `awk '{ print $2 }'` (`:182`, `:184`), so a worktree whose path holds a space is read as its first word, every later check (`-d`, `rev-parse`, `status`, the lock) runs on that other path, and `rm -rf "${wt}"` (`:223`) removes it when `git worktree remove` left it standing. The lock check (`:207`) names the admin directory by `basename "${wt}"`, while git names it `worktrees/<basename><n>` when two worktrees share a basename, so the lock of one tree is read for another. After this unit the lever reads the listing with `-z` through a NUL-delimited reader (every byte of a path kept, newlines and spaces included), takes the admin directory from `git -C "${wt}" rev-parse --path-format=absolute --git-dir`, and removes a directory with `rm -rf` only after proving it is the root of a worktree of this repository (a directory that is not a symlink, whose physical path equals its own `git rev-parse --show-toplevel` physical path, whose `--git-common-dir` is this repository's, and which is not the main worktree); every other state is logged and kept. The lever gets its first test module.

SCOPE
One branch `fix/disk-gc-worktree-paths` from `origin/main` (eee4c25a or newer; take the base the coordinator names). May write: `home/dot_local/bin/common/executable_disk-gc` (`discover_repos`, `worktree_gc`, `lock_is_live`'s caller and the shdoc of each); `tests/unit/test_disk_gc.py` (new). Nothing else: not the systemd units, not `worktree-gc.sh`, not the docker or cache functions.

CONTEXT
Measured 2026-11-05 on eee4c25a. The lever is deployed by chezmoi as `~/.local/bin/common/disk-gc` and run daily on Ubuntu by `home/dot_config/systemd/user/disk-gc.service.tmpl` (`ExecStart=... disk-gc --apply`, `:6`) under the timer `disk-gc.timer.tmpl` (04:00); the macOS bats assert the units absent (`tests/files/macos.bats:24-25`). It is not a pinned lever (no line under `claude.levers.sha256`) and has no unit test; `tests/unit/test_worktree_gc.py` is the model for a scratch-repository test of a sibling lever (a bare origin, a checkout, worktrees in each state, a `git` wrapper on PATH recording argv, `scratch_git.git_init`). The listing reads: `main_wt=$(... | awk '/^worktree / && !seen { print $2; seen = 1 }')` (`:182`), `worktrees=$(... | awk '/^worktree / { print $2 }')` (`:184`), `while read -r wt; do ... done <<< "${worktrees}"` (`:185`, `:225`); `discover_repos` counts `grep -c '^worktree '` (`:144`, a count, unaffected). `git worktree list --porcelain -z` terminates every line with NUL and every record with a second NUL (git-worktree(1), `-z`; measured on this host, git 2.56.0: `worktree <path>\0HEAD <sha>\0branch <ref>\0\0`). The lock: `lock_is_live "${gitdir}/worktrees/${name}/locked"` with `name=$(basename "${wt}")` (`:187`, `:207`); git's admin directory for a worktree is `git -C <wt> rev-parse --path-format=absolute --git-dir` (`<common>/worktrees/<id>`), and `git worktree list --porcelain` also prints a `locked` line per locked tree. The removal: `run git -C "${repo}" worktree remove --force --force "${wt}"` then `[ -d "${wt}" ] && rm -rf "${wt}"` under `--apply` (`:221-224`). The lever uses GNU `find -files0-from` (`:128`, `:201`) and `date -d` (`:86`), so it runs on Ubuntu; on this macOS host both work (find 0.8.0 answers `-files0-from`, `date -d` exit 0), on the macos-15 CI runner they may not, so the test module probes both in `setUpModule` and skips with a reason when either is absent.
Why the closing form is parser-module: the listing is read by one reader over git's `-z` record grammar (a line ends at NUL, a record at two NULs, the `worktree ` prefix names the path and nothing is split on whitespace), and the removal decision is a fixed set of identity checks; no path is read as text where git or the filesystem gives an identity.

CHANGE
1. One reader. Replace the two `awk` reads and the `<<<` loop with `git -C "${repo}" worktree list --porcelain -z` consumed by `while IFS= read -r -d '' line; do case ${line} in 'worktree '*) ... ;; esac; done < <(git ... -z)` (or a function `worktree_paths` that prints the paths NUL-separated and a loop with `read -r -d ''`), the first path being `main_wt`; a `git` that fails there is a `log` and `return 0` for that repository (nothing removed), never an empty list read as no worktrees (standing order 21: the status is read, `set -o pipefail` is in force). The `locked` line of the same record, when present, is kept per path (a map or a parallel read) so the lock check needs no basename.
2. The admin directory. `name` stays for log lines (basename of the path, as text), but the lock file is `"$(git -C "${wt}" rev-parse --path-format=absolute --git-dir)/locked"` with the status read (a failed read keeps the tree and logs it), or the `locked` attribute of item 1; `lock_is_live` itself is unchanged.
3. The removal guard. Before `git worktree remove` and again before `rm -rf`: `wt_real=$(cd "${wt}" && pwd -P)` (status read; a failed `cd` keeps the tree), `[ ! -L "${wt}" ]`, `[ "${wt_real}" != "${main_real}" ]`, `top=$(git -C "${wt}" rev-parse --show-toplevel)` with its physical path equal to `wt_real`, and `git -C "${wt}" rev-parse --path-format=absolute --git-common-dir` equal to `gitdir` (the repository's); any mismatch is `log "keep ${name}: not a worktree root of ${repo} (<which check>)"` and `continue`. The `rm -rf` after `worktree remove` runs only when `[ -d "${wt}" ] && [ ! -L "${wt}" ]` and the directory is still the same inode as `wt_real` was (`[ "${wt}" -ef "${wt_real}" ]` is tautological for the same path; keep the pre-check's `wt_real` and compare `$(cd "${wt}" && pwd -P)` again), else log and keep.
4. `discover_repos` keeps its count but reads the status of `git worktree list` (`|| continue` already skips a repository whose listing fails; keep).
5. `tests/unit/test_disk_gc.py` (new), in the style of `test_worktree_gc.py`: a scratch HOME and workspace, a bare origin and a checkout with `main`, `DISK_GC_REPOS` set to the checkout, `PATH` with a `docker` absent (so `docker_gc` skips) and `uv`/`npm` absent, `DISK_GC_WORKTREE_DAYS=0` or files aged with `os.utime` so a tree counts as idle, `XDG_DATA_HOME` under the scratch root. Tests: (a) a worktree at `<workspace>/My Tree` (a space) merged into main and idle, and a sibling directory `<workspace>/My` holding a marker file: `disk-gc --apply` removes `My Tree` and the marker under `My` is untouched (the base removes `My`: red proof); (b) a worktree whose path holds a newline (`os.mkdir` with `\n` in the name; skip the subtest when the filesystem refuses): removed as a whole, nothing else touched; (c) two worktrees with one basename under two parents, the first locked by a live pid (the test's own `os.getpid()` in the lock file's `pid N` form) and the second unlocked and merged: the second is removed and the first kept (the base reads the first's lock for both, or the wrong admin dir: assert the log lines); (d) a path in the listing that is not a worktree root (make the worktree, then replace its directory with a plain directory holding a file, so `rev-parse --show-toplevel` fails): kept with the `not a worktree root` log and the file present after `--apply`; (e) the report mode (`disk-gc` without `--apply`) removes nothing and prints `would run` lines naming the full path with its space; (f) a `git worktree list` that fails (a `git` wrapper that exits 1 on `worktree list`): the repository is logged and skipped, nothing removed. Each test asserts what is on disk and the lever's log lines; the `git` wrapper records argv so (a) can assert that no git call received the truncated path `My`.
