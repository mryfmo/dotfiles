# U192 records-sync.sh --ff fast-forwards the coordinator's checkout past a merged sync without a stash, resolving the store's append-only tables as the local superset and adopting main's masked bytes for files written once

GOAL
After every records sync merges, the coordinator's checkout must fast-forward `main` while its live store under `.orchestration/orchestrate/<program>/` holds rows appended since the sync and files that differ from `main` only by the sync's secret masking. Today this is a hand procedure with three steps that went wrong once on 2026-11-05 (decisions row of 05:3xZ: the ledger was written empty for a minute and recovered from a dropped autostash): `git pull --ff-only` refuses over untracked store files the sync added to `main`; the coordinator removes those byte-identical to `origin/main`; the pull then autostashes and the stash apply conflicts on the append-only tables (both sides end in new rows); the coordinator resolves by hand. Standing order 31 forbids `git stash` in worker trees for the same class of accident. After this unit `records-sync.sh --ff` does the whole step with its invariants checked and no stash: it refuses unless the checkout is the main checkout on `main` with `HEAD` an ancestor of the fetched `origin/main` and every path the fast-forward would change outside the store is clean; it classifies every store path the fast-forward touches by a fixed table (untracked and byte-identical to main, or equal to main after masking: removed before the merge; tracked and unmodified: nothing; an append-only table whose first N lines equal main's N lines after masking: main's N lines plus the local tail; `units.tsv` whose id set covers main's: the local file; a file written once that equals main's after masking: main's bytes adopted; anything else: a refusal naming the path and the first differing line, nothing written); it backs every store file it will overwrite up under a scratch directory it names in the receipt, performs `git checkout -- <paths>` and `git merge --ff-only FETCH_HEAD` only after the whole classification passed, writes the resolved files back, verifies the store with the one ledger reader and `rounds-check.py --all`, and on any failure after the checkout step restores the backup byte for byte and exits 1 naming the step.

CHANGE
1. The mode: `records-sync.sh --ff [--program <name>]` (no `--unit`, no `--base`; `--ff` with either is a usage refusal). Shared with the sync: the self-check, the `GIT_*` scrub, the main-checkout refusal, the program resolution, the scratch directory and the fetch of `origin`'s `main` into the scratch bare repository (`main` and `main_tree` as now). New refusals (exit 2, nothing written): the current branch is not `main`; `git merge-base --is-ancestor HEAD <main>` is false (a local commit on main, or main behind); a merge, rebase or cherry-pick in progress (`.git/MERGE_HEAD`, `rebase-merge`, `rebase-apply`, `CHERRY_PICK_HEAD` present); `HEAD` equals `<main>` (nothing to do, exit 0 with the receipt `up to date`).
2. The touched set: `git_isolated diff-tree -r -z --name-status HEAD <main>` (status read; the NUL list read from a file as the sync does). Every path outside the store must be clean in the working tree and index (`git_isolated status --porcelain -z -- <path>` empty), else refuse naming the path (the coordinator resolves by hand).
3. The classification of each touched store path, in one function returning a word per path, with main's blob read through `git_scratch cat-file blob <main>:<path>` and the local file read from disk; masking through main's validator extracted as the sync does (`mask <file>` writes the masked copy under the scratch directory and the lever compares bytes):
   - `untracked-equal`: the local path is untracked (`git ls-files --error-unmatch` fails) and its bytes, or its masked bytes, equal main's blob: the local file is removed before the merge (the merge checks it out again).
   - `clean`: tracked and unmodified (`git diff --quiet HEAD -- <path>` and no index change): nothing.
   - `table-append`: the path is `ledger.tsv`, `decisions.tsv` or `dispositions.tsv`, tracked and modified, main's blob has N lines, the local file has M >= N lines, and the masked local file's first N lines equal main's N lines byte for byte: the resolved file is main's N lines followed by the local lines N+1 to M (local bytes, unmasked).
   - `units-local`: the path is `units.tsv`, tracked and modified, the header line equal, and every id of main's rows is an id of a local row: the resolved file is the local file.
   - `once-adopt`: any other tracked and modified path whose masked local bytes equal main's blob: the resolved file is main's blob (the local raw copy goes; the record of truth is main's).
   - everything else (an untracked file that differs, a table whose first N lines differ, a units.tsv missing an id, a once-written file that differs beyond masking, a deletion on main of a path modified locally, a symlink or directory at a path): refuse, exit 2, naming the path, the class attempted and the first differing line number; nothing has been written.
4. The write phase, only after every path classified: a backup directory under the scratch root named in the receipt holds every local store file about to be replaced or removed (a copy of each, with its relative path); then the `untracked-equal` files are removed, `git_isolated checkout -- <the tracked modified store paths>` discards the local versions, `git_isolated merge --ff-only <main>` moves `HEAD` (any failure here restores every backed-up file and exits 1 naming the step), then each resolved file is written over the checked-out one, and the verification runs: `python3 -I -S scripts/orchestrator/ledger.py <store> verdict 0 <40 zeros>` must exit 0 or 1 (never 2), `rounds-check.py --all <store>` exit 0, and `git_isolated diff --name-only HEAD -- <store>` must list exactly the `table-append` and `units-local` paths; a verification failure restores the backup over every written file, prints the failing check and exits 1 (HEAD stays moved; the files are the pre-merge ones, which the coordinator can read beside main's). The scratch directory is kept on exit 1 (the receipt names it) and removed on exit 0 and 2.
