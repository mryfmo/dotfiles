# U192b `records-sync.sh --ff` moves the branch and the index to main and writes nothing inside the store (round 2 of U192, mechanism change)

GOAL
Round 1 of U192 (PR 663, head 52bcf537, `verdicts/U192-52bcf537.md`, Codex threads 4478615213, 4478615225, 4478615239) was incorrect on eight P1 and four P2, every one of them a way the write phase into the live store could lose or misplace bytes: a SIGTERM after the removals deleted the backup, a `status --porcelain` without `--ignored` let an ignored file be overwritten, a store filename read as a pathspec reset a sibling, the checkout's `info/grafts` steered the ancestry check, the working tree's `ledger.py` and `rounds-check.py` ran as the verifier, the checkout's clean filters ran during classification, `merge.autoStash` undid the no-stash guarantee, equal resolved files failed the expected-set check, a symlinked parent let `rm` unlink an outside file, and so on. Each is a consequence of one premise: that the fast-forward must go through `merge --ff-only`, which insists on writing the working tree, so the lever had to remove, resolve, back up and restore store files around it. The coordinator measured the alternative on 2026-11-05 in a scratch pair of repositories (decisions row of this date, `U192 mechanism change`): `update-ref refs/heads/main <main> <head>`, then `read-tree <main>` (the index alone), then `checkout-index -f` for the paths main changed outside the store, leaves `HEAD` and the index at main, every store file byte-for-byte as it was (the local table tails and unmasked files now show as modifications against main, which is exactly what the next sync publishes), and the files outside the store at main's content. After this head `--ff` is that sequence behind its refusals, with no classification table, no masking, no table resolution, no removal and no backup, because nothing inside the store is written.

The prototype of the new form (the coordinator's, in Python over plain git with a scratch origin and clone): `diff-tree -r -z --name-status --no-renames <head> <main>` names the changed paths; those outside `.orchestration/orchestrate/<program>/` must each be clean (`status --porcelain --ignored -- <path>` prints nothing); `update-ref refs/heads/main <main> <head>` (the old value given, so a moved branch refuses), `read-tree <main>`, `checkout-index -f -- <outside paths>`; afterwards `rev-parse HEAD` is main, `status --porcelain` lists only the store files whose local bytes differ from main's, and the outside files hold main's content. The checkout guard (`checkout-guard.sh`, the `reference-transaction` hook) accepts a move of `refs/heads/main` to a commit `refs/remotes/origin/*` reaches, and the levers' isolated git runs no hook anyway (`core.hooksPath=/dev/null`); the mode must still fetch origin's `main` into the checkout's `refs/remotes/origin/main` (or `update-ref` it from the scratch repository's object) so the guard's rule holds for the operator's later commands. Git reads `info/grafts` and `refs/replace/*` for ancestry unless told otherwise: `--no-replace-objects` covers replace refs; a non-empty `<git-dir>/info/grafts` or any `refs/replace/*` ref is a refusal. Clean and smudge filters: `checkout-index` applies smudge filters as every checkout does, which is the repository's own behaviour on its own tracked files; no store file is read through a filter because none is read at all. Literal pathspecs: every path given to git is prefixed `:(literal)` (or git runs with `--literal-pathspecs`), so `wild*.md` names one file. The round-1 tests (`RecordsFfTest`, 11) assert the removed behaviour and are replaced; `RecordsSyncTest` (34) stays green untouched.

CHANGE
1. Replace the round-1 mode: delete `classify`, `differing_line`, `ff_restore`, `ff_step_failed`, `ff_verify_failed` and the body of `ff_run`; keep the usage form (`--ff [--program <name>]`, `--ff` with `--unit` or `--base` refused) and the shared preamble. The new `ff_run`, in order, with every refusal before any write and exit 2: on a branch named `main`; no merge, rebase or cherry-pick in progress; `<git-dir>/info/grafts` absent or empty and no `refs/replace/*` ref (`for-each-ref refs/replace`); the index equal to `HEAD` (`diff --cached --quiet`); origin's `main` fetched into the scratch repository as today and its object made reachable in the checkout (`fetch` from the scratch repository over the local transport the sync already opens, into `refs/remotes/origin/main`); `HEAD` an ancestor of main (`--no-replace-objects merge-base --is-ancestor`); the touched set from `diff-tree -r -z --name-status --no-renames`, read to its end, every entry's status one of `A`, `M`, `D`, `T`; for each touched path outside the store: nothing at the path that is not the tracked clean file (`status --porcelain --ignored --untracked-files=all -- :(literal)<path>` empty) and no symlink component between the toplevel and the path; `up to date head=<sha>` and exit 0 when `HEAD` equals main. Then the writes, in order: `update-ref refs/heads/main <main> <head>`; `read-tree <main>`; `checkout-index -f -- :(literal)<path>` for every outside path with status `A`, `M` or `T`, and `rm` of the outside paths with status `D` (each path checked again as a regular file or absent before the unlink); then the receipt `fast-forwarded from=<head> to=<main> outside=<n> store-modified=<n>` where the second count is `diff --name-only -z HEAD -- :(literal).orchestration/orchestrate/<program>` read to its end. A failure after `update-ref` exits 1 naming the step and prints that a rerun converges (every step is idempotent: `read-tree` and `checkout-index -f` repeat without harm); nothing is restored because nothing of the store was written. The scratch directory is removed on every exit.
