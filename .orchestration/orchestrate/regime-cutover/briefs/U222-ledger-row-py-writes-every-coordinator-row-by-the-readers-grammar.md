# U222 ledger-row.py writes every coordinator row of the ledger by the reader's grammar, and refuses the shapes that have cost a round

GOAL
Every `ledger.tsv` row the coordinator writes today (merge receipts, carried rows, sweep rows, audit rows, push and lever receipts) is composed by hand in a Python cell, and four of them have been wrong in ways the readers found later: a merge row whose verifier cell carried a note hid three merges from `rounds-check.py` (decisions 2026-11-06T00:18:19Z); a `-` receipt row written against an audited head voided every later carry from it, since `pr-merge.sh` reads the newest row of the earlier head whatever its verdict (2026-11-05T23:53:08Z); a verdict file stored under a fix unit's name while the row named the parent unit refused the next audit (2026-11-07T12:39:21Z); a carried row whose digest ended with a semicolon failed the merge gate's whole-word regex (2026-11-04T07:04:58Z). One writer, `scripts/orchestrator/ledger-row.py` beside `ledger.py`, composes the row from named arguments, fixes the verifier vocabulary per kind, re-reads the ledger plus the new line through `ledger.parse_ledger` before anything is written, refuses each of those four shapes by name, and appends. The coordinator calls it instead of composing rows; nothing else changes.

DATA SHAPE
One frozen `Row` per `ledger.py`'s header, composed by one function per kind from named arguments and the clock (`ts` is now in UTC under `TS_FORMAT`, never an argument), with the verdict and the verifier's fixed words chosen by the kind and never typed by the caller:
- `merged`: pr, head, unit, the `pr-merge.sh` receipt line; verdict `-`; verifier exactly `pr-merge.sh`; evidence the receipt (`merged pr=<pr> head=<sha8 or 40> commit=<40 hex>`, whose pr and head must equal the arguments) then `; <note>` when a note is given.
- `carried`: pr, head, unit, the `audit-carry.py` stdout line, a note; verdict `carried`; verifier `audit-carry.py (<note>)`; evidence the line, which must match the merge gate's regex with the second sha equal to head, then `; <evidence note>` when given, so the digest is a whole word before a separator.
- `sweep`: head, unit (`U<n>` or `U<n><letter>`), seat, run number, task unit, the findings path, the findings count, an optional pr; pr cell `-`; verdict `sweep`; verifier `security-audit-skill <pin8> (full audit mode on the srt worker seat <seat>, run-<n>; TASK U<n>)` with `<pin8>` the first 8 characters of the manifest's `assets.security-audit-skill.pin` (the manifest `~/.agents/agent-config.yaml`, else the checkout's `home/dot_agents/agent-config.yaml`, read as `sweep_pin_probe` reads it); evidence `<findings path>; pr <pr or none>; <count> findings; validate-findings.cjs PASS; validate-coverage-ledger.cjs PASS`; the findings path must be `sweeps/<dir>/findings.json` and a regular file under the store.
- `audit`: pr, head, unit, the verdict file path, the verifier text (must start with `pr-audit.sh`), an optional class word; the verdict word is read from the file's last line (`Verdict: correct` or `Verdict: incorrect`), never from an argument; the file must be `verdicts/<unit>-<sha8>.md` with `<unit>` the row's unit and `<sha8>` the head's first 8 (the 12:39:21Z lesson), a regular file under the store, scored (a `Filed: <n>` line); evidence `class=<word> verdicts/<unit>-<sha8>.md: Blocking: <n>; Filed: <n>; Verdict: <word>` for incorrect (the class is required; standing order 39) and the same without the class for correct, the two counts read from the file.
- `pushed`: pr (or `-` before a pull request exists), head, unit, how (free text), what (free text); verdict `pushed`; verifier `coordinator (<how>)`; evidence the text.
- `receipt`: pr, head or `-`, unit, lever name from the set {`pr-update-branch.sh`, `pr-close.sh`, `records-sync.sh`}, the receipt line, an optional note; verdict `-`; verifier the lever name alone; evidence the receipt then `; <note>`.
Two cross-row refusals before any write (standing order 21, the 23:53:08Z lesson): a `pushed` or `receipt` row whose head is 40 hex and already has an audit row of the same pull request (`ledger.already_audited`) is refused naming that row's ts, since it would become the newest row of an audited head and void every carry from it (the `merged` kind is exempt: the merge is the last row of a head); and any cell holding a tab or a newline is refused naming the cell. The write: the ledger is read through `read_ledger` (a store that does not parse is exit 2 naming the line), the new line is appended to the text in memory and the whole re-read through `parse_ledger` (a row the reader would refuse is never written), then the one line is appended to the file opened in append mode and flushed; stdout one line `appended <ts> line <n>`; exit 0. Refusals exit 2 with one stderr line; a write failure exits 1 naming the file.
