# The audit loop: diagnosis and the decided redesign (2026-10-30)

This file decides how the program's review loop changes so that a unit stops costing ten to twenty-four audit rounds. It rests on the store's own measurements (section 1), on the four research files written on 2026-10-30 under [research/](research/) (04 literature, 05 review tools and loop practice, 06 Codex and Actions documentation, 07 OSS lints and shell safety), and on the earlier analysis in [02-audit-treadmill-analysis.md](02-audit-treadmill-analysis.md) and plan in [05-remediation-plan.md](05-remediation-plan.md). Labels: "measured" is a store row or a command on this host, "doc" is a cited source in a research file, "inferred" is this file's conclusion.

## 1. What is slow, measured

The time is in the round count, not in one audit.

One round is the owner's fix (15 to 30 min), the audit (307 to 723 s measured this session, eight runs), and CI (13 to 16 min, in parallel). Audits run one at a time because the Codex login is one serialized job stream (`/tmp/dotfiles-wt/audit-unit.sh` header), so a second unit waits up to 12 min for the slot. A round is therefore about one hour, and U109 and U112 paid it twelve to fourteen times.

Why the count did not fall (ledger evidence column, measured):

1. The rule surface is open-ended and the gate is binary. U112's lint must read every Bash construct that can lose a status or rebind a word; U109's rule must bound `apt` against anything an earlier step can do. Each fresh audit found one more construct (fd `02`, `alias`, `export 'PATH=…'`, `ProcSubst`; `BASH_ENV`, `container.env`, `GITHUB_PATH`). Any P2 makes the verdict `incorrect` (`pr-audit.sh:1099`), so each construct costs one hour.
2. The auditor is fresh each round with no memory of earlier dispositions. It re-raises classes the coordinator has parked unless the PR body says so. U109 got `correct` at round 19 and a near-identical head got a new P2 on round-11 code one round later.
3. Body-only defects cost a code round. U109 round 22 was `incorrect` for a missing threat-table row and took a body edit plus a 10-minute re-audit of the same head.
4. The sandbox blocks the auditor's own reproduction. Verdicts say Bash heredoc temp files, Perl and `ps` were denied, so the auditor spends time on workarounds and writes "could not verify".
5. The owner round is heavy. The PR body is a 60 KB document after 24 rounds and each owner condenses it; two owners stalled today for 33 and 58 minutes without writing.

## 2. What the sources say (doc, from the research files)

- A fresh LLM judge disagrees with itself across runs (Krippendorff's alpha 0.27 to 0.56, well under the 0.8 bar; 04 entry 1). An open-ended "is this vulnerable" prompt flags safe code above 88% of the time (04 entry 4). One `incorrect` verdict is a sample, not a fact.
- Repeating review on the same artifact adds findings without adding real defects: a second review round produced 62% more false positives and the fresh-context variant was worst (04 entry 5); multi-round review F1 fell from 0.65 at round 2 to 0.29 at round 10 (04 entry 6); a critic that catches more also hallucinates more (04 entry 9).
- Repair loops with an executable oracle plateau after three to four rounds (04 entry 7). Every vendor review loop stops itself at three to five rounds and hands the rest to a person; the one fifty-round case became the reason for the cap (05 sections 3.1 and 6).
- Every vendor that re-reviews on push moved to incremental review with finding memory between 2025 and 2026; the Claude Code team measured 59% of late-round flags on code unchanged since round one, and after diff-only re-review, class flagging and no repeats their mean reviews to pass fell from 2.08 to 1.32 (05 section 2 and 6).
- No vendor blocks a merge on a general finding by default; Codex itself posts only P0 and P1 on GitHub (05 summary; 06 section 3). The repository's P2 threshold is stricter than every product default.
- A denylist over shell never closes: 69.0 to 98.6% of 1,709 real command denylists are fragile and fixing one needs 217 more commands on average (04 entry 14); the systems community states that pattern matching over shell text cannot decide safety (04 entry 15); the Bash manual lists eleven rebinding channels reachable from the text or from outside it (07 section 3). A finite allowlist turns the semantic question into a syntactic one (07 section 3.4).
- No OSS tool replaces the two bespoke rules; ghalint covers `timeout-minutes` presence and zizmor the env and credential channels (07 section 1.3 and 5).
- Codex documents the reasoning-effort direction only ("takes longer and uses more tokens"), not a figure; the audit's `xhigh` is a choice, not a constraint (06 section 1.5). No vendor statement forbids concurrent `codex exec`; the one rule is one `auth.json` per serialized stream, which matters only when a refresh falls due (06 section 2).

## 3. The decision

Attack the premise first: the loop assumed that a fresh adversarial judge with a binary gate converges on an open-ended rule. The sources and the ledger say it does not. The loop is rebuilt so that each round changes a measured thing, the judge sees the history as data, and the gate blocks on what the vendors and the store's own residual rule already treat as blocking.

Order of delivery: 1 and 2 first (they are text in the lever and the skill plus one small script, and they stop the tail today), then 3 (lever work), then 5 (measurements), with 4 already in the plan as P-11. P-41 measures the result: median audit rounds per unit before and after, from the ledger.

What is not adopted, and why: a jury of models (it reduces but does not remove judge variance, 04 entry 3, and doubles the audit cost); a merge queue (plan D6); the API-key route (G18, the operator's decision; the throughput gain is parallel audits, which change 5 gives without it); hiding findings below a confidence threshold (every finding stays reported; only what blocks changes); replacing the bespoke lints with OSS (07 section 1.3: no tool carries the apt form or the status grammar; ghalint and zizmor are added beside them, not instead).

Expected effect (inferred, to be measured by P-41): the tail above three rounds disappears by construction (change 2), body-only and P2 rounds stop costing code rounds (change 1), and the re-raised classes stop (change 3). The Claude Code team's measured drop (mean 2.08 to 1.32 reviews, five-plus rounds 8.9% to 1.5%) is the nearest published analogue; this program's trust-boundary units should land in three rounds or fewer, with the rest written as residual rows the operator can read.
