| 10 (optional) | tailnet admin console, policy file | Limit port 22 on the seat host to the laptop. (a) The policy is deny-by-default and every rule only adds access, so a new narrow rule takes nothing away: first find each rule in `grants` and `acls` whose `src` reaches the seat host, such as the default `{"src": ["*"], "dst": ["*"], "ip": ["*"]}` grant or an `{"action": "accept", "src": ["*"], "dst": ["*:*"]}` ACL. Narrow it so its `dst` no longer covers the seat host's port 22, or remove it, after writing separate rules for the other traffic it carried. (b) Name both nodes in `hosts`: `"hosts": {"laptop": "<laptop tailscale IP>", "seat-host": "<seat-host tailscale IP>"}`. (c) Add one rule, in `grants`: `{"src": ["laptop"], "dst": ["seat-host"], "ip": ["tcp:22"]}`, or, in a tailnet that still writes `acls`: `{"action": "accept", "src": ["laptop"], "dst": ["seat-host:22"]}`. (d) Add `tests` that pin it: `{"src": "laptop", "proto": "tcp", "accept": ["seat-host:22"]}`, and one `{"src": "<other>", "proto": "tcp", "deny": ["seat-host:22"]}` per other user, tag or host that must not reach it | The console saves the policy only when every test passes; a `deny` test that fails names the rule still granting access, which goes back to step (a).
