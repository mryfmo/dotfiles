## Product, principals, protected resources

A chezmoi dotfiles repository (`.chezmoiroot` = `home`) that bootstraps and maintains one operator's macOS laptop and Ubuntu client/server hosts, and that also hosts a multi-agent "regime" orchestration toolchain: Claude Code, Codex and omp agent configuration, hooks, and shell levers under `scripts/orchestrator/` that launch omp "seats" (an orchestrator and workers) on an hcom message bus, audit pull requests with Codex, and merge them.

Principals, from most to least trusted: the operator (one OS user, one GitHub account); the coordinator (a Claude Code session in the main checkout, typically `~/Workspace/dotfiles`); omp seats (`approvalMode: yolo`, contained by Anthropic's `srt` sandbox per seat); Claude Code and Codex sessions in arbitrary projects (contained by each tool's Bash sandbox); content those agents read (repositories, pull requests, bus text: prompt-injection input); GitHub pull-request authors, including outside forks; upstream publishers of downloaded tools.

Protected resources: the operator's unsandboxed execution context and credentials (gh `hosts.yml`, ssh, age key, Claude and Codex logins); the main checkout and its records store; the GitHub repository and its CI secrets (private-dotfiles deploy key, e-mail address, Codecov and benchmark tokens).

## Stack, deployment paths, offline limits

Bash (setup.sh, install/**, levers), Python (hooks, contextdb, generators, CI checks), TypeScript/Bun (omp extensions and hooks), chezmoi templates, GitHub Actions. Deployment modes: macOS client, Ubuntu client and server, a Docker test container, and CI. This run executes nothing from the target (brief U248 forbids it, and no OS sandbox with every required control was used), so every candidate whose proof needs execution is `needs_validation`.

## Entry surfaces and paths

- CI: `pull_request` workflows (contents: read; secrets only for same-repository runs) and `regime.yml` on `pull_request_target` (base checkout; head read as git data; PR body parsed as data).
- Bootstrap and update downloads: setup.sh, install/**, chezmoi externals, `scripts/update-agent-assets.sh`, sheldon plugins; checksums, release attestations, pinned key fingerprints and revisions.
- Agent sandboxes and permissions: managed Claude Code settings (`home/.chezmoitemplates/claude-settings-managed.json`: sandbox on, `autoAllowBashIfSandboxed`, `allowWrite` roots), the `permgate` PermissionRequest hook, the Codex workspace-write sandbox, omp approval overlays.
- Seat containment: `scripts/orchestrator/hcom-seat` writes per-seat srt settings (write roots, deny lists, network allow-list) and an omp shim under `<seats-root>/.sandbox/<name>`.
- Hooks that run outside a sandbox: Claude Code user hooks (`home/dot_claude/hooks`), this repository's project hooks (`.claude/settings.json` -> `.claude/hooks/*.py` -> `.claude/contextdb`), the Codex notify hook, the omp stop gate.
- Bus: `hcom-dispatch` sends lines with a caller-chosen `--from`; seats can write the store.
- Local services: `regime-url-opener` (loopback HTTP, launchd), ssh loopback forwards, the SIWC OAuth loopback callback, systemd/launchd timers (`disk-gc --apply`, usage snapshot, regime supervisor).
