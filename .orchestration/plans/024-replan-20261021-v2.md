## 5. 方針

- **A. 統合優先、dispatch は配賦表の task_id だけ**: 送達可能なのは、第 7 節の各行に task_id・担当 identity・前提が書かれ、その前提が満たされたもの（R1〜R3 の全行が対象。R1 だけではない）。分割後の task_id は配賦表（R1-1 の成果物 `.orchestration/plans/024-allocation.tsv`）で固定する。WIP: active 台帳（第 6 節）が 8 本以下で、未分類の open PR が無いときだけ dispatch する。
- **B. 1 手番 1 動作、すべてコマンド**: 統合は `chain-integrate.sh`（R2-13 まで 3600 秒 alarm 付き、各 step の経過時間を残す）、境界は `boundary-list.sh` → boundary.sh、送信は `send-task.sh`、transport は `transport.sh`。手組み、手入力の sha、ad hoc cp、amend/force-push、`--auto` は禁止。
- **C. 本文の上限**: 新規・リセット・未送達の本文は Checks 込み 200 行以下、allowed_files 8 以下。brief 先行。C-80 ≤ 2、超えたら再分割。未送達の 7 本（verdict-audit-pool-a04、binding-a01、hold-playbook-a02、dispositions-a02、audit-pool-a02、ci-efficiency-followup-a04、record-ledger-carry-a01）は送達前に分割（例外なし、J7）。
- **D. 無人時間帯と操作者不在**: 22:00〜07:00 JST は merge 停止。sandbox 外の操作は操作者不在時には開始しない（在席 = 直近 30 分以内の返答）。gate-bound 操作の前に holds/PING と独立作業。各 merge 後は main の push CI 緑を確認してから次の merge（赤なら凍結、fix-forward 先）。
- **E. 境界**: 150 ファイル・5 MB 上限、超過は分割。gate-ready の code PR がある間は、その regime 前提になる境界以外は後回し（C-110）。bus 照合は copy 前・commit 前・push 前の 3 回。
- **F. Codex 席**: 段階 B まで transport。D-024-20/25: P1-15 配置前の security: true は Codex 席（allowed_files が P1-15 と互いに素）。D-024-37: security: true の新 mechanism 本文（record-json-sync-a01、records-sync-pr-a01）は #436 と P1-15 launcher slice が main に入るまで hold。割当: a010 = P1-15 slice1〜4 と a05、a012 = anchor review と a08、a013 = #448 後に hooks-path。
- **G. DoD-P1**: R3 で述語ごとに実証。未達は L11 の区分で 1 件ずつ。
- **H. 記録の律動**: progress.tsv は毎時（抜けたら理由）。project map はマイルストーンごと。マージ 2 本ごとに第 8 節を実測で直す。
