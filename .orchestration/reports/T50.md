# T50 Report

Status: `ready_for_review`

Implemented `contextdb recall "<query>" [--session <id>] [--k N] [--json]` as read-only, query-conditioned retrieval.

- FTS5 lexical retrieval queries both `events_fts` and `memories_fts`, using `-bm25()` so larger values mean better relevance before min-max normalization.
- Optional semantic retrieval runs only when semantic configuration is enabled and stored vectors for the configured model exist. It embeds only the query through the existing semantic adapter and silently falls back to lexical-only if unavailable.
- Each view uses min-max normalization; absent scores are 0.0 and degenerate single/all-equal views normalize to 1.0.
- Fusion uses `rho * lexical + (1 - rho) * semantic`; defaults are `recall.rho=0.6` and `recall.k=5`, with CLI `--k` override.
- Event closure retrieves same-tool-use, same-session adjacent-id, and shared-file events. Closure items inherit half the parent score, appear directly after their parent, and deduplicate by event UUID while retaining the higher score.
- `--session` restricts events to the exact session and keeps memory visibility to project plus that session.
- JSON preserves each complete event/memory row and adds `record_type`, normalized `score`, display `ts`/`kind`, and `via` (`lexical`, `semantic`, `fused`, or `closure:<path>`).
- The CLI branches before spool draining and uses `ContextStore.connect(initialize=False)`. Its read-only regression pins the database SHA-256 before and after recall.
