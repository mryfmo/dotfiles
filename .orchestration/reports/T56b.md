The SessionStart staleness hook now keeps the first observed epoch for each Claude `session_id`, so later resume/clear/compact invocations compare managed assets against the true session baseline instead of a fresh `date +%s` value.

## Implementation

- Added `agent-session-staleness hook`, which reads the documented Claude hook JSON payload from stdin, validates `session_id` and optional `source`, and rejects payloads over 64 KiB.
- Stores one SHA-256-keyed epoch file per session under `~/.local/state/agent-staleness/`. The directory is forced to mode 0700 and each file to 0600; an advisory file lock makes concurrent first sightings select one baseline.
- The first invocation writes `time.time()` and emits nothing. Later invocations reuse the existing `check --since <epoch>` path, so detection/output logic remains single-source.
- Prunes regular state files older than seven days on a best-effort scan bounded to 1,000 entries and the existing five-second process deadline.
- Contains every hook-specific parse, state, prune, lock, scan, and timeout failure as silent exit 0.
- Replaced only the existing staleness SessionStart command with `agent-session-staleness hook`; async mode, five-second timeout, category order, `check --since`, and doctor integration are unchanged.
- Regenerated `home/.chezmoitemplates/claude-settings-managed.json` through the existing generator.
