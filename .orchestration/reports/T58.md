# T58 Report

Status: `ready_for_review`

`remove-agent-asset <step-name> [--dry-run|--yes]` now consumes the T57 version-1 manifest as the sole inverse map. It defaults to a non-mutating dry run; only explicit `--yes` runs an inverse and atomically removes the completed step record.

## Removal safety

- Filesystem removal requires both a fixed agent-asset root and a normalized prefix from the selected manifest entry. All paths in an entry are preflighted before the first deletion, so a later tampered path cannot leave an earlier valid path partially removed.
- Parent components are realpath-normalized, while the final symlink is deliberately not followed. A recorded link is removed and its external target remains intact.
- Directory deletion is limited to manifest-recorded directories under the fixed roots. Plugin settings (`~/.claude/settings.json`, Codex `config.toml`) are never deleted wholesale by fallback handling.
- A missing step exits 1 and prints the sorted known-step list. Unsupported kinds, unsafe identities, ambiguous Brew formulae, and unrecognized fallback paths also fail rather than guess.
- On successful `--yes`, a same-directory temporary manifest is mode `0600`, rendered with `jq`, and moved atomically over the old manifest.

## Kind inverses and read-only verification

The following local help commands were inspected before implementation:

- `claude plugin --help` and `claude plugin uninstall --help`: inverse is `claude plugin uninstall <plugin>`.
- `codex plugin --help` and `codex plugin remove --help`: inverse is `codex plugin remove <plugin>`.
- `crit --help`: Crit exposes install but no uninstall; the implementation removes only guarded manifest-recorded Crit data/cache paths.
- `herdr integration --help` and `herdr integration uninstall --help`: inverse is `herdr integration uninstall <name>` when available, otherwise guarded path removal.
- Brew uses `brew uninstall <formula>` only when one safe, unambiguous formula is recoverable from recorded commands.

## Doctor taxonomy

`scripts/check-agent-runtime.py` now scans directories/symlinks directly under `~/.agents` and `~/.agents/skills` without deleting anything:

1. Source-derived or explicitly allowlisted runtime/Understand-Anything paths are ACCOUNTED and silent.
2. Manifest-overlapping but no longer source-derived paths are STALE and warn with `remove-agent-asset <step>`.
3. Paths owned by neither source, manifest, nor allowlist are ORPHAN and warn with `manual review required`.

The warnings retain the existing doctor WARN semantics, so warnings alone do not make the command fail.
