# T66b report: Pi workspace-write permission policy

Status: ready for review

## Result

Added a deny-first, Pi-only deterministic workspace layer so the non-interactive
RPC worker can perform bounded productive work without turning ask into allow.

- The extension now gates `read` alongside `write`/`edit`, includes `ctx.cwd`
  in every normalized action, and preserves path bytes for permgate to resolve.
- Pi path tools allow only realpath-resolved descendants of an existing,
  absolute, non-root cwd. Equal-cwd paths, `..`/absolute escapes, symlink
  escapes, symlink loops, invalid cwd, and root cwd fall through to ask.
- Pi Bash allows the exact expanded
  `$HOME/.agents/skills/agmsg/scripts/send.sh ` prefix only when non-empty
  arguments contain no listed shell metacharacter or newline.
- Deny patterns run first. Existing allow patterns run afterward. Claude and
  Codex cannot enable the workspace switch and retain byte-identical outputs.
- `pi.workspace_write=true` and the exact deny/workspace/allow order are policy
  validated; Pi LLM classification remains disabled.

The managed extension's final SHA-256 is
`da95e5a3be363faa9dcd749d781b4bc2e125321409dbfe86e9ea2b9a5659845c`.
