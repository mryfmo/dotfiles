# T66c report: Pi read semantics alignment

Status: ready for review

## Result

Aligned Pi with the established workspace-write baseline: every resolvable
ordinary read is allowed regardless of cwd, while sensitive paths are denied
after realpath resolution. Missing or unresolvable reads remain ask.

- `pi.read_deny_patterns` now declares eight exact families: `.env*`, names
  containing `credentials`, named SSH keys, `.ssh/`, `.aws/`, `.gnupg/`,
  `*.pem`, and `auth.json` below `~/.pi`, `~/.codex`, or `~/.claude`.
- Read decisions are separate from the unchanged write/edit workspace helper.
  In-workspace mutations remain allow; outside/equal/root/symlink escapes remain
  ask.
- Pi still reuses the common Bash allow layer for `gh pr/run/repo` reads,
  `git status/diff/branch/remote get-url`, `ps|pgrep|sysctl`, and known CLI
  version checks. The exact safe agmsg `send.sh` lane is unchanged.
- Claude/Codex golden stdout bytes remain identical. The Pi extension already
  carried `path+cwd`, so it and its managed hash were not changed; SHA-256 stays
  `da95e5a3be363faa9dcd749d781b4bc2e125321409dbfe86e9ea2b9a5659845c`.
