# T66e report: platform-identical strict workspace paths

Status: ready for review

## Result

Pi workspace decisions now use one strict candidate resolver for write/edit and
sensitive reads. It resolves absolute cwd and the candidate parent with
`os.path.realpath(..., strict=True)`, then `lstat`s the final component.
Cwd/parent resolution errors, loops, missing parents, invalid terminal names,
and root cwd all fall through to ask; a missing final name remains the one
intentional write/edit creation case.

Write/edit may create a missing final file under an existing strict parent but
never follows an existing final symlink. Reads require the final component to
exist and strictly follow its symlink so a sensitive target remains denied.
Resolved cwd and candidate aliases share the same canonical namespace, so
macOS `/var` and `/private/var` forms make the same containment decision.

Clean existing-parent writes/edits, ordinary resolvable reads, and plain
escapes retain their prior decisions. Deny precedence and all Claude/Codex,
Pi Bash, policy, and extension paths are unchanged.

## Python contract
