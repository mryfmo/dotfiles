# T67 report: Pi model-access verification

Status: ready for review

## Result

Added `pi-model-access-check`, a shdoc Bash entrypoint that refuses any Pi
version except `0.84.2`, checks only the documented credential-variable name
for the selected provider, runs an exact-`OK` JSON print request, drives a
bounded JSONL RPC request through `agent_end`, prints the ordered envelope
KINDS, and makes the accepted permgate extension an explicit startup input.
Every defined step emits PASS, SKIP, or FAIL; only FAIL produces a nonzero
exit.

Added the operator procedure/result form at
`.orchestration/validation/T67-model-access.md`. It gives the pinned `/login`
UI paths for Claude Pro/Max and ChatGPT Plus/Pro (Codex), `/model`/`Ctrl+L`
catalog checks, `Shift+Tab` thinking-level collection, provider-terms judgment,
future `model_profiles.pi` choices, and the T68 headless gate. It explicitly
forbids recording credentials.

No real Pi binary, provider login, model call, dependency install, chezmoi
apply, Bats run, model-profile edit, commit, or push occurred.

## Pinned-source decision

`get_commands` cannot identify this permgate extension because it registers a
`tool_call` handler, not a slash command. The checker instead supplies the
deployed file through `--extension`. Pi v0.84.2 imports the module and awaits
its factory before startup; loader errors become fatal startup diagnostics and
exit 1. A completed explicit-extension RPC request through `agent_end` is
therefore the positive load signal.
