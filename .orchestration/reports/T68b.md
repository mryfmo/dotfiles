# T68b report: first-class `agmsg_send` tool

Status: ready for review

## Result

Pi workers now send their own `AGMSG-RESULT` through a dedicated extension
tool instead of composing a privileged shell command. `agmsg_send` exposes
only typed `team`, `to`, and `body` strings. Its `from` value is always the
bridge-exported `AGMSG_PI_IDENTITY`; an empty or absent identity fails before
process creation.

The extension invokes the fixed
`~/.agents/skills/agmsg/scripts/send.sh` path with `execFile`, one argv array
`[team, identity, to, body]`, no shell, and a 10-second timeout. Results are a
single fixed success/error line, and child stderr is never returned to the
model. The schema and prompt metadata follow Pi v0.84.1
`docs/extensions.md:1338-1365` and `:1882-1888` plus
`dist/core/extensions/types.d.ts:341-371`.

The bridge now preflights and explicitly loads `agmsg.ts` after `permgate.ts`,
exports its verified identity only to the Pi child, and appends the fixed
instruction to send RESULT with `agmsg_send`. The obsolete send.sh Bash prefix
lane was deleted. Absolute, leading-tilde, and `/bin/bash -lc` send attempts
now fall through to ask. `agmsg_send` itself is intentionally outside
permgate: that extension gates only bash/read/write/edit, while this tool's
safety comes from its constrained implementation.
