# T69 report: CompactionDB Pi extension

Status: ready for review

## Result

Added `contextdb.ts`, a pinned Pi extension that captures three lifecycle
surfaces into opted-in project CompactionDB instances:

- `tool_execution_end` becomes `PostToolUse` / `PostToolUseFailure` with a
  canonical tool name, success, tool-call ID, and only the primary command,
  path, or pattern. Raw tool output is not captured.
- `turn_end` becomes `Stop` with text-only assistant content capped at 240
  characters.
- `session_compact` becomes `PostCompact` with the saved summary and trigger.

The extension checks `<cwd>/.claude/hooks/contextdb_cli.py` at session start,
caches the result for that session, and rechecks on the next session start.
Opted-in events invoke `python3 <cli> ingest --ingested-from pi` with compact
hook JSON on stdin and a five-second timeout. Every handler catches synchronous
and asynchronous errors; capture failures emit one fixed stderr line and never
throw into Pi. Non-opted sessions are silent.

Pinned `tool_execution_end` does not contain args, so the extension retains
only the start event's args in a session-memory map until the matching end
event. No state file or network access was added.

The validator now SHA-256 checks both managed Pi extensions. The final
`contextdb.ts` digest is
`ef21284b72ae8ea9597b3fa0f7dec7ef8d4ba7034dc3fa2287669934dbc199ef`.

`session_before_compact` ledger injection remains intentionally out of scope
as the plan's future extension.
