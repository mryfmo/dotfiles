## What this changes against T124 v3/v4 and T125, and why

1. **Structured verdicts replace the finding grammar (INV-4, INV-5).** Both runtimes validate output against a JSON schema (`codex exec --output-schema`, `claude -p --json-schema`). An audit becomes a JSON document (`findings[]`, `invariants{}`, `verdict`, `orchestration_findings`), rendered to the `.last.md` for humans. Regex parsing of prose, the `blocked`-on-unparsable rule and the headless-prompt drift (SKILL vs AGENTS.md) all go away; the fallback auditor is the same schema on the other runtime. T124 wave 3b's grammar work is redirected to the schema and the invocation (Amendment 3 to wave 3b).
2. **Worker evidence travels in the PR (INV-8).** T124 round 1 named the standing weakness: the gate reads what the orchestrator copies. Committing the worker's `.orchestration/<task>/` files on the branch before the final RESULT makes the Bot review them, lets CI validate their shape (the validator and a JSON-schema check as a required status check), and lets the gate read them from the audited head. The orchestrator's own evidence cannot ride on the branch: the merge is `--match-head-commit <audited head>`, and a commit that adds the audit JSON or the acceptance record would move the head away from the audited one, so those stay in the boundary commit. Cost: PR noise, acceptable; the masker already runs before artifacts are written.
3. **Reviews and audits are headless runs, not seats (INV-2, INV-4).** A `claude -p` run without `--bare` loads the project's hooks (SessionStart `herdr-agents --attach`, the Stop gate), and `--bare` needs an API key rather than the subscription; so every headless review or audit runs from a detached worktree under `.claude/worktrees/` (where the regime's hooks skip, as the SKILL notes for `session-start.sh`) with `--settings` that sets `disableAllHooks` for the run, and `codex exec` runs with `--sandbox read-only` in the same worktree. A design review is `scripts/design-review.sh <design>`: a `claude -p --permission-mode plan --json-schema` (or `codex exec --sandbox read-only --output-schema`) run under a `-review-` identity that joins agmsg for the run and sends its RESULT with the receipt path and hash, so INV-2's history anchor holds without a resident seat; `--max-budget-usd` bounds it. The audit likewise runs in a detached worktree per head from `herdr-agents --audit` or a small `scripts/audit-head.sh`, pooled (two concurrent), started by a watcher when CI and the Bot are green. Resident seats remain for implementation work (agmsg stays the bus per its SKILL; Claude's native messaging is not used while the project is on agmsg).
4. **The reset rule is the vendor's own guidance, made mechanical (INV-6).** "After two failed corrections, start fresh with a better prompt" is Anthropic's documented practice; Osmani's threshold is three failed iterations. Two revises with implementation findings is the count; (d) counts Bot P1 heads after the first RESULT only (the operator calibration question from PR #313: pre-RESULT pushes are the Bot's normal early feedback, which INV-3 deliberately invites). A Codex orchestrator gets the loop-time rule through `[hooks].Stop`, so the T124 v3 statement that only the merge backstop runs under `codex-orchestrate` is withdrawn.
5. **Cost becomes a measured input (INV-10, INV-7).** Headless runs report `total_cost_usd`; seats are read from transcripts. Each tier carries a budget (rounds, wall time, tokens) and passing it pauses the task with a named operator decision, the per-agent budget practice from the field. Model routing follows the tier table: docs tier on `express`, reviews on `review`, design-tier audits on `audit`; nothing changes model mid-session (cache), and effort differences live in seat profiles (effort changes would keep the cache on Fable 5.1, but the independence of a separate context is the lever T124 round 1 demonstrated).
6. **Parallelism with a cap and idle detection (INV-11).** Four workers at most, matching the 3–5 practitioner band and this host; headless reviews and audits do not count. Idle detection from history and the task directory, as T125 drafted.
7. **Dropped from T124/T125:** INV-5's Codex-orchestrator exception; INV-7's prose grammar; T125's `accept-task.py` stays but shrinks (sweep, dispositions scaffold, acceptance rows, gate invocation, merge command) because evidence in the PR removes the copy step.

## Decisions (orchestrator recommendation given to the operator 2026-10-10; in force unless the operator objects)

- **INV-5(d) is redefined, not waived.** The reset rule exists to stop a wrong premise being patched round after round; Bot findings on pre-RESULT pushes are the early-feedback loop INV-3 deliberately invites, so counting them would punish early pushing. (d) counts Bot P1 on two heads after the first RESULT. PR #313 therefore needs no waiver; its acceptance record states the redefinition.
- **agmsg stays as the bus and the history; herdr stays the launch and viewing surface for seats; reviews and audits run headless and join agmsg only for their record.** This environment has three runtimes (Claude Code workers, Codex workers and the Codex Bot, the GPT auditor) and a requirement that the auditor can find the orchestrator's mistakes. INV-2 and INV-6 anchor in an append-only history shared across runtimes, which only agmsg provides (its SKILL names the same properties: history, export, cross-machine sync, cross-type addressing); Claude's agent view and cross-session messaging are Claude-only and session-scoped; agent teams are experimental, cost about 7x, auto-approve teammate plans and have no Codex seat. Cross-vendor verification is a feature (the Codex Bot and the GPT auditor found different defect classes on T119). Native features that do not fragment the history are adopted: `claude -p --output-format json` cost reporting and `--max-budget-usd`, JSON-schema outputs, worktree isolation. Agent view is reconsidered only if Codex seats and the GPT auditor are dropped.
