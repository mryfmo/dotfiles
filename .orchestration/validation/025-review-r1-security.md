## 健全と確認できた統制

- srt の書込 allow-only と読取 open-by-default の意味は README の記述どおりで、auditor の cwd を `allowWrite` に入れない形（【srt-facts Q4】）は表現できる。第 2 脚 #7 の `forbidden.txt` canary はこの点を直接測る。
- 挿入点としての PATH shim は hcom の `which_bin` → `--hcom-tool-path` → `hcom pty` の exec で成立する（【srt-facts Q2】）。pty は hcom が外で確保するので TUI は srt の下で動く見込みが文書で支えられている。
- `--settings` のファイルが無い・不正なときに srt が既定へ fallback せず終了する（README「must also exist」）ので、設定不在は fail-closed。第 2 脚 #1 がこれを測るのは正しい。
- A-2 の install prefix（`~/.local/lib`）をどの席の `allowWrite` にも入れない方針は README の "Where This Package Is Installed" に一致する（hcom 側の抜けは S-04）。
- srt の必須 deny（`.git/hooks`、`.git/config`、shell rc、`.claude/commands\|agents`、`.mcp.json`）は全役割に自動で掛かる。
- 0.0.81 は npm の provenance attestation と signatures を持ち（S-11 はそれを使えという指摘）、既知の srt advisory の対象外。
- 第 2 層（omp policy）の `deny` は `yolo` を含む全モードで絶対で、`pilot/policy.yml` が `tools.approval.eval: deny` を含むのは【b2c2 Q2】の `eval` 迂回を正しく閉じている。
- パイロットの店読みは `sqlite3 -readonly` で、書込は hcom 自身に限る。`--no-session` で omp の session journal も残らない。
- PR 経由 main、`--match-head-commit`、sweep/disposition、gate、`allowed_files` の互いに素は不変（design 5.6）で、計画はそれらに触れていない。
- `src/` の fetch で確認した hcom の runner は秘密を 0755 のスクリプトに書かず 0600 の sidecar に分ける（launcher.rs:1209-1212）。
