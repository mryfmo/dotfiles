## 閉じたと確認できた経路

- PR は repository setting を変えられない: `refs/pull/*/merge` 型の policy を足すのは admin API だけ（F3）。`pull_request` の run の `GITHUB_REF` は `refs/pull/<n>/merge` で branch rule `main` に一致しない（F3 の引用）。閉じるのは「PR が持つ file」に対してであり、admin token を持つ席には U-01。
- `schedule` は default branch の file だけ（S-13 のまま）。`workflow_dispatch` を持つ 4 本（`agent-assets.yml`、`docs.yml`、`private-bootstrap.yaml`、`remote.yaml`）はどれも `inputs:` を定義しない【実測 `grep -n inputs: .github/workflows/*` = 0 行】ので、`main` に対する dispatch は main の file を main の内容で走らせるだけ。
- PR が `pull_request_target` workflow を**新規に足しても**その PR では走らない（base の file が走る）。既存の `regime.yml` は base を checkout、head は `refs/regime/pr-head` に fetch して sha を照合、`regime-ci.py` は `git show` で読み、checker には scratch file の bytes を渡す（`regime.yml:23-39`、`regime-ci.py:4-5,159-170`）。`permissions: contents: read`。
- PR 起因の全 workflow の `GITHUB_TOKEN` は `contents: read`（8 本の `permissions:` ブロック【実測】、`docs.yml` だけ `contents: write` で `pull_request` を持たない）。Actions の approve switch は W0a で `false` を確認（L-11）。
- 除外一覧の正本 `scripts/orchestrator/protected-paths.txt` は `scripts/` 配下 = 保護。chain は `<main>` の scripts が HEAD と一致することを要求し（`chain-integrate.sh:78`）、review worktree には `cd` しない（`:13-14`）ので、PR の head にある一覧は読まれない。
- environment 付き main-push job が別 ref の code を実行する経路: `macos.yaml`/`ubuntu.yaml` の `BRANCH_NAME` は push では `ref_name`（= main）、`private-bootstrap.yaml` は `GITHUB_WORKSPACE` の checkout、`docs.yml` は main の `make deploy`。別 ref の checkout は無い。main の整合性が前提（= 保護パス規則と U-08）。
- `-r2` の dir 分離（r7 で確認）は保たれ、pid の再利用は「再試行しない」方向にしか誤らない。`hcom kill` 前の `herdr pane list` の label 確認（O-11）は変わらず。
- audit 系の allowedDomains に `github.com` 系が無く gh dir も無い（pilot `srt-audit.json`【実測】、§1.3）= environment と ruleset への攻撃面は orchestrator/worker の token だけ。
- `make update` の `--ff-only` + sha 突合で subject の偽装（S-10）は閉じたまま; 残るのは U-08 の「名指しの出所」。
- W0b 後の worker token（`contents: write` + `pull_requests: write`）は `gh workflow run` を打てず（S-03 の処分）、`workflows` 権限が無ければ `.github/workflows/**` の push 自体が拒まれる【未確認: GitHub 側の挙動は網無しで確かめていない。U-09 (b) の受理検査として提案】。
