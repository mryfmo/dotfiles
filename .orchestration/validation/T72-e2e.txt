E2E-π1 bridge round trip (PASS after 5 live rounds; each round's finding
was root-cause fixed by a dedicated task)
-----------------------------------------
Round 1 -> T66b: ask->deny blocked ALL work (4 blocks; no artifact) —
  workspace-write layer added (writes cwd-scoped, send.sh lane).
Round 2 -> T66c: reads gated to cwd blocked legitimate contract reading
  (SKILL.md) — read semantics aligned to the Codex baseline (allow
  everywhere except sensitive families).
Round 3 -> T66d: model used `~/` form; prefix mismatch — leading-tilde
  normalization.
Round 4 -> T68b: model wrapped in /bin/bash -lc — the string-prefix
  design itself was the defect; replaced by the first-class agmsg_send
  tool (identity pinned via bridge env, argv-array spawn, bash lane
  REMOVED).
Round 5 (restore semantics: task P5 queued while the bridge was down,
fetched at startup): hello.txt created (`pi-worker-ok`), and the
worker's OWN result arrived on the bus:
  pi-standard-dot -> claude-deep-dot
  "AGMSG-RESULT v1 task_id=P5 status=ready_for_review note=hello-created"
Bridge lifecycle observed: identity join, bus-task fetch, correlated
prompt, turn events, turn-complete, boundary inbox recheck,
agent_settled tolerance.

Known operational characteristic (recorded, matches the codex-worker
reality): an IDLE bridge only checks the inbox at startup and turn
boundaries; tasks queued while idle need a bridge (re)start as the wake,
exactly as idle codex panes need a nudge. Runbook: queue tasks before
starting the bridge, or restart it.
