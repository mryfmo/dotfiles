## Q3. Reset rule: signals, gaming, waiver visibility

- Right signals: revise count in agmsg history (a'), audits with P0–P2 `specification|implementation` findings (a), Bot P1 heads (d). Wrong or weak as written: (b) and (c) read a file the orchestrator edits and can rename sections in.
- Gaming paths and the counter for each: splitting a round into two RESULTs without a revise (the worker sends RESULT, the orchestrator sends `AGMSG-TASK` again with the same id) — count repeated TASKs as revises; renaming `## Amendment` to `## Clarification` — undetectable by count; the audit prompt names relabelling as an `orchestration` finding, which the orchestrator cannot disposition; omitting an audit file from the gate's cwd — read audits from the main checkout and cross-check with revise count ≥ audits − 1; re-dispatch under a new id — the boundary check above; a single all-encompassing wave — PR ⊆ one wave.
- The waiver is visible, not prevented: `DESIGN_RESET_WAIVED_BY` is a string the orchestrator types into its own command. State that honestly in Trust anchors; add that `check-regime-boundary.sh` lists every acceptance record carrying a waiver, and that the boundary PR body names them, so a waiver cannot land silently. The Makefile target passes only its listed variables explicitly (`Makefile:210-216`); the new ones pass as inherited environment like `AUDIT_EVIDENCE` does today, so no recipe change is needed but the SKILL should say so.

## Q4. INV-7 implementability and the format change

Implementable in `require-crit-review.py` once the finding grammar is fixed. Needed: (1) extend `AUDIT_FINDING` (`:31`) to capture level, confidence and category with an enum of exactly five categories; (2) a finding line that does not parse makes the audit `blocked` (same branch as `:661`), never a silent miscount; (3) number findings in audit order as today (`:688-696`) and map each `audit-finding: <n>` line to its parsed category; (4) for `orchestration` and `conformance` at P0–P2 accept only `waived:<operator>` with `DESIGN_RESET_WAIVED_BY` set; (5) require one `INV-n: holds|violated <file:line>` line per task invariant and a line `Orchestration findings: <count>` so an auditor that was not asked for the category is detectable from its output alone (this is what makes the headless path safe). The prompt at `executable_herdr-agents:1946` and the AGENTS.md Audit section carry the grammar; the headless prompt in the SKILL cites AGENTS.md.

## Q5. Scope and waves

Four waves is the right cut in dependency order, with three changes. Wave 1 validates waves 2–4 only in the sense that their task files pass the validator; it cannot validate their gate logic, so say "validated by" means that. Wave 2 carries INV-3, INV-4 (gate part), INV-5 and INV-7, almost all enforcement, in the operator-routed shared source; split it into 2a (design-review evidence and per-invariant lines) and 2b (reset rule and category lock), each its own PR with its own audit, since `test_require_crit_review.py` is already 1167 lines. Wave 3 names two seats for one PR: `agent-stop-gate.sh` is a Claude hook (Codex seat) and `executable_herdr-agents` is not in the boundary list (Claude seat); make it 3a and 3b, and 3a shrinks to the orchestrator-side INV-5 stop check once INV-4 leaves the stop gate. Wave 4 (dispatch pre-check) adds little given INV-1's verdict; fold the worker-side run into wave 1's SKILL text and drop the dispatch change, or keep it as a last, optional wave. Also add to wave 2a the `pr-feedback.py` commit-id field, which INV-5(d) needs.

## Q6. What the design should not do

- Put INV-4 in the Stop hook (Claude-only, 3 s budget, no YAML parser in bash); it belongs in the gate.
- Compare `reviewed_at` with commit timestamps; use agmsg history order.
- Count orchestrator-written files from the gate's cwd; count from the main checkout and from agmsg history.
- Apply the validator to all 311 existing task files at every boundary; grandfather by task id or by a `format: 2` front-matter key.
- Make prose paths `security: true`.
- Accept `waves` as a key; require PR ⊆ one wave.
- Claim the orchestrator "cannot waive"; it can type the waiver, the mechanism makes it visible.
- Carry a second high-risk pattern list.
- Promise that the worker-conduct failure of T119 is closed; it is not, without a permgate-log check.

Design verdict: revise
