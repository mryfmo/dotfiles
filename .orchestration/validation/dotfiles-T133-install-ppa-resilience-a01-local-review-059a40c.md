Full review comments:

- [P1] Recognize apt's download-failure summary on the outage path — install/ubuntu/client/ghostty.sh:57-59
  When the Ghostty .deb download returns 503, apt normally follows `E: Failed to fetch ...` with `E: Unable to fetch some archives, maybe run apt-get update or try with --fix-missing?`. This catch-all treats that summary as an unrelated error and returns 100, so a PPA-only outage still fails the apply and required CI check. Recognize the fetch-failure summary without suppressing independent errors, and include it in the pool-failure fixture.

- [P2] Set a stable locale before classifying apt diagnostics — install/ubuntu/client/ghostty.sh:53-53
  In a non-English session, such as `ja_JP.UTF-8` generated by `setup_locale.sh`, apt translates the diagnostics that this parser matches. Because the captured commands inherit that locale, PPA fetch failures miss the English patterns and fail instead of taking the retry path. Run the inspected commands with `LC_ALL=C`, ensuring that locale also reaches apt through sudo.

- [P2] Add a threat-table row for the executed smoke script — .orchestration/dotfiles-T133-install-ppa-resilience-a01/task.md:18-18
  The new `smoke.sh` extracts PR-controlled shell code from the test file and executes it with `bash -c`, but this table covers the wildcard only as command-output and learning records. The threat-table rules require concrete coverage for executed scripts under a wildcard, not just data-file coverage ([AGENTS.md:78](AGENTS.md#L78)). Add a dedicated control row for `smoke.sh` with its test or compensating control.
