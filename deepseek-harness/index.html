    DeepSeek harness (dsh) under srt¶

    The DeepSeek harness control host runs under Anthropic's sandbox-runtime as the dsh role of scripts/orchestrator/hcom-seat (installed as ~/.local/bin/common/hcom-seat; regime-cutover U272, after the four audits of the standalone launcher of PR 687 withdrew it). From a checkout of this repository, hcom-seat dsh [--profile <name>] [--home <DSH_HOME>] -- <dsh args> renders the worker seat's srt settings with the role's own rows and nothing else: the write roots are DSH_HOME (the --home option, else the environment's DSH_HOME, else ~/.dsh), a per-launch state slot <seats-root>/.state/dsh-<utc stamp>-<pid> holding the scratch cwd and the bridge child's CLAUDE_CONFIG_DIR, the role's own omp profile ~/.omp/profiles/dsh (where the login child omp auth-gateway stdio lives, selected by OMP_PROFILE) and ~/.omp/run; the read grants are the role's own as well (the scratch cwd and its state slot, DSH_HOME, ~/.omp/profiles/dsh, ~/.agents/skills and the lever's pinned tool directory; U272c). srt reads everything an explicit deny does not name, so a grant the role lacks denies nothing: the role's containment is a deny list it owns (U272d). After the worker's read denies (credentials, the operator's Claude Code state, ~/.omp/agent, the chezmoi sources, ~/Workspace, ~/.local/state/hcom, every seats root, the main checkout), the dsh settings deny for read and for write the physical paths of the checkout's git directory and git common directory, the .git entry of every linked worktree git lists, the hcom store HCOM_DIR and every existing ~/.local/state/hcom-* sibling store (the lever's own hcom-seat directory excepted), the records directory <checkout>/.orchestration and every other seat's directory under the seats root. Every row of the settings' final allowRead and allowWrite lists is judged against every row of their final denyRead and denyWrite lists (every path compared physically and by identity), and a grant that is, contains or lies inside a deny is refused by name before any directory is made, the only exemptions being the own slot and cwd against the seats-root and project-file rows they overlap by construction and the own profile against the profiles deny, each by a tag the rendering attaches and only while the grant lies where it is rendered (U272f); the per-launch slots are removed with their modes reset, a slot that remains failing the launch with exit 2 on a normal exit and under a signal alike (U272e, U272f). Git directories elsewhere on the host are not computed by the lever and are not denied. The domain list, no unix socket and no local binding are the worker's. The lever's existing containment does the rest: every tool it runs outside the sandbox is pinned by its physical argv and refused when it, or a directory above it, has the identity of any seat write root, DSH_HOME included from the first statement, so a node or python3 planted under DSH_HOME never runs; the shim <seats-root>/.sandbox/dsh-<stamp>-<pid>/bin/dsh proves the sandbox with the four-word canary (a write into the sandbox directory, reads of the settings file and ~/.ssh, a write under the operator's ~/.claude/debug must all fail inside) and only then execs srt --settings <file> -- /usr/bin/env PATH=<seat path> <DSH_HOME>/bin/dsh [--profile <name>] <args>; the lever runs that shim in the foreground under /usr/bin/env -i with HOME, USER, LANG, TERM, PATH, DSH_HOME, OMP_PROFILE and a caller's CLAUDE_CODE_OAUTH_TOKEN alone, waits, removes the per-launch slots and returns dsh's status; a hangup, interrupt or termination runs the same removal before the lever ends by that signal. Before the launch the lever places the kit's rendered overlay ~/.agents/omp/profiles/dsh.yml (the bridge route as modelRoles.default, the bridge extension, the seat providers off) as the profile's own ~/.omp/profiles/dsh/agent/config.yml, the file the gateway child reads for its providers, with the extension entry at its canonical allow-list path; the write is one run of the pinned helper profile-config-place.py beside the lever, every step on one held descriptor of agent/ (dir_fd, O_NOFOLLOW: the compare, an exclusive create at a random name, the write, the rename, a read-back), so an equal file is left alone, a different one replaced, and a linked agent/ or config.yml, a directory at config.yml, an entry at the temporary's name or a failed step refuses with exit 2 naming the step (U310, U310d; tests/unit/test_profile_config_place.py). The dsh runtime is never executed outside srt. Two launches at once share no settings file. The role's rows and the hazard-by-hazard account of the four verdicts are in scripts/orchestrator/README.md ("The dsh role") and the tests in tests/unit/test_hcom_seat_dsh.py.

    The router role (regime-cutover U321). The dsh-superagent Router runs under the same lever as hcom-seat router [--profile router] [--home <DSH_HOME>] -- <dsh args>, one more row of the role table: the dsh row's containment (the per-launch slot, the write roots, the deny row, the four-probe canary, OMP_PROFILE=dsh and the shared omp profile, the environment list, the slot removal) with three cells of its own. The DSH profile is router and the only one the role accepts; --profile router or none, any other refused by name, exit 2, before any tool is resolved. The srt settings carry allowLocalBinding: true for this role alone, because U317b measured (2026-11-07T00:12Z, the prototype at pin 8c32a9dc) that the Runtime does not start without the dsh-host-webserver plugin, so the Router needs its loopback listener; srt 0.0.81 has no loopback-only form, so the grant is bind and inbound on every interface, and what the listener answers is bounded by the upstream Management API's host check (the hosts 127.0.0.1:<port> and localhost:<port> alone, and only with the x-orchestrator-request header, upstream docs/006-deployment.md); the port is the profile's, the role grants binding and no port. The Router's state root <DSH_HOME>/router-state, where U317b renders stateDir, is a write root of its own (allowWrite row 6, after ~/.omp/run, inside DSH_HOME), judged like any untagged row. The router settings differ from the dsh settings in exactly those two values, the dsh and omp roles' settings do not change by a byte, and tests/unit/test_hcom_seat_dsh.py asserts both.

    The install itself is contained the same way (regime-cutover U322). On a host whose operator opted in (DSH_HOME exported and equal to ~/.dsh), make update runs update_deepseek_harness in scripts/update-agent-assets.sh: it downloads GitHub's tag archive, checks its sha256 against the manifest pin before anything is unpacked, unpacks the tree under ~/.dsh/dsh/<tag>.<suffix> and then runs every piece of upstream code inside srt through one shared function, build_under_srt: pnpm install --frozen-lockfile and pnpm run build in the new tree, and pnpm install in the thak profile. Each run is /usr/bin/env -i HOME=… PATH=<mise pnpm and node> DSH_HOME=… <the cache and log variables> srt --settings <file> -- pnpm …: the environment is sanitised outside srt, so no variable of the caller reaches the build, and srt's own injected variables (SANDBOX_RUNTIME, the HTTP_PROXY pair its sandbox routes every connection through, its TMPDIR) reach the command untouched (regime-cutover U322b). The settings file is created 0600 beside the tree and removed after the run; its allowWrite is the build directory, ~/.dsh/.pnpm-store and pnpm's store operation lock directory <physical /tmp>/pnpm-store-operation-locks-<uid> (0700, this user's, made before the run, a planted entry refused by name; regime-cutover U363), its denyWrite the paths srt 0.0.81 would otherwise grant on its own (/tmp/claude, /private/tmp/claude, ~/.npm/_logs), while the tools' caches and logs are pointed under the store (CLAUDE_CODE_TMPDIR, the XDG directories, pnpm's store-dir, cache-dir and state-dir, npm's cache and logs-dir); its denyRead is the credential and state list the dsh seat role denies (~/.ssh, ~/.gnupg, ~/.aws, ~/.netrc, ~/.docker, ~/.kube, ~/.config/gcloud, ~/.config/gh, ~/.codex, ~/.omp/agent, ~/.omp/profiles, the hcom stores, the chezmoi sources, ~/Workspace, the seats root, the operator's Claude Code state) plus the dotfiles checkout and its git common directory, and its network.allowedDomains is the default registry plus the host of every tarball: row of the tree's pnpm-lock.yaml (the pinned tag adds cdn.sheetjs.com), never a wildcard; no local binding, no unix socket, no pty. Before the first build the step runs the U272 canary under the same settings, one write beside the tree, and refuses the install unless srt denies it. srt is the kit's mise pin; a host without it gets no build and no install. The tests are in tests/unit/test_update_agent_assets.py (DeepseekHarnessTest, the U322 and U322b groups).

    The dsh-superagent intake (regime-cutover U317) is a second profile under the same role: assets.dsh-superagent pins the prototype at one commit with the sha256 of GitHub's archive and zero patches, update_dsh_superagent (the harness step's sibling, the same DSH_HOME opt-in) installs it under $DSH_HOME/plugins/dsh-superagent and runs pnpm install in the rendered router profile, whose package.json links it beside the omp-gateway plugin. Every archive member must lie under the one root that names the pin, and the upstream build (pnpm install --frozen-lockfile && pnpm build) runs inside one srt --settings invocation whose writes are the new tree and $DSH_HOME/.pnpm-store, whose reads deny the credential roots the dsh role denies, and whose network is the package registry alone; the profile install runs the same way with the profile directory as its write root. srt, pnpm and node are the kit's mise pins, and an absent srt refuses the step before any download. The rendered home/dot_dsh/profiles/router/cordis.patch.yml keeps the thak rows (the session log upload off, the API-key rows and the harness sandbox disabled, the default model on the gateway provider), binds the panel to 127.0.0.1:3082, puts stateDir at $DSH_HOME/router-state (inside the role's write root; the listener itself waits for a router role with the loopback grant, U321), and restates the bundle's two agent presets with their sandbox rows disabled. The GitHub Source row (assets.dsh-superagent.sources.github: the repository and accept_mode: observe, the M-18 ladder row) is data for the Management API save; in observe mode the allowed list is empty, so a positive assessment is an ignore Decision marked would-accept and nothing is accepted. hcom-seat router -- --no-open starts the Router under srt, and intake-observe.py <orchestrator.sqlite> <decisions.tsv> appends the would-accept Decisions as rows, reading the store read-only, creating the table with the decisions.tsv header when it is absent, and refusing to run when its own sha256 differs from its manifest pin.
