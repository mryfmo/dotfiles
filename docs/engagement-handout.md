# Engagement handout: the prepared host, the client repository and the program store

An engagement receives three artefacts. The prepared host is a machine where `./setup.sh`, `make update` and the seat logins have run and `make doctor` exits 0. The client repository is the checkout that `regime-init <program>` has initialised, with its checkout guard and its `## Audit` section in `AGENTS.md`. The program store is the directory `.orchestration/orchestrate/<program>/` with its five files (`preferences.md`, `units.tsv`, `ledger.tsv`, `decisions.tsv`, `gates.md`), placed by the same run. Every section below names the command that produces the artefact and the read-only check that proves it, in the shape of the [G16 operator handout](operator-handout-g16.md): a dated page pinned to a commit, hosts named by kind, every row a command and its check. The facts are measured on `origin/main` c92078d0 on 2026-11-04; the file and line citations are to that commit. The readers are the operator of the engagement and the coordinator; a seat runs no command on this page. The page names the two seat roles, `orchestrator` and `worker`, since every audit is one fresh `~/.local/bin/common/pr-audit.sh <n> --records <store>` run from a terminal outside every seat and no seat login serves it.

## The doctor gate before any seat

A seat starts on a host with `hcom-seat orchestrator`, then `hcom-seat worker`, typed from a terminal outside every seat (`scripts/orchestrator/hcom-seat:71-73,85`), and only after `make doctor` on that same host has exited 0 with the `Seat logins` section listing `orchestrator` and `worker` as `found`. The doctor's `Agent tools` section reports `omp`, `hcom` and `srt` against the mise pin (`scripts/check-tools.sh:446-449`, `:240-281`); an `srt` that differs from the pin is a required failure whose remedy is `make update`. The launcher reads the same facts: `hcom-seat` declines to start a seat when `srt` is missing or off the pin, or when the role's login is absent (`README.md:118-123`). The gate is therefore one fact read twice, once by the operator through `make doctor` and once by the launcher. A login is per host and the operator's own step; nothing copies a token between hosts ([Seat logins on a remote host](remote-host-logins.md), first paragraph).

The hosts are named by kind: the operator's macOS laptop, and the Ubuntu seat host reached with `herdr --remote <ssh-target>` (`README.md:90-91`). The table is the coordinator's own run of `make doctor` on each host on 2026-11-04; run `make doctor` again on the host before starting a seat there, and if its summary line differs from the row, read the host's output, not this page.
