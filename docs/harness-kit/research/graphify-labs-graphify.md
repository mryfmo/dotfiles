## Verdict

- graphify is a **code and knowledge graph builder plus query layer**, not an agent memory store and not a harness. Code is parsed locally with tree-sitter into a NetworkX graph (`calls`, `imports`, `inherits`, communities); docs, PDFs, images and transcripts enter through an optional LLM pass; there are no embeddings and no database. The "memory" in its marketing is the hosted product; the open-source package has only a deterministic `save-result` / `reflect` journal of Markdown files.
- Three query surfaces: the `graphify` CLI (`query`, `path`, `explain`, `affected`, exit codes 0/3/4), the Python library, and `graphify-mcp`, a ten-tool MCP server over stdio or streamable HTTP. The `/graphify` skill and the always-on `PreToolUse` hooks are what change an agent's behaviour: query the graph before grep, strict mode refuses raw reads until a query ran.
- Runtime is Python 3.10+ installed with `uv tool install graphifyy`; a code-only build is offline and keyless. Provider keys (`GEMINI_API_KEY`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `MOONSHOT_API_KEY`, `DEEPSEEK_API_KEY`, Azure, Bedrock) are read from the environment only for the semantic pass; `GRAPHIFY_API_KEY` only for the HTTP transport.
- Against this repository's MCP parity policy the local server is admissible only as a Codex-only, `enabled: false` stdio entry whose one required argument is an absolute per-project `graph.json` path, which makes a manifest entry pointless; the Claude Code route is the operator's `claude mcp add --scope user`, outside the repo by policy; the hosted OAuth route is a SaaS connection the policy asks to review before enabling. The no-token-literals rule is not in tension: graphify stores no keys and references them by environment-variable name.
- Recommended shape if trialled: pinned `uv tool install`, `graphify install --project` inside one project so nothing lands in the generated `~/.claude`, `~/.codex` or `~/.agents` trees, code-only extraction, no manifest MCP entry.

## 1. What it builds a graph of

### 1.1 Code

- README ("What it does" table) and `docs/how-it-works.md`: "Pass 1 — Code structure (free, no API calls)". Tree-sitter parses code files and extracts classes, functions, imports, call graphs and inline comments; "About 40 languages are supported: 33 are parsed with tree-sitter grammars and 7 (Dart, Apex, COBOL, Razor, Blade, Pascal and Robot Framework) use built-in parsers." Cross-file `calls` / `imports` / `inherits` / `mixes_in` edges are resolved after extraction.
- `ARCHITECTURE.md`, "Pipeline": `detect() → extract() → build() → cluster() → analyze helpers → report.generate() → export.to_*()`. Stages exchange plain dicts and NetworkX graphs. The extraction schema is `{"nodes": [{id, label, source_file, source_location}], "edges": [{source, target, relation, confidence}]}` and `validate.py` enforces it before `build()`.
- `pyproject.toml` `dependencies`: `networkx>=3.4`, `numpy`, `rapidfuzz`, `pyyaml`, `tree-sitter>=0.25,<0.26` and 26 grammar packages (python, javascript, typescript, go, rust, java, groovy, c, cpp, ruby, c-sharp, kotlin, scala, php, swift, lua, zig, powershell, elixir, objc, julia, verilog, fortran, bash, json). Extras add sql, hcl, pascal, ocaml, commonlisp, dm, vb.net, r, erlang, solidity.
- Communities: Leiden through the `leiden` extra (`graspologic`); without it "clustering silently uses networkx Louvain. Switching later reshuffles every community" (README, "Labeling and rendering limits"). Community labels are "LLM-free" by default with an optional `label` command that calls a backend.
- Rationale: "`# NOTE:` / `# WHY:` comments and ADR/RFC citations become first-class nodes linked to the code" (README table, "Rationale + doc refs").

### 1.2 Knowledge (documents and media)

- `docs/how-it-works.md`, "Pass 3 — Docs, papers, images (LLM subagents, costs tokens)": the assistant's subagents, or a headless backend with `graphify extract --backend`, read Markdown, PDFs, images and transcripts in batches and return JSON fragments. "Code files are not sent to the LLM semantic extractor in the normal pipeline. If a corpus contains only code files, Pass 3 is skipped entirely."
- Pass 2 transcribes video and audio locally with faster-whisper (`video` extra).
- "No embeddings needed ... The graph structure is the similarity signal — there's no separate embedding step or vector database." The README's first bullets repeat this: "Not a vector index. No embeddings, no vector store."

### 1.3 Agent memory

Two distinct things carry the word "memory", and only the first exists in the open-source package.

- Work memory (local, deterministic). `graphify save-result --question ... --answer ... --nodes ... --outcome useful|dead_end|corrected` writes one Markdown file with YAML frontmatter under `graphify-out/memory/`. `graphify reflect [--graph graphify-out/graph.json]` aggregates them into `graphify-out/reflections/LESSONS.md` with preferred, tentative, contested, dead-end and corrected sections (`graphify/reflect.py` module docstring: "It is deterministic: no LLM, stable sort orders, byte-stable output"; a node is promoted to preferred only after `--min-corroboration` distinct useful results, default 2, with a 30-day half-life). `serve.py:_read_graph` attaches this as a `_learning_overlay` so `query` and MCP output can annotate node lines; the docs call it "an optional layer over graph exploration, not a replacement for current source evidence" (docs, "Record useful findings").
- Agent memory (hosted only). "Memory for each repository, shared with the workspace" and the `graphify_patterns`, `graphify_impact`, `graphify_tests_for` tools exist only on `https://api.graphify.com/mcp` (docs, "Graphify vs Graphify CLI", "Only in Graphify"; `for-agents.md`: "Do not assume open-source Graphify's MCP server has the same tool set").
- The LOCOMO and LongMemEval numbers in the README (recall@10 0.497, QA 45.3%, LongMemEval-S 76%) measure the graph used as a conversational-memory retriever in graphify's own harness with Kimi K2.6 as the shared model (`BENCHMARKS.md`, last updated 2026-07-05). **Inferred**: they say the graph retrieves well when conversation transcripts are the corpus; they do not describe a memory API an agent writes to at runtime.

### 1.4 Provenance

- Every edge carries `confidence` in `EXTRACTED` (explicit in the source, score 1.0), `INFERRED` (with a `confidence_score` on a discrete rubric 0.95 / 0.85 / 0.75 / 0.65 / 0.55) or `AMBIGUOUS` (flagged in the report), plus `source_file` and `source_location`; a repeated relation keeps the strongest copy and lists the others under `also_seen` (`docs/how-it-works.md`, "Confidence tagging" and "The graph format"). `graphify path` ends with the path's overall confidence, "that of its weakest hop" (README).
- `graph.json` records `schema_version`, `graphify_version` and `built_at_commit` (README; `serve.py` reads `built_at_commit` into `G.graph["_built_at_commit"]`).
- Edge direction is stored as arc order even though the file says `"directed": false`; loaders must go through `paths.load_node_link_graph()` (`ARCHITECTURE.md`, "Edge direction in graph.json"). **Inferred**: anything in this repository that reads `graph.json` directly should use that helper, not `networkx` alone.

## 2. Storage and query interfaces

### 2.1 Storage

- Output directory `graphify-out/` (override `GRAPHIFY_OUT`): `graph.json`, `graph.html` (skipped above `GRAPHIFY_VIZ_NODE_LIMIT`, default 5,000 nodes), `GRAPH_REPORT.md`, `cache/` (SHA256 per file), `memory/`, `reflections/`, `converted/` (Office and Google Workspace sidecars), `wiki/` after `--wiki`. Load cap `GRAPHIFY_MAX_GRAPH_BYTES` 512 MiB (docs, "Environment variables").
- Exports: Obsidian vault, SVG, GraphML, Canvas, Cypher text, direct push to Neo4j (`--neo4j-push bolt://...`) or FalkorDB (`exporters/graphdb.py`; `ARCHITECTURE.md` module table). The team workflow commits `graph.json` and registers a git merge driver (docs cookbook "Share a code graph with your team"; the always-on block says "A committed graphify-out/graph.json is rewritten whole on every build, so a large diff to it in a pull request is expected").
- Query logging is off by default and writes JSON Lines to `~/.cache/graphify-queries.log` only with `GRAPHIFY_QUERY_LOG_ENABLE=1` or `GRAPHIFY_QUERY_LOG=<path>` (`graphify/querylog.py:14-25`). The README's Privacy section still says it is on by default; the code and the docs table say off (#1797). **Inferred**: the README sentence is stale.

### 2.2 CLI

- `graphify extract <path> [--code-only] [--backend NAME] [--force]`, `graphify update .` (incremental, AST-only, no API cost), `graphify watch`, `graphify query "<question>" [--dfs] [--budget N]`, `graphify path A B`, `graphify explain X`, `graphify affected "<node>"`, `graphify god-nodes`, `graphify export <format>`, `graphify merge-graphs`, `graphify global add`, `graphify prs [N | --triage | --conflicts]` (uses `gh`), `graphify hook install` (git post-commit and post-checkout), `graphify save-result`, `graphify reflect`, `graphify provider add|list|show|remove`, `graphify install [--platform X] [--project]`, `graphify uninstall [--purge]` (README "Common commands"; docs "CLI reference").
- Exit codes for scripts: `0` an answer, `3` an ambiguous name (candidates listed, never guessed), `4` no matching node (README, "Using the graph directly").

### 2.3 Library

- `from graphify.extract import extract; extract(paths, root=Path(".").resolve())`; `ARCHITECTURE.md` insists on passing `root` so node ids are relative to the project, not to the file list. `serve.py:_read_graph(graph_path)` is the library-grade loader; `tests/test_architecture_doc.py` imports every symbol in the module table so the documented signatures cannot drift.

### 2.4 MCP server

- Entry point `graphify-mcp = "graphify.serve:_main"` (`pyproject.toml` `[project.scripts]`), in the `mcp` extra (`mcp>=1,<3`, `starlette>=1.3.1,<2`, `anyio>=4.14.2`; the comment pins `starlette` above two 2026 CVE fixes). Also reachable as `graphify <path> --mcp` from the skill.
- Transport: stdio by default (`serve()` uses `mcp.server.stdio.stdio_server`, `serve.py:3164-3176`); `--transport http` is streamable HTTP on `127.0.0.1:8080/mcp` by default with `--api-key` or `GRAPHIFY_API_KEY` checked as `Authorization: Bearer` or `X-API-Key`, a warning when bound to `0.0.0.0` without a key, and `--stateless`, `--json-response`, `--session-timeout` flags (`serve.py:3324-3414`; docs "MCP server quickstart").
- Ten tools (measured from `serve.py`, matching the docs page): `query_graph` (BFS or DFS, `depth` 1-6, `token_budget` default 2000, `context_filter`), `get_node`, `get_neighbors` (`relation_filter`), `get_community`, `god_nodes` (`exclude_hubs_percentile`), `graph_stats`, `shortest_path` (`max_hops` 8, `undirected`), `list_prs`, `get_pr_impact`, `triage_prs` (the three PR tools shell out to `gh`). Every tool accepts an optional absolute `project_path` to another `graphify-out/graph.json`; contexts are cached in an LRU of `GRAPHIFY_MAX_CONTEXTS` (default 8) keyed by mtime and size, so the server reloads when `graph.json` changes. Resources `graphify://report` and `graphify://god-nodes` are published.
- Guards: `security.validate_graph_path()` requires the path to resolve inside a `graphify-out/` directory; `sanitize_label()` strips control characters from text returned to agents; node labels and rationale text pass `redact_secrets()` before being written (`SECURITY.md`, "Threat Surface").
- The MCP server makes no model calls ("Do I need a model for the MCP server? No", docs "LLM providers").

## 3. How an agent harness would use it

### 3.1 Code navigation

- The skill body (`graphify/skill-codex.md`, the Codex variant; `skill.md` is Claude Code's) has a fast path: "check whether `graphify-out/graph.json` exists ... skip Steps 1–5 entirely and jump straight to `## For /graphify query`". It also says when a graph is worth building: "With no graph, one targeted lookup ... is faster and free with a plain text search such as `grep` and `Read`"; build one when many questions are expected, the corpus is large or unfamiliar, or the question needs doc-to-code links or structure (communities, bridges, import cycles).
- The always-on blocks (`graphify/always_on/agents-md.md`, `claude-md.md`) tell the agent: run `graphify query "<question>"` before the first grep or source read for a codebase question, "put this rule in every subagent prompt that explores code", use `path` for relationships and `explain` for one concept, read `GRAPH_REPORT.md` only for broad review, and run `graphify update .` after modifying code.
- Claude Code gets a `PreToolUse` hook pair: matcher `Bash|Grep` runs `<exe> hook-guard search`, matcher `Read|Glob` runs `<exe> hook-guard read [--strict]`, timeout 10 s (`graphify/install.py:506-511`). Strict mode "blocks raw file reads until the agent has queried the graph", with `GRAPHIFY_HOOK_STRICT_TTL` (1800 s) and `GRAPHIFY_HOOK_NUDGE_CAP` (5 reminders per session) (docs "Environment variables", "Hooks and the agent loop"). Codex gets `.codex/hooks.json` with a `PreToolUse` `Bash` hook running `hook-check`, which the installer itself calls "intentional no-op; Codex Desktop rejects additionalContext on PreToolUse, so graph guidance comes from AGENTS.md" (`install.py:1946-1948`).
- Subagent extraction on Codex needs `multi_agent = true` under `[features]` in `~/.codex/config.toml` and uses `spawn_agent` / `wait_agent` / `close_agent` (`skill-codex.md`, Step B2). A code-only corpus never reaches that step.

### 3.2 Memory

- Open-source: the agent (or the operator) calls `graphify save-result` after a verified answer and `graphify reflect --if-stale` at session start; the lessons file is meant to be loaded as orientation. Nothing is automatic; the skill does not call `save-result` on its own. **Inferred**: this is a write-through-CLI journal, not a store a harness queries, and the hosted "Memory" is what the marketing means by "always-on memory".

### 3.3 Provenance

- `EXTRACTED` / `INFERRED` / `AMBIGUOUS` tags and `source_file:source_location` let a reviewer separate what the source states from what graphify resolved. The hosted docs' own warning applies to the local tools too: "A returned path is source-level context, not proof of runtime execution" (docs "MCP tool reference").

## 4. Runtime

- Language and install: Python 3.10+, `uv tool install graphifyy` (or pipx), optional `graphifyy[mcp]`, `[leiden]`, `[pdf]`, `[video]`, `[all]`. The `dm` extra needs a C toolchain on macOS and Linux; everything else ships wheels (`pyproject.toml` comments).
- Database: none. The graph is JSON on disk; Neo4j and FalkorDB are optional export targets.
- Embeddings: none, by design (`docs/how-it-works.md`).

## 5. Conflict with the MCP parity policy and the no-token-literals rule

### 5.1 Parity policy (Codex only, disabled by default)

Repository rules read:

- `home/dot_agents/README.md:25-27`: every MCP server in `agent-config.yaml` targets Codex only; the validator rejects `agents.claude: true`; Claude Code user-scope servers live in `~/.claude.json`, "which this repository does not manage; add a Claude server with `claude mcp add --scope user`"; the generated Codex config must hold exactly the declared names; servers "remain disabled by default. Enable them locally only after confirming credentials, filesystem scope, and network behavior."
- `scripts/validate-agent-assets.py:1512-1537`: `enabled` must be `False`; `agents.claude` refused; the enabled agent set must equal `{"codex"}`; transport `stdio` needs `command`, `http` needs `url`; `sampling` must be false; deprecated packages refused. `:1540-1544` compares manifest and Codex names. `:1198-1202` requires `enabled = false` on every rendered Codex server.
- `home/dot_agents/agent-config.yaml:1071-1072`: `mcp_servers: {}` with the comment "MCP servers are declared only when one is enabled for a target agent."
- Live state is looser than the manifest: `home/dot_codex/modify_private_config.toml` preserves "Current-target tables outside the generated baseline" (`README.md:47`), and **measured** `~/.codex/config.toml` on this host holds one operator-added `[mcp_servers.node_repl]` table with no `enabled` key while the manifest holds none; `check-agent-runtime.py` has no `mcp_servers` check (grep, no match). `~/.claude.json` holds no `mcpServers` on this host (measured).

Where graphify fits:

1. The local stdio server is admissible under the policy in form: `transport: stdio`, `command: graphify-mcp`, `args: [<absolute>/graphify-out/graph.json]`, `enabled: false`, `agents: {codex: true}`, `sampling: false`. It fails in substance: the one required argument is an absolute per-project `graph.json` path, which a dotfiles manifest cannot carry portably, and the server is useful only when enabled. The `project_path` tool argument lets one server serve many projects, but the server still needs a default graph to start (`serve.py:3164`, `_default_graph_json`). **Inferred**: a disabled, pathless placeholder would satisfy the validator and serve no one.
2. The Claude Code route the docs give (`claude mcp add --transport stdio graphify -- graphify-mcp ...` or an edit to `~/.claude.json`) is exactly the route `README.md:25` reserves for the operator outside the repository. No change to the repository is needed or allowed for it.
3. The hosted route (`[mcp_servers.graphify] url = "https://api.graphify.com/mcp" auth = "oauth"`) is an `http` transport to a third-party SaaS with OAuth tokens stored by Codex; it is admissible in form only as `enabled: false`, and the README's rule 3 asks for a credentials, scope and network review before enabling. The renderer emits `url`, `bearer_token_env_var`, `http_headers` and `env_http_headers` for an `http` server (`scripts/generate-agent-configs.py:494-499`) and no `auth` key, so an OAuth entry cannot be expressed in `agent-config.yaml` today; a bearer-token entry could, as an environment-variable name.
4. The skill and CLI paths bypass MCP altogether and are the path upstream itself prefers for Codex ("Instruction-file platforms (Codex, OpenCode, Cursor, etc.): persistent instruction files provide the same query-first guidance", README). They collide with a different repository mechanism: the skill audience map. A graphify skill must be declared in `skills.audience` or the doctor warns, and it must be placed where only the named agents read it. `~/.codex/skills` (upstream's Codex default) is a root this repository does not render or check.

### 5.2 No-token-literals rule

- `README.md:29`: "Public dotfiles must not contain token literals. Credential-bearing servers inherit environment variables or refer to private configuration only." `agent-config.yaml:12`: "Store credentials as environment-variable references or inherited environment only."
- `validate-agent-assets.py:250-271` (`SECRET_RULES`): provider rules for `ghp_`, `github_pat_`, `sk-` keys, and assignment rules for quoted `api_key` / `api-key` / `apikey`, `password`, `secret`, `token` values; `:2481-2540` scans every tracked, non-ignored file (JSON per string) and fails on any finding not covered by a `SECRET_ALLOWLIST` row with a reason.
- Graphify's design agrees: it stores no keys (`SECURITY.md`), reads provider keys from the process environment, and `graphify provider add --env-key NAME` persists the variable name ("The key itself is never stored", docs "LLM providers"). The `GRAPHIFY_API_KEY` for HTTP serving is likewise read from the environment.
- Collision points, all avoidable:
  - A rendered `[mcp_servers.graphify.env]` table holding a literal `GRAPHIFY_API_KEY` or `ANTHROPIC_API_KEY` value would trip `generic-api-key`; an environment reference (`"${GRAPHIFY_API_KEY}"`) is what the policy asks for and what the T129 follow-up (`.orchestration/dotfiles-T129-.../task.md:74`, not on main) formalises as "an API-key value only when its whole value is one environment reference".
  - A committed `graphify-out/graph.json` or `memory/*.md` could carry a secret-shaped label lifted from source; graphify's `redact_secrets()` reduces this and the sensitive-file filter skips `.env`, keys and credential files (docs "Ignore files"), but `generic-token` / `generic-secret` assignment rules would still fire on a `token = "..."` string that survived into a node label. **Inferred**: if a graph is ever committed here, add `graphify-out/` to the scan's expectations or run the validator before committing.
  - The skill's `.graphify_python` sidecar and `graphify-out/.graphify_root` hold absolute host paths; `validate_no_obvious_secrets()` only flags home paths under `.orchestration/` (`:2524-2530`), so these would pass the scan but would not be portable.

### 5.3 Net reading

- The MCP server is the least compatible surface: per-project absolute path, enabled-or-useless, Claude Code via an unmanaged file, hosted variant via OAuth to a SaaS. Nothing in it needs a token literal.
- The CLI plus a project-scoped install (`graphify install --project --platform <x>`, which writes `.claude/skills/graphify/`, `.claude/settings.json` hooks with a bare command, `.codex/skills/graphify/`, `.codex/hooks.json`, `AGENTS.md` and `CLAUDE.md` in the project tree) is the surface that touches none of the files this repository generates, and the always-on hook is the piece that most changes an agent's behaviour (strict mode refuses raw reads until a query ran).
- Trust: the installer edits settings files in place with a single rolling `.graphify-bak` and refuses only on a non-dict `hooks` value (`install.py:1129-1143`, `:2241-2262`); the hook commands embed an absolute interpreter path at user scope; the skill runs `uv tool install --upgrade graphifyy` on its own when the import fails (`skill-codex.md`, Step 1). Those are the behaviours the repository's pin-and-verify posture (`assets:` entries with `verify`, `pin`, `sha256`; `agent-config.yaml:1074-1084`) exists to control.

## 6. Proposals

- G-1 (scope): treat graphify as a code-navigation layer for large or unfamiliar corpora, not as agent memory. If an evaluation of "memory" is wanted, the open-source `save-result` / `reflect` loop is the only local surface and it is operator-driven.
- G-2 (install shape): if trialled, use `uv tool install graphifyy` pinned to a release (currently 0.9.100) through an `assets:` entry with `installer`, `pin` and a checksum, and `graphify install --project --platform claude` / `--platform codex` inside one project, never the user-scope install. Measure before and after with the doctor (`scripts/check-agent-runtime.py`) that `~/.claude/skills`, `~/.agents/skills`, `~/.claude/settings.json` and `~/.codex/config.toml` are unchanged.
- G-3 (MCP): do not declare a `graphify` server in `agent-config.yaml`. The policy already names the two admissible routes: Codex-only and disabled in the manifest (useless for a per-project graph), or an operator's `claude mcp add --scope user` outside the repository. If a Codex stdio entry is wanted on one host, `codex mcp add graphify -- graphify-mcp <abs>/graphify-out/graph.json` lands in the preserved non-baseline tables of `~/.codex/config.toml`, as the measured `node_repl` table shows; record it as a local, undoctored addition. Refuse the hosted OAuth route unless a credentials, scope and network review is written first (README rule 3).
- G-4 (skills audience): a graphify SKILL.md under any shared root must be added to `skills.audience` or the doctor warns; the upstream Codex default `~/.codex/skills` is outside every rendered and checked root, so prefer `--project` installs or an explicit audience entry with `codex` and `claude` only (omp seats cannot run its subagent steps and should not list it).
- G-5 (keys): run code-only (`graphify extract . --code-only` or `GRAPHIFY_BACKEND=none`) so no provider key is read; if the semantic pass is ever used, pass keys through the login environment, never through a rendered `env` table, and keep `graphify-out/` out of the repository or run `validate-agent-assets.py` on it before committing.
- G-6 (docs drift to watch): the README's query-log sentence (on by default) disagrees with `querylog.py` and the docs table (off by default); the skill's "reads no provider key but Gemini" disagrees with the headless auto-detection table. Both should be re-read at the release that is pinned.
