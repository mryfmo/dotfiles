    Engagement handout: the prepared host, the client repository and the program store¶

    An engagement receives three artefacts. The prepared host is a machine where ./setup.sh, make update and the seat logins have run and make doctor exits 0. The client repository is the checkout that regime-init <program> has initialised, with its checkout guard and its ## Audit section in AGENTS.md. The program store is the directory .orchestration/orchestrate/<program>/ with its five files (preferences.md, units.tsv, ledger.tsv, decisions.tsv, gates.md), placed by the same run. Every section below names the command that produces the artefact and the read-only check that proves it, in the shape of the G16 operator handout: a dated page pinned to a commit, hosts named by kind, every row a command and its check. Every table carries two further columns: source, the document or file:line that defines the command's behaviour, and dry-run, the receipt of a scratch run, the coordinator's measured output, or operator-only: <reason> where the command needs the operator's own host, terminal or browser. The facts are measured on origin/main c92078d0 on 2026-11-04; the file and line citations are to that commit, and the one scratch run used that commit's regime-init. The readers are the operator of the engagement and the coordinator; a seat runs no command on this page. The page names the two seat roles, orchestrator and worker, since every audit is one fresh ~/.local/bin/common/pr-audit.sh <n> --records <store> run from a terminal outside every seat and no seat login serves it.

    Prepared host¶

    A prepared host is a machine, the operator's macOS laptop or the Ubuntu seat host, that the repository's installers have set up, that is current with origin/main, and that holds a login for each seat role; the login is per host and the operator's own step (see Seat logins on a remote host).

    The doctor gate before any seat¶

    A seat starts on a host only after that host has passed the doctor gate, and the two launch commands of the table below are typed from a terminal outside every seat. A host passes the gate when make doctor on that same host exits 0 with the Seat logins section listing orchestrator and worker as found, and with its Agent tools block printing srt as found at the pin: an absent srt is only an optional warning to the doctor (scripts/check-tools.sh:253-255, warn_optional "srt not installed; run make update" and the check returns 0), so an exit 0 alone does not prove it, while the launcher refuses to start a seat without it (scripts/orchestrator/hcom-seat:1597). The doctor's Agent tools section reports omp, hcom and srt (scripts/check-tools.sh:446-449); for srt it reads the exact version pinned in the applied mise config, or in the checkout's home/dot_mise/config.toml when the host has not applied the pin yet (:257-262, the pin is 0.0.81, home/dot_mise/config.toml:26), and a version that differs from the pin is a required failure whose remedy is make update (:276-279). The launcher reads a different fact: hcom-seat encodes the srt release line 0.0, the major and minor only (SRT_LINE, scripts/orchestrator/hcom-seat:218-223), refuses an installed srt of another line (:1600-1609), and declines to start a seat when srt is missing (:1597) or when the role's login is absent, since it runs seat-login-preflight <role> first (:1877-1878, README.md:118-123). So the doctor and the launcher read two facts over the same install: the doctor the exact pin, the launcher the line. A host that passes the gate as stated passes both; an srt on the 0.0 line but off the exact pin fails the doctor and passes the launcher's check, and an absent srt passes the doctor's exit code and fails the launcher, which is why the gate names the srt row and not the exit code alone. A login is per host and the operator's own step; nothing copies a token between hosts (Seat logins on a remote host, first paragraph).

    The dsh-superagent Router (hcom-seat router -- --no-open, the router role of scripts/orchestrator/hcom-seat) acts on GitHub as the agent account of the M-25 handout (handouts/m25-agent-github-account.md in the program store: a direct collaborator with the Write role, never the operator's own login), through the gh wrapper router-gh whose GH_CONFIG_DIR is <DSH_HOME>/router-credentials/gh.
