# Agent configuration architecture

This directory is the canonical source for AI-agent assets shared by Codex, Claude Code and omp.

## Single source of truth

- `agent-config.yaml` is the only hand-edited source for shared agent settings.
- `skills/` is the canonical cross-agent skill tree and is exposed as `~/.agents/skills`.
- Claude Code receives generated symlinks under `~/.claude/skills` so it sees the same skill set.
- Codex receives the same skill tree through the shared `~/.agents/skills` location and the local workflow plugin adapter.
- Agent-native files are generated by `../../scripts/generate-agent-configs.py`.

`expected_outputs()` in the generator is the one expected output set, and each write run records it in
`scripts/generated-agent-outputs.json`: `outputs` lists every generated source file with its deployed target, and
`scopes` lists the generated directories (with the file glob each one owns). Read that file for the current list; this
page does not copy it. A file in a generated directory that the set does not hold is an orphan, which `--check` (and
so `validate-agent-assets.py`) reports and a write run deletes. `make doctor` checks every deployed target in the list
and reports a file in a generated directory under `$HOME` that no output deploys; the operator removes it.

## Parity policy

1. Every MCP server in `agent-config.yaml` targets Codex only, and `validate-agent-assets.py` rejects `agents.claude: true`. Claude Code reads user-scope MCP servers from `~/.claude.json`, which this repository does not manage; add a Claude server with `claude mcp add --scope user`.
2. The generated Codex config must contain exactly the server names declared in `agent-config.yaml`.
3. MCP servers remain disabled by default. Enable them locally only after confirming credentials, filesystem scope, and network behavior.
4. GitHub MCP must use the maintained official GitHub server (`ghcr.io/github/github-mcp-server`), not deprecated `@modelcontextprotocol/server-github`.
5. Public dotfiles must not contain token literals. Credential-bearing servers inherit environment variables or refer to private configuration only.
6. Claude plugins are not enabled by `settings.json` unless this repository also installs the marketplace/plugin. Shared workflows should live in skills first.
7. Do not hand-edit generated files unless you immediately move the change back into `agent-config.yaml` and regenerate.
8. For implementation tasks shared between Codex and Claude Code, use separate worktrees or make one agent a reviewer; do not let both write to the same worktree. This is an operational guideline and is intentionally not enforced by `validate-agent-assets.py`.
9. The Claude Code Bash sandbox (`claude.sandbox`) mirrors the Codex `workspace-write` sandbox: its `filesystem.allowWrite` is rendered from `codex.sandbox_workspace_write.writable_roots`, and `validate-agent-assets.py` requires it to be enabled, to set `failIfUnavailable` to `true` and `allowUnsandboxedCommands` to `false` (strict sandbox mode: no unsandboxed retry), to keep `excludedCommands` exactly `["git push *", "gh *"]` with an identical `Bash(...)` ask rule for each entry and no rule naming `dangerouslyDisableSandbox`, to allow only hostnames in `network.allowedDomains`, to list no Unix socket, to keep every write root (Claude `allowWrite`, Codex `writable_roots`, Claude `additionalDirectories`) byte-identical to an entry of the exact allowlist `SANDBOX_WRITE_ROOTS` (no normalisation; adding a root is a reviewed change to that list), to deny the agents' file-based login stores and the age key (on macOS the Keychain-held Claude login and gh token stay reachable through securityd, which the Claude Code 2.1.310 sandbox always allows), to list each credential path and variable once, to deny the gh hosts file, to keep every credential entry a plain deny (no mask, no `network.tlsTerminate`: a mask lets the proxy write the real token into a request body that GitHub can echo back), and to withhold `CLAUDE_CODE_OAUTH_TOKEN` (U68). The coordinator's `claude.permissions.allow` levers, the `env` and the two writable directories they need are described in `scripts/orchestrator/README.md`, "Pre-authorized levers", and the validator refuses any allow rule outside that set. The two layers that guard secret files (the Read/Edit deny rules and `sandbox.credentials` with `sandbox.filesystem.denyRead`) are described in the top-level `README.md`, "Claude Code sandbox".
10. The managed Claude settings template carries no `autoUpdates`, `autoUpdatesChannel` or `alwaysThinkingEnabled` key, and the settings merge drops those keys from an installed `~/.claude/settings.json` only while they hold the former managed values (`RETIRED_MANAGED_DEFAULTS` in `home/dot_claude/modify_private_settings.json`); a different value is an operator override and stays. mise is the only Claude Code version channel, its updater is blocked by `DISABLE_UPDATES` and `DISABLE_AUTOUPDATER` in the login environment (top-level `README.md`, "Claude Code version"), and `claude update` is not a supported command here.

## Codex runtime state

Codex writes stable runtime state into `~/.codex/config.toml`, so the file is managed through `home/dot_codex/modify_private_config.toml` instead of a full-file template. The generated managed baseline lives at `home/.chezmoitemplates/codex-config-managed.toml`.

The merge script keeps managed settings from `agent-config.yaml` authoritative while preserving these Codex-owned table prefixes from the live target when they exist:

- `hooks.state`
- `marketplaces`
- `tui.model_availability_nux`
- `projects`

Current-target tables outside the generated baseline are also preserved so local Codex additions are not lost during `chezmoi apply`.

Project trust and hook trust keyed by an absolute path that no longer exists on the host are dropped on each apply, by the base and the profile (`modify_private_<profile>.config.toml`) merges alike: a `[projects."<path>"]` table, and a `[hooks.state."<file>:<event>:<group>:<handler>"]` entry whose `<file>` is a `hooks.json` or `config.toml`. Only a not-found result drops an entry; a path that cannot be checked (for example, permission denied) keeps its entry and prints a warning. Plugin hook keys (`<plugin>@<marketplace>:...`) and relative keys are never pruned, and trust for a path that still exists, including trust Codex wrote when you accepted its prompt, is kept.

## omp runtime state

omp writes its own keys into `~/.omp/agent/config.yml`, so the file is managed through `home/dot_omp/private_agent/modify_private_config.yml`; the `private_` attributes keep `~/.omp/agent` at 0700 and the file at 0600, because the directory also holds omp's auth databases. The script merges the keys the generated `home/.chezmoitemplates/omp-config-managed.yml` carries (a leading `~` expanded; the script's `@description` says how each key merges) and keeps every other key and role. `extensions` loads the pi-claude-bridge on a plain `omp` launch, because the default route `claude-bridge/...` exists only while that extension is loaded; a hand-added entry in the live file is replaced on the next apply. Its merge runs under `uv run --no-project --with pyyaml`, so the system `python3` needs no PyYAML; without `uv` it leaves the file unchanged and warns on stderr.

## Commands

Generate agent-native files:

```bash
uv run --with pyyaml scripts/generate-agent-configs.py
```

Verify generated files are up to date:

```bash
uv run --with pyyaml scripts/generate-agent-configs.py --check
```

Run the full agent asset validator:

```bash
uv run --with pyyaml scripts/validate-agent-assets.py
```

After applying chezmoi, prove the active HOME runtime files match this source tree:

```bash
scripts/check-agent-runtime.py
```

The validator checks generated-file freshness and orphans (through `generate-agent-configs.py --check`), the Agent Skills frontmatter limits, MCP parity, disabled-by-default safety, deprecated MCP packages, that the Codex and Claude configs parse and name their schema URL (it does not validate either file against that schema), and obvious committed secrets. The runtime doctor checks every generated target in `$HOME` (including `~/.omp/agent/config.yml` and `~/.agents/agent-config.yaml`), the skill trees and the hooks without modifying them; a host where `make update` never wrote `~/.agents/.installed-manifest.json` gets a WARN.
