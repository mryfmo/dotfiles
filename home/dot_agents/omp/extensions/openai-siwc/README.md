# openai-siwc

omp provider extension for OpenAI's official Sign in with ChatGPT route. It registers the provider `openai-siwc` on omp's built-in `openai-responses` transport, logs in through dynamic client registration with a `127.0.0.1` loopback callback, and rewrites each request into the shape the SIWC preview accepts. The design, strip list, error mapping and threat table are in `docs/openai-siwc.md` at the repository root.

Status: loads in omp 18.11.3 and registers `openai-siwc/gpt-6.1-sol` and `openai-siwc/gpt-6-astra`; no real login or completion has run through it yet (gate G2 below). `gpt-6-astra` on this route is an assumption; only `gpt-6.1-sol` was measured (pilot facts #S0).

## Operator steps for G2

Run these in the operator's own terminal, in the `audit` profile (the omp role on the openai-siwc route; `omp.roles` in `home/dot_agents/agent-config.yaml`). The login opens the system browser, so an agent never runs it. `PI_OPENAI_STATEFUL` must be unset; the extension refuses to load when it is truthy.

## On a remote seat host

A seat on the Ubuntu host reached through `herdr --remote` signs in with the laptop's browser (`docs/remote-host-logins.md` at the repository root). The SIWC callback stays a `127.0.0.1` loopback on the seat host. `OPENAI_SIWC_CALLBACK_PORT` pins it, so the laptop's `LocalForward 1455 127.0.0.1:1455` (the `seat-host` SSH entry) carries the browser's redirect to it. With the variable set, a taken port fails the login before any URL is shown; unset, the listener keeps 1455-else-random.

## Tests

```sh
bun test
```

`tests/requests.test.ts` imports omp's own Responses transport and error classifier from the installed omp package to prove the rewritten request and the error mapping end to end. It reads `OMP_PACKAGE_DIR`, defaulting to `~/.local/lib/node_modules/@oh-my-pi/pi-coding-agent`.

The loopback bind test is skipped, with a printed reason, only when binding `127.0.0.1` fails with `EPERM`, `EACCES`, or Bun's `EADDRINUSE` for port 0 (how Bun 1.4 reports a sandbox refusal). Any other bind error fails the run.

`tsconfig.json` maps `@oh-my-pi/*` to the installed omp under `~/.local/lib/node_modules`, relative to the applied copy at `~/.agents/omp/extensions/openai-siwc`. shortcut: no type check runs, because `tsc` is not installed and the package adds no dependency; run `bunx tsc --noEmit` from the applied copy once a TypeScript compiler and Bun's types are available.
