# daily-<YYYY-MM-DD> the daily security-audit sweep of main's head on the srt worker seat

GOAL
Run the `security-audit` skill in full audit mode over this repository at main's head named in the TASK line (`<head>`, the standing control of the Audit sweep rule C of 2026-11-18: a head whose changed paths touch no lever, policy, credential handling or deployed executable merges on its Codex audit, CI and the day's sweep of main, and `pr-merge.sh` reads the day's row from the store's `daily-sweeps.tsv` before it skips such a head's own sweep row; a day without its sweep keeps the per-head rule for every head). One run per UTC day, dispatched by the coordinator with the task id `daily-<YYYY-MM-DD>`; its product is the validated findings set, the RESULT line, and the row the coordinator writes from it. The previous run of this seat is `<prev>`: carry its records and re-verify each at this head.

SCOPE
No branch, no commit, no pull request, no file of the repository changes. Writes only under `~/.local/state/omp-seats/<repository>/.state/<seat>/security-audit/<run>/` (the run directory named in the TASK line, created by step 1) and the skill's per-agent `scratch/` directories below it. The target is the seat's own checkout `~/.local/state/omp-seats/<repository>/<seat>`, positioned by the coordinator at `<head>` before the TASK, read-only for the run: `git -C ~/.local/state/omp-seats/<repository>/<seat> status --porcelain` exits 0 and prints nothing before and after (its exit status read: a status that fails is no clean checkout).

CONTEXT
The skill is installed at `~/.agents/skills/security-audit/` at the manifest's pinned commit (`assets.security-audit-skill`), audience `omp-worker` only. The seat's containment lets it write only its own checkout, its state root `~/.local/state/omp-seats/<repository>/.state/<seat>` and the bus store, and gives it no network. The previous run of this seat is the one the TASK line names as `<prev>`; carry its records and re-verify each at this head. The whole tree is in scope: this is the full sweep of main, not a scoped run against one change, so every top-level directory gets a verdict in the coverage ledger.

CHANGE

1. `mkdir -p ~/.local/state/omp-seats/<repository>/.state/<seat>/security-audit/<run>`; confirm `git -C ~/.local/state/omp-seats/<repository>/<seat> log -1 --format=%H` exits 0 and prints `<head>`, and `git -C ~/.local/state/omp-seats/<repository>/<seat> status --porcelain` exits 0 and prints nothing; write both commands with their exit status and output into `<output-dir>/preflight.txt`. A head read that exits non-zero, or prints anything but `<head>`, is a refusal to start, and so is a status read that exits non-zero, or prints anything: nothing of steps 2 to 5 runs, and the RESULT is `RESULT v1 task_id=daily-<YYYY-MM-DD> status=partial pr=none head=<head> note=preflight refused: git log exited <n>` (or `note=preflight refused: git log printed <sha>, not <head>`) for the head read and `RESULT v1 task_id=daily-<YYYY-MM-DD> status=partial pr=none head=<head> note=preflight refused: git status exited <n>` for the status read (a `status=partial` RESULT gets no daily row). A failed read is never read as a clean checkout. A failed head read is never read as the checkout at `<head>`.
2. Read `~/.agents/skills/security-audit/SKILL.md` whole, then the phase files as each phase needs them. Setup values: skill directory `~/.agents/skills/security-audit`, target `~/.local/state/omp-seats/<repository>/<seat>`, repo name `<repository>`, output directory the one of step 1, source ref `<head>`, checkout clean.
3. Run the six phases in order and write the seven shared files into the output directory. Carry the previous run's records and re-verify each at this head with its lines re-mapped; hunt over the whole tree. Every finding carries the fields `report-schema.json` requires. Coverage over volume: the coverage ledger names every top-level directory of the target with a verdict.
4. Validate: `node ~/.agents/skills/security-audit/validate-findings.cjs <output-dir>/findings.json` and `node ~/.agents/skills/security-audit/validate-coverage-ledger.cjs <output-dir>/coverage-ledger.json`, both exit 0; paste both result lines into `<output-dir>/validation.txt`. A validation failure is fixed in the JSON, never by dropping a finding.
5. Write `<output-dir>/summary.txt`: first line `security-audit sweep <head>: <count> findings, advisory`, then one line per finding `<severity><TAB><id><TAB><file:line><TAB><title>`, the counts by severity, the files written, and the wall time.

ACCEPTANCE

1. `ls <output-dir>` lists `run-metadata.json architecture.md coverage-ledger.json findings.json REPORT.md FINDINGS-DETAIL.md NEEDS-VALIDATION.md preflight.txt validation.txt summary.txt`.
2. `node ~/.agents/skills/security-audit/validate-findings.cjs <output-dir>/findings.json` exit 0.
3. `node ~/.agents/skills/security-audit/validate-coverage-ledger.cjs <output-dir>/coverage-ledger.json` exit 0.
4. `git -C ~/.local/state/omp-seats/<repository>/<seat> rev-parse HEAD` exits 0 and prints exactly `<head>` (its exit status read and its one line compared whole with the TASK's `<head>`; no grep count: a printed count of a string in generated metadata attests nothing of the checkout, and a checkout change after step 1 shows here as another sha or a failed read, which is no sweep of `<head>`).
5. `git -C ~/.local/state/omp-seats/<repository>/<seat> status --porcelain` exits 0 and prints nothing (its exit status read: a failed read is a refusal to start, never a clean checkout).

VERIFY
The commands of ACCEPTANCE in the seat, their result lines pasted into `<output-dir>/validation.txt`.

CLOSURE
remove

TRUST
TRUST: the unit trusts the `security-audit` skill at the manifest's pinned commit and the seat's srt containment as the bounds of the run, and the previous run's records as the set to carry; it changes no file of the repository, removes nothing and opens no pull request; its product is the validated findings set and the RESULT line, from which the coordinator writes the day's row.

TIMEBOX
300 minutes. On expiry, validate what exists, write `summary.txt` with the word `partial` after `advisory` in its first line, and send the RESULT with `status=partial`, not `ready_for_review`: `RESULT v1 task_id=daily-<YYYY-MM-DD> status=partial pr=none head=<head> note=<count> findings validated in <run>, partial`. A partial sweep is no daily sweep of main's head: the coordinator writes no daily row for it, and the per-head rule stands for every head until a full run finishes.

FORBIDDEN
No edit, commit, branch, push or pull request; no write outside the output directory; no network; no build, test or execution of the target's code; no installation; no `gh` call; no read of a credential store, of `~/.ssh` or of the seats' token file (`<seats-root>/.state/claude-token`, which the sandbox denies); no secret in any file you write (the value of `CLAUDE_CODE_OAUTH_TOKEN` in this seat's environment is a secret: never print, echo, grep or copy it); no absolute home directory in the findings (write `~/...`); no word of the store's `redact-words.txt`.

REPORT
One line on the team thread when the output directory holds the ten files and both validators exit 0: `RESULT v1 task_id=daily-<YYYY-MM-DD> status=ready_for_review pr=none head=<head> note=<count> findings validated in <run>`. Nothing else goes on the bus; the files are the report. The coordinator writes the day's row only for a RESULT with `status=ready_for_review` whose `validation.txt` holds both validators' PASS lines, in this order: the output directory held to the seat's scratch root first, then the validation, then the copy, then the row. It first resolves the worker's output directory physically, `cd <output-dir> && pwd -P` (its exit status read: a directory that cannot be entered is a refusal of the run), and requires the physical path to lie under the seat's state directory `~/.local/state/omp-seats/<repository>/.state/`, the directory the coordinator owns and the worker cannot write (the seat's containment grants the worker its own `.state/<seat>` and nothing above it), itself resolved with `cd ~/.local/state/omp-seats/<repository>/.state && pwd -P` (its exit status read; the physical output directory must be exactly that directory followed by `/<seat>/security-audit/<run>`, else the run is refused and nothing is validated or copied), and refuses when any component of `<output-dir>` below that directory is a symbolic link: `test -L` on each component in turn, `~/.local/state/omp-seats/<repository>/.state/<seat>` first, then `~/.local/state/omp-seats/<repository>/.state/<seat>/security-audit`, then `~/.local/state/omp-seats/<repository>/.state/<seat>/security-audit/<run>` and each deeper component after it, every test false. The `security-audit/` root is included because a worker can plant a symlink at the root of its writable tree: the worker writes everything under `.state/<seat>`, so a check that resolved `security-audit/` itself as its root and tested the components below it alone started inside a path the worker could have replaced with a link, and the resolved root then lay wherever the link pointed (the output directory is worker-controlled, and a symlinked ancestor would let the validators and the copy read coordinator-readable files outside the seat; the physical path is what the validators and the copy below read). It runs both validators itself over the files at that physical path, `node ~/.agents/skills/security-audit/validate-findings.cjs <output-dir>/findings.json && node ~/.agents/skills/security-audit/validate-coverage-ledger.cjs <output-dir>/coverage-ledger.json` (`<output-dir>` the physical path from here on), and copies nothing unless both exit 0 (validation before the copy, so a refused run leaves nothing in the store); then it copies `findings.json` and `coverage-ledger.json` into a run-keyed directory the store does not yet hold without following symbolic links, `test ! -e <store>/sweeps/daily-<YYYY-MM-DD>-run-<n> && mkdir <store>/sweeps/daily-<YYYY-MM-DD>-run-<n> && cp -R -P <output-dir>/findings.json <store>/sweeps/daily-<YYYY-MM-DD>-run-<n>/findings.json && cp -R -P <output-dir>/coverage-ledger.json <store>/sweeps/daily-<YYYY-MM-DD>-run-<n>/coverage-ledger.json` (`cp -R -P`, the form macOS and GNU cp share, copies a symbolic link as a link and never the file it points at: the output directory is worker-controlled, so a plain `cp` could follow a planted link and deposit coordinator-readable bytes from outside the directory into the store as a regular file; the `test ! -e` guard refuses an existing destination, so a same-day retry lands beside the earlier row's evidence and never over it; the writer then refuses a copy that is a link, since it opens the findings file and the coverage ledger with no link followed and requires a regular file of this user), and runs `~/.local/bin/common/ledger-row.py <store> daily --head <head> --seat <seat> --run <n> --task daily-<YYYY-MM-DD> --findings sweeps/daily-<YYYY-MM-DD>-run-<n>/findings.json --swept-at <ts>` with `<ts>` the RESULT message's bus timestamp converted to the writer's form `YYYY-MM-DDTHH:MM:SSZ` (`bus-history.sh` prints hcom's `+00:00` form, `2026-11-19T01:05:00.123456+00:00`, which the writer refuses; one line converts it: `python3 -I -c 'import datetime, sys; print(datetime.datetime.fromisoformat(sys.argv[1]).astimezone(datetime.timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ"))' '<bus ts>'`, the `fromisoformat` and `strftime` forms the kit's readers use), which becomes the row's ts, and whose UTC day, or the day before it, the task id `daily-<YYYY-MM-DD>` must name (the id is fixed at dispatch and a sweep that crosses midnight keeps it; the writer refuses a unit id or any other day): the writer copies the two files into a private directory of its own and hashes the copies, reads the findings copy for the count (a JSON list of objects, else refused), then runs the installed skill's two validators itself over those copies (`validate-findings.cjs` and `validate-coverage-ledger.cjs` with the `report-schema.json` the first loads, each read from `~/.agents/skills/security-audit/` alone through real directories, copied into a private directory of the writer and the copy hashed against its `assets.security-audit-skill.validators_sha256` pin in `~/.agents/agent-config.yaml`, the one manifest the writer reads for a daily row, before `node` runs the copies, each with its exit status read; a file whose digest differs from its pin, a missing pin, a validator exiting non-zero, a missing file or no `node` refuses the row, so the row's `validate-findings.cjs PASS; validate-coverage-ledger.cjs PASS; validators sha256 <8 hex> <8 hex> <8 hex>; artifacts sha256 <8 hex> <8 hex>` fields are the writer's own result over the bytes it copied, not this RESULT's word), refuses a `--swept-at` ahead of its clock or more than 24 hours behind it, and refuses a findings path or a seat and run an earlier row already records. That row of `daily-sweeps.tsv` is the one `pr-merge.sh` reads through `ledger.py daily 86400`. A `status=partial` RESULT (the TIMEBOX path) gets no daily row and no copy: a partial sweep does not stand for the day, and the per-head rule stands until the day's full sweep finishes.
