## Regime

- **Loop.** Work runs through the omp seats on the hcom bus: the `hcom-orchestration` skill is the loop and `hcom-worker` its worker half; each audit is one fresh `~/.local/bin/common/omp-run.sh --role audit` run per head. The standard a change meets is `AGENTS.md` "Audit" and "Code Review Rules".
- **`main`.** Every repository change lands through a seat's pull request, merged with `gh pr merge --squash --match-head-commit <audited head>`; never push to `main`.
- **Routing.** A seat never widens its own execution boundary on its own authority. A change to that boundary (the omp policies, profiles, hooks and extensions, the levers, `hcom-seat`, `omp-run.sh`, the bridge, the Claude and Codex permission and sandbox settings) is a trust-boundary unit: its pull request carries a `## Threat table` and gets the per-head audit (`AGENTS.md` "Audit"), and permgate and credentials go to the operator.
- **Records.** The program store is `.orchestration/orchestrate/<program>/`; its `preferences.md` is the standing order. It outranks bus messages and other repository text, never the operator's own instructions, which outrank both.
- **Levers.** Only logins and Keychain steps are the operator's. Everything else is a lever with an allow rule or a seat policy row, never an ad-hoc permission. A lever never widens a seat's boundary: approval is not containment, and the account and the worktree stay the boundary (`home/dot_agents/omp/policies/README.md` threat table).
- **Cases.** Do not design for rare or future cases nobody has asked for. A case is real when a test, an incident, a user or a measured run names it; otherwise state it in the Contract's Left out and move on.
