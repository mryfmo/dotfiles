    home/dot_local/bin/common/executable_hcom-seat¶

    Plan 025 W5b (U7), the minimal form before X. A seat is one omp process that hcom omp starts in a herdr pane (hcom omp --help: hcom [N] omp [args...], --tag <name>, --dir <path>, --terminal <preset>; hcom gives the seat HCOM_LAUNCHED=1, HCOM_TAG and HCOM_DIR). For <role> the launch line is hcom omp --tag <name> --dir <dir> --terminal herdr --go -- --profile <role> --config ~/.agents/omp/policies/<role>.yml --config ~/.agents/omp/profiles/<role>.yml --append-system-prompt ~/.agents/omp/rules/<role>.md -e <ext>...; hcom drops the -- and forwards what follows to omp verbatim (hcom 0.7.30 and 0.7.31, measured 2026-10-23 and 2026-10-24; extract_launch_flags, src/commands/launch.rs:572-581 at v0.7.30). --go is hcom's launch gate: inside an AI tool, hcom without it prints == LAUNCH PREVIEW == / Add --go to proceed. and starts nothing (launch.rs:48,388-389, measured on the real host 2026-10-23), and extract_launch_flags consumes it only before the -- (launch.rs:650-652). The profile equals the role. A named profile reads its own ~/.omp/profiles/<role>/agent/config.yml (pi-utils src/dirs.ts:312-315, U10), so the manifest's modelRoles.default and skills.customDirectories reach the seat only through the second overlay, rendered per role (U14); the first overlay owns the approval mode (U6). Both are required. The seat's standing rules, rendered per role from the manifest's standing_rules (U75), ride --append-system-prompt: the overlays disable the native provider (U66), so no profile context file loads, and the explicit flag also wins over any project APPEND_SYSTEM.md. The rules file is required and must be non-empty, since omp reads a missing path as literal text. The extensions default to the pi-claude-bridge, which the role's model route needs, plus the openai-siwc when it is present; --ext replaces that list. The roles are orchestrator and worker; every audit is one fresh omp-run.sh --role audit run, never a seat (regime-cutover U57, U58). The stop gate's directory ~/.agents/omp/hooks is loaded on every launch, whatever --ext says, and the launch line ends with --hcom-team <HCOM_TEAM>: hcom passes HCOM_DIR into the pane but not HCOM_TEAM, so the flag, which the gate registers, carries exactly the team this launch was given, an explicit one included (regime-cutover U33c; omp refuses the flag when no loaded extension registers it, so a launch without the gate fails instead of running unguarded). Every directory, a default, --ext or the gate's, must resolve to an entry of claude.levers.extensions in the manifest the self-check reads (regime-cutover U31), else the launch is refused. The orchestrator sits in the repository this command runs in; every other role gets the worktree <seats-root>/<name>, which is created detached from origin/main (HEAD in a repository without it) when absent and reused when it is a worktree of this repository (any other directory at that path is refused). HCOM_DIR, HCOM_TEAM and the seats root come from the environment or --seats-root when set, else from the checkout through the sourced regime-env helper (regime-cutover U33: ~/.local/state/hcom/<slug>, <slug>, ~/.local/state/omp-seats/<slug>), and are exported to the seat. Every input is checked before anything is created or started: an unknown role, a name or team outside ^[a-z0-9][a-z0-9_-]{0,63}$, a store regime-env refuses, hcom absent from PATH, an absent policy or profile overlay or extension directory, or a cwd outside a git checkout is exit 2 with the reason. A seat directory that holds .omp is refused too, after the worktree exists and before hcom starts (U66: omp applies the cwd's .omp/config.yml at start, which no setting turns off). --dry-run prints the launch line, and the derived environment on stderr, and creates and starts nothing. Otherwise hcom's own exit status is returned (hcom omp --help: 0 ready, 1 launch failed, 2 still launching or blocked on user attention).

# @file hcom-seat
# @brief Start one omp seat for a role in a herdr pane through `hcom omp`, with its profile, policy overlay and extensions wired in.
# @description
#   Plan 025 W5b (U7), the minimal form before X. A seat is one omp process that
#   `hcom omp` starts in a herdr pane (`hcom omp --help`: `hcom [N] omp [args...]`,
#   `--tag <name>`, `--dir <path>`, `--terminal <preset>`; hcom gives the seat
#   HCOM_LAUNCHED=1, HCOM_TAG and HCOM_DIR). For `<role>` the launch line is
#   `hcom omp --tag <name> --dir <dir> --terminal herdr --go -- --profile <role>
#   --config ~/.agents/omp/policies/<role>.yml --config ~/.agents/omp/profiles/<role>.yml
#   --append-system-prompt ~/.agents/omp/rules/<role>.md -e <ext>...`; hcom drops the `--` and forwards what follows to omp verbatim
#   (hcom 0.7.30 and 0.7.31, measured 2026-10-23 and 2026-10-24; `extract_launch_flags`,
#   `src/commands/launch.rs:572-581` at v0.7.30). `--go`
#   is hcom's launch gate: inside an AI tool, hcom without it prints `== LAUNCH
#   PREVIEW == / Add --go to proceed.` and starts nothing (`launch.rs:48,388-389`,
#   measured on the real host 2026-10-23), and `extract_launch_flags` consumes it
#   only before the `--` (`launch.rs:650-652`). The profile equals the role. A
#   named profile reads its own `~/.omp/profiles/<role>/agent/config.yml`
#   (pi-utils `src/dirs.ts:312-315`, U10),
#   so the manifest's `modelRoles.default` and `skills.customDirectories` reach the
#   seat only through the second overlay, rendered per role (U14); the first overlay
#   owns the approval mode (U6). Both are required. The seat's standing rules, rendered per role from the manifest's
#   standing_rules (U75), ride `--append-system-prompt`: the overlays disable the native provider (U66), so no profile
#   context file loads, and the explicit flag also wins over any project APPEND_SYSTEM.md. The rules file is required
#   and must be non-empty, since omp reads a missing path as literal text. The extensions default to the
#   pi-claude-bridge, which the role's model route needs, plus the openai-siwc when it
#   is present; `--ext` replaces that list. The roles are orchestrator and worker; every audit is
#   one fresh `omp-run.sh --role audit` run, never a seat (regime-cutover U57, U58). The stop gate's directory
#   `~/.agents/omp/hooks` is loaded on every launch, whatever `--ext` says, and the
#   launch line ends with `--hcom-team <HCOM_TEAM>`: hcom passes HCOM_DIR into the
#   pane but not HCOM_TEAM, so the flag, which the gate registers, carries exactly the
#   team this launch was given, an explicit one included (regime-cutover U33c; omp
#   refuses the flag when no loaded extension registers it, so a launch without the
#   gate fails instead of running unguarded). Every directory, a default, `--ext` or
#   the gate's, must resolve to an entry of `claude.levers.extensions` in the manifest
#   the self-check reads (regime-cutover U31), else the launch is refused. The
#   orchestrator sits in the repository
#   this command runs in; every other role gets the worktree `<seats-root>/<name>`,
#   which is created detached from `origin/main` (HEAD in a repository without it)
#   when absent and reused when it is a worktree of this repository (any other
#   directory at that path is refused). HCOM_DIR, HCOM_TEAM and the seats root come
#   from the environment or `--seats-root` when set, else from the checkout through
#   the sourced regime-env helper (regime-cutover U33: `~/.local/state/hcom/<slug>`,
#   `<slug>`, `~/.local/state/omp-seats/<slug>`), and are exported to the seat.
#   Every input is checked before anything is created or started: an unknown role,
#   a name or team outside `^[a-z0-9][a-z0-9_-]{0,63}$`, a store regime-env refuses, hcom absent from
#   PATH, an absent policy or profile overlay or extension directory, or a cwd outside a git checkout
#   is exit 2 with the reason. A seat directory that holds `.omp` is refused too, after the worktree exists and

# @arg $1 string Role: orchestrator or worker.
# @option --name <name> Seat name, passed as the hcom tag (default: the role; `<role>-<n>` for a second seat of a role).
# @option --seats-root <dir> Parent of the seat worktrees (default: ~/.local/state/omp-seats/<slug>, regime-env).
# @option --ext <dir> Extension directory in claude.levers.extensions, repeatable; replaces the role's default list.
# @option --dry-run Print the launch line and exit 0 without creating a worktree or starting hcom.
# @env HCOM_DIR The program's private hcom store (default: ~/.local/state/hcom/<slug>, regime-env).
# @env HCOM_TEAM The team thread (default: the repository slug, regime-env); passed to the seat as --hcom-team.

# @example
#   HCOM_DIR=/path/to/.hcom scripts/orchestrator/hcom-seat worker --name worker-2 --dry-run
set -euo pipefail

# @description Refuse to run unless this file's sha256 equals its pin in the manifest beside it (regime-cutover U31):
#   `~/.agents/agent-config.yaml` for the installed copy under ~/.local/bin/common, which a sandboxed session cannot
#   write, else the checkout's home/dot_agents/agent-config.yaml. Every read is checked; a failure exits 2 naming the
#   file. The pin is the `claude.levers.sha256.<name>` line, which `scripts/generate-agent-configs.py` refreshes.
# @set LEVER_MANIFEST The manifest the pin came from.
# @set LEVER_DIR The physical directory of this file, where the sourced regime-env helper sits (U33).
lever_self_check() {
    local src dir self name pin digest home
    # The directory is split from the path in the shell, so no external producer (dirname) can fail unseen.
    src=${BASH_SOURCE[0]}
    case ${src} in
    */*) dir=${src%/*} ;;
    *) dir=. ;;
    esac
    [[ -n ${dir} ]] || dir=/
    dir=$(cd "${dir}" && pwd -P) || {
        echo "${src##*/}: refused: cannot resolve the script directory of ${src}" >&2
        exit 2
    }
    self=${dir}/${BASH_SOURCE[0]##*/}
    # shellcheck disable=SC2034 # read by the levers that source regime-env from this directory
    LEVER_DIR=${dir}
    name=${self##*/}
    home=$(cd "${HOME}" 2> /dev/null && pwd -P) || home=''
    if [[ -n ${home} && ${dir} == "${home}/.local/bin/common" ]]; then # lint-comparisons: allow both sides are pwd -P forms
        LEVER_MANIFEST=${HOME}/.agents/agent-config.yaml
    else
        LEVER_MANIFEST=${dir}/../../home/dot_agents/agent-config.yaml
    fi
    [[ -r ${LEVER_MANIFEST} ]] || {
        echo "${name}: refused: manifest unreadable: ${LEVER_MANIFEST}" >&2
        exit 2
    }
    pin=$(sed -n -E "s/^      ${name//./\\.}: ([0-9a-f]{64})\$/\\1/p" "${LEVER_MANIFEST}") || {
        echo "${name}: refused: cannot read ${LEVER_MANIFEST}" >&2
        exit 2
    }
    [[ ${pin} =~ ^[0-9a-f]{64}$ ]] || {
        echo "${name}: refused: no single sha256 pin for ${name} in ${LEVER_MANIFEST}" >&2
        exit 2
    }
    if command -v sha256sum > /dev/null; then
        digest=$(sha256sum < "${self}") || digest=''
    else
        digest=$(shasum -a 256 < "${self}") || digest=''
    fi
    digest=${digest%% *}
    [[ ${digest} =~ ^[0-9a-f]{64}$ ]] || {
        echo "${name}: refused: cannot hash ${self}" >&2
        exit 2
    }
    [[ ${digest} == "${pin}" ]] || {
        echo "${name}: refused: sha256 ${digest} of ${self} differs from the pin in ${LEVER_MANIFEST}" >&2
        exit 2
    }
}
lever_self_check

usage='usage: hcom-seat <orchestrator|worker> [--name <name>] [--seats-root <dir>] [--ext <dir>]... [--dry-run]'
refuse() {
    echo "hcom-seat: $*" >&2
    exit 2
}

(($# >= 1)) || refuse "${usage}"
role=$1
shift
name=${role} seats_root='' dry_run=0 user_exts=()
while (($#)); do
    case $1 in
    --dry-run) dry_run=1 ;;
    --name | --seats-root | --ext)
        (($# >= 2)) || refuse "${usage}"
        case $1 in
        --name) name=$2 ;;
        --seats-root) seats_root=$2 ;;
        --ext) user_exts+=("$2") ;;
        esac
        shift
        ;;
    *) refuse "${usage}" ;;
    esac
    shift
done

bridge=${HOME}/.local/lib/omp-extensions/pi-claude-bridge
siwc=${HOME}/.agents/omp/extensions/openai-siwc
gate=${HOME}/.agents/omp/hooks
# The extension the role's model route needs first, the optional one second.
case ${role} in
orchestrator | worker) exts=("${bridge}" "${siwc}") ;;
*) refuse "unknown role '${role}'; expected orchestrator or worker" ;;
esac
[[ ${name} =~ ^[a-z0-9][a-z0-9_-]{0,63}$ ]] || refuse "name '${name}' is outside ^[a-z0-9][a-z0-9_-]{0,63}\$"
# HCOM_DIR, HCOM_TEAM and the seats root come from the environment when set, else from this checkout (regime-env,
# regime-cutover U33). hcom passes HCOM_DIR into the seat but not HCOM_TEAM, so the team rides --hcom-team below.
[[ -r ${LEVER_DIR}/regime-env ]] || refuse "regime-env unreadable beside this script: ${LEVER_DIR}/regime-env"
# shellcheck source=scripts/orchestrator/regime-env
. "${LEVER_DIR}/regime-env"
regime_env hcom-seat || exit 2
command -v hcom > /dev/null || refuse 'hcom not found on PATH'
[[ ${HCOM_TEAM:-} =~ ^[a-z0-9][a-z0-9_-]{0,63}$ ]] || refuse "team '${HCOM_TEAM:-}' is outside ^[a-z0-9][a-z0-9_-]{0,63}\$"
policy=${HOME}/.agents/omp/policies/${role}.yml
profile=${HOME}/.agents/omp/profiles/${role}.yml
[[ -f ${policy} ]] || refuse "policy overlay absent: ${policy}"
[[ -f ${profile} ]] || refuse "profile overlay absent: ${profile}"
rules=${HOME}/.agents/omp/rules/${role}.md
[[ -f ${rules} && -s ${rules} ]] || refuse "standing rules absent or empty: ${rules}"
if ((${#user_exts[@]})); then
    exts=("${user_exts[@]}")
elif [[ ! -d ${exts[1]} ]]; then
    exts=("${exts[0]}")
fi
# The stop gate rides every launch, after the route's extensions; --ext never drops it (U33c).
exts+=("${gate}")
# The extension allow-list (regime-cutover U31): claude.levers.extensions in the manifest the self-check read, so the
# installed copy reads it from ~/.agents, outside every sandbox write root. A read failure is a refusal, not an empty list.
allowed=$(awk '
    /^  levers:$/ { levers = 1; next }
    levers && /^  [^ ]/ { levers = 0 }
    levers && /^    extensions:$/ { list = 1; next }
    list && /^      - / { sub(/^      - /, ""); print; next }
    list { list = 0 }
' "${LEVER_MANIFEST}") || refuse "cannot read the extension allow-list in ${LEVER_MANIFEST}"
[[ -n ${allowed} ]] || refuse "no extension allow-list (claude.levers.extensions) in ${LEVER_MANIFEST}"
# The launch passes the canonical allow-list entry (`pwd -P` of the listed path), never the caller's spelling: a
# symlink the caller controls could be swapped between this check and omp resolving `-e`.
checked=()
for ext in "${exts[@]}"; do
    [[ -d ${ext} ]] || refuse "extension directory absent: ${ext}"
    real=$(cd "${ext}" && pwd -P) || refuse "cannot resolve extension directory: ${ext}"
    listed=''
    while IFS= read -r entry; do
        entry=${entry/#\~/${HOME}}
        # An entry that is absent or cannot be resolved lists nothing, so the extension stays refused.
        [[ -d ${entry} ]] || continue
        entry_real=$(cd "${entry}" && pwd -P) || continue
        if [[ ${entry_real} == "${real}" ]]; then listed=${entry_real}; fi # lint-comparisons: allow both sides are pwd -P forms
    done <<< "${allowed}"
    [[ -n ${listed} ]] || refuse "extension directory is not in the allow-list (claude.levers.extensions): ${ext}"
    checked+=("${listed}")
done
exts=("${checked[@]}")
repo=$(git rev-parse --show-toplevel 2> /dev/null) || refuse 'run hcom-seat inside the repository checkout'
common=$(git rev-parse --path-format=absolute --git-common-dir) || refuse "cannot read the git common directory of ${repo}"
seats_root=${seats_root:-${REGIME_SEATS_ROOT:-}}
[[ -n ${seats_root} ]] || refuse 'no seats root: pass --seats-root or run inside a checkout'
case ${role} in
orchestrator) dir=${repo} ;;
*) dir=${seats_root}/${name} ;;
esac

argv=(hcom omp --tag "${name}" --dir "${dir}" --terminal herdr --go -- --profile "${role}" --config "${policy}" --config "${profile}" --append-system-prompt "${rules}")
for ext in "${exts[@]}"; do
    argv+=(-e "${ext}")
done
argv+=(--hcom-team "${HCOM_TEAM}")
if ((dry_run)); then
    printf '%q ' "${argv[@]}"
    echo
    echo "hcom-seat: environment HCOM_DIR=${HCOM_DIR} HCOM_TEAM=${HCOM_TEAM:-}" >&2
    exit 0
fi
# U37: a remote seat host needs this host's own login first (seat-login-preflight beside this file).
"${BASH_SOURCE[0]%/*}/seat-login-preflight" "${role}" || exit $?
if [[ ! -e ${dir} ]]; then
    # A repository without a remote (a fresh project) seats its worktrees at HEAD instead of origin/main. Only a
    # genuinely absent ref means that: a ref that is broken or names no commit, or a failed git, is a refusal.
    origin_main=$(git -C "${repo}" for-each-ref --format='%(objecttype)' refs/remotes/origin/main 2>&1) ||
        refuse "cannot inspect refs/remotes/origin/main in ${repo}: ${origin_main}"
    case ${origin_main} in
    commit) base=origin/main ;;
    '')
        base=HEAD
        echo "hcom-seat: origin/main is absent in ${repo}; the seat worktree starts at HEAD" >&2
        ;;
    *) refuse "refs/remotes/origin/main in ${repo} does not resolve to a commit: ${origin_main}" ;;
    esac
    git -C "${repo}" worktree add --detach "${dir}" "${base}"
elif ! seat_common=$(git -C "${dir}" rev-parse --path-format=absolute --git-common-dir 2> /dev/null) ||
    ! [[ -d ${dir} && ${seat_common} -ef ${common} ]]; then
    # A stale or foreign directory at the seat path would seat omp in the wrong tree.
    refuse "seat directory exists and is not a worktree of ${repo}: ${dir}"
fi
# U66 (F005): omp 18.11.3 merges the cwd's .omp/config.yml and .omp/settings.json at start whatever disabledProviders
# says (the list binds only after settings load; measured under a scratch HOME), so a seat never starts in a directory
# that holds .omp. The profile overlay's disabledProviders (native and the other project-code providers) keeps the
