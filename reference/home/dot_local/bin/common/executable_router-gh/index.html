    home/dot_local/bin/common/executable_router-gh¶

    Regime-cutover U353 (M-26 stage B), U353b and U353c. Upstream's deployment guide gives the Router a gh wrapper whose GH_CONFIG_DIR is the agent account's own directory (docs/006-deployment.md "Agent GitHub account", gh-agent), and the Router's GitHub Source names it as its cli (src/sources/github.ts:46-47): the Router acts as the account that wrapper is signed in to, and the Executor calls it as gh. This file is that wrapper for the kit. The login lives in <DSH_HOME>/router-credentials/gh/hosts.yml: the credential root is the one directory the router role of hcom-seat reads beyond the dsh row's grants (allowRead row 7, held like the state root and made 0700 by the launch), every other role denies it for read, and no role writes it (the login is the operator's step, docs/engagement-handout.md: gh auth login --insecure-storage under that GH_CONFIG_DIR; the Keychain stays reachable under srt, and the file-only token source below keeps gh off it). DSH_HOME is the one hcom-seat exports into the Router (its held physical form); unset, ~/.dsh as the kit's default. DSH_HOME, the root, its gh/ and the hosts.yml inside are held as one chain, top-down, each component by its own test before anything is read (U353c, the shape of seat-login-preflight's claude_config_validate; U490f makes DSH_HOME the first component): no link, the three directories this user's, DSH_HOME searchable and read physically (pwd -P), the root read physically inside it and gh/ resolving inside the root, the leaf a regular file of this user; a link, a file in a directory's place, a directory in the file's place, or a directory this user cannot search or resolve refuses (exit 2) before gh runs, and an absent component refuses with exit 3 (U490e, below). No component's absence is claimed before its parent has passed in full: -e is false both for a missing entry and for an entry under a directory this user cannot search, so round 5 called an existing root under a DSH_HOME of mode 000 absent (verdict U490-f6175c44 P1). DSH_HOME itself has no "absent" form: the kit makes it (home/dot_dsh) and every launch holds it, so each failed test on it is exit 2. The chain stands on one text rule, held before any file test (U490g): DSH_HOME's spelling passes the levers' one clean-path grammar, clean_path below, the regular expression of hcom-seat's require_clean_path (absolute; every component of [A-Za-z0-9._@+-]; none empty, . or ..; so no repeated or trailing /), because the shell resolves a trailing / before -L tests the entry, so /path/to/link/ passed round 6's link test and ran gh through the linked root (verdict U490-34bb6fe7 P1 :135); any other spelling is exit 2 naming DSH_HOME and the grammar, and the file tests run on the clean text alone. gh resolves a credential as GH_TOKEN, then the config directory's hosts.yml, then the host-wide Keychain on macOS (gh help environment; verdict U353-8791100f P1 :97): GH_CONFIG_DIR alone let an empty root authenticate as the operator's own Keychain login, since srt permits securityd. So this wrapper is the only credential source gh sees: it reads the oauth_token: of github.com from <root>/gh/hosts.yml itself (a regular file of this user, no link, readable by this user alone as gh auth login writes it; the row at the github.com: block's own depth, exactly one, since gh 2.40 and later repeats each account's row deeper under users:, which is never read (U353c); its value inside [A-Za-z0-9_]; each else refused by name and no gh run, the value never printed) and runs gh with GH_TOKEN set to it and GH_CONFIG_DIR the root's gh/, so the Keychain is never consulted and an absent or empty login is a refusal, never a fallback. The caller's GH_TOKEN, GITHUB_TOKEN, GH_ENTERPRISE_TOKEN and GITHUB_ENTERPRISE_TOKEN are replaced or removed first, so the account is the credential root's login and never a value of the caller's environment (the Router's setup removes them too, docs/006-deployment.md "Setup checks"); GH_HOST is removed so the host is github.com. gh is resolved from the caller's PATH (type -P, inside the sandbox the seat's PATH), and an absent gh refuses by name. Every other argument reaches gh verbatim.

# @file router-gh
# @brief The dsh-superagent Router's GitHub CLI: `gh` signed in as the agent account alone, with the token read from the login under the Router's credential root.
# @description
#   Regime-cutover U353 (M-26 stage B), U353b and U353c. Upstream's deployment guide gives the Router a `gh` wrapper whose
#   `GH_CONFIG_DIR` is the agent account's own directory (docs/006-deployment.md "Agent GitHub account", `gh-agent`), and
#   the Router's GitHub Source names it as its `cli` (`src/sources/github.ts:46-47`): the Router acts as the account that
#   wrapper is signed in to, and the Executor calls it as `gh`. This file is that wrapper for the kit. The login lives in
#   `<DSH_HOME>/router-credentials/gh/hosts.yml`: the credential root is the one directory the router role of `hcom-seat`
#   reads beyond the dsh row's grants (allowRead row 7, held like the state root and made 0700 by the launch), every
#   other role denies it for read, and no role writes it (the login is the operator's step, docs/engagement-handout.md:
#   `gh auth login --insecure-storage` under that `GH_CONFIG_DIR`; the Keychain stays reachable under srt, and the file-only
#   token source below keeps gh off it). `DSH_HOME` is the one `hcom-seat` exports into the Router (its held physical form); unset,
#   `~/.dsh` as the kit's default. `DSH_HOME`, the root, its `gh/` and the `hosts.yml` inside are held as one chain, top-down,
#   each component by its own test before anything is read (U353c, the shape of seat-login-preflight's
#   claude_config_validate; U490f makes `DSH_HOME` the first component): no link, the three directories this user's,
#   `DSH_HOME` searchable and read physically (`pwd -P`), the root read physically inside it and `gh/` resolving inside
#   the root, the leaf a regular file of this user; a link, a file in a directory's place, a directory in the file's
#   place, or a directory this user cannot search or resolve refuses (exit 2) before `gh` runs, and an absent component
#   refuses with exit 3 (U490e, below). No component's absence is claimed before its parent has passed in full: `-e` is
#   false both for a missing entry and for an entry under a directory this user cannot search, so round 5 called an
#   existing root under a `DSH_HOME` of mode 000 absent (verdict U490-f6175c44 P1). `DSH_HOME` itself has no "absent"
#   form: the kit makes it (home/dot_dsh) and every launch holds it, so each failed test on it is exit 2. The chain
#   stands on one text rule, held before any file test (U490g): `DSH_HOME`'s spelling passes the levers' one clean-path
#   grammar, `clean_path` below, the regular expression of `hcom-seat`'s `require_clean_path` (absolute; every
#   component of `[A-Za-z0-9._@+-]`; none empty, `.` or `..`; so no repeated or trailing `/`), because the shell
#   resolves a trailing `/` before `-L` tests the entry, so `/path/to/link/` passed round 6's link test and ran `gh`
#   through the linked root (verdict U490-34bb6fe7 P1 `:135`); any other spelling is exit 2 naming `DSH_HOME` and the
#   grammar, and the file tests run on the clean text alone.
#   gh resolves a credential as `GH_TOKEN`, then the config directory's `hosts.yml`, then the host-wide Keychain on
#   macOS (`gh help environment`; verdict U353-8791100f P1 `:97`): `GH_CONFIG_DIR` alone let an empty root authenticate
#   as the operator's own Keychain login, since srt permits securityd. So this wrapper is the only credential source gh
#   sees: it reads the `oauth_token:` of `github.com` from `<root>/gh/hosts.yml` itself (a regular file of this user, no
#   link, readable by this user alone as `gh auth login` writes it; the row at the `github.com:` block's own depth,
#   exactly one, since gh 2.40 and later repeats each account's row deeper under `users:`, which is never read (U353c);
#   its value inside [A-Za-z0-9_]; each else refused by name and no `gh` run, the value never printed) and runs `gh` with
#   `GH_TOKEN` set to it and `GH_CONFIG_DIR` the root's `gh/`, so the Keychain is never consulted and an absent or
#   empty login is a refusal, never a fallback. The caller's `GH_TOKEN`, `GITHUB_TOKEN`, `GH_ENTERPRISE_TOKEN` and
#   `GITHUB_ENTERPRISE_TOKEN` are replaced or removed first, so the account is the credential root's login and never a

# @description Two refusal codes (regime-cutover U490e). Exit 3 is "not yet": the credential root, its `gh/` or its
#   `hosts.yml` is absent (neither a link nor an entry), or `hosts.yml` names no `oauth_token:` row for github.com at
#   the block's own depth; the agent account's login is the operator's pending step (docs/engagement-handout.md step 2)
#   and nothing is broken. Exit 2 is every other refusal: a broken or unreadable root (a link anywhere in the chain, a
#   wrong owner or mode, a root that cannot be resolved, two rows, a value outside the grammar), a `DSH_HOME` whose
#   spelling is outside the clean-path grammar (U490g), is a link, is not a directory of this user, or cannot be
#   searched or resolved (U490f), an absent `gh`, the self-check. One caller reads the two codes: `check_router_token`
#   in scripts/check-tools.sh (the doctor), an optional warning for 3 and a required failure for 2, with no path test of
#   its own; the Router reads `gh`'s status alone. Both codes print one line on stderr, the same form.
# @description Refuse to run unless this file's sha256 equals its pin in the manifest beside it (regime-cutover U31):
#   `~/.agents/agent-config.yaml` for the installed copy under ~/.local/bin/common, which a sandboxed session cannot
#   write, else the checkout's home/dot_agents/agent-config.yaml. Every read is checked; a failure exits 2 naming the
#   file. The pin is the `claude.levers.sha256.<name>` line, which `scripts/generate-agent-configs.py` refreshes.
# @arg $@ string gh's arguments, verbatim.
# @exitcode 2 The self-check, `DSH_HOME`, the credential root, its gh directory, the login file or `gh` refused: broken, not pending.
# @exitcode 3 No login yet: the credential root, its gh directory or the login file is absent, or the login file names no active github.com login; the operator's step.
# @exitcode * gh's own status.
# @example
#   DSH_HOME=~/.dsh router-gh api user --jq .login
set -u

lever_self_check() {
    local src dir self name pin digest home
    # The directory is split from the path in the shell, so no external producer (dirname) can fail unseen.
    src=${BASH_SOURCE[0]}
    case ${src} in
    */*) dir=${src%/*} ;;
    *) dir=. ;;
    esac
    [[ -n ${dir} ]] || dir=/
    dir=$(cd "${dir}" && pwd -P) || {
        echo "${src##*/}: refused: cannot resolve the script directory of ${src}" >&2
        exit 2
    }
    self=${dir}/${BASH_SOURCE[0]##*/}
    name=${self##*/}
    home=$(cd "${HOME}" 2> /dev/null && pwd -P) || home=''             # producer-status: allow the if below takes an empty home as the checkout layout
    if [[ -n ${home} && ${dir} == "${home}/.local/bin/common" ]]; then # lint-comparisons: allow both sides are pwd -P forms
        LEVER_MANIFEST=${HOME}/.agents/agent-config.yaml
    else
        LEVER_MANIFEST=${dir}/../../home/dot_agents/agent-config.yaml
    fi
    [[ -r ${LEVER_MANIFEST} ]] || {
        echo "${name}: refused: manifest unreadable: ${LEVER_MANIFEST}" >&2
        exit 2
    }
    pin=$(sed -n -E "s/^      ${name//./\\.}: ([0-9a-f]{64})\$/\\1/p" "${LEVER_MANIFEST}") || {
        echo "${name}: refused: cannot read ${LEVER_MANIFEST}" >&2
        exit 2
    }
    [[ ${pin} =~ ^[0-9a-f]{64}$ ]] || {
        echo "${name}: refused: no single sha256 pin for ${name} in ${LEVER_MANIFEST}" >&2
        exit 2
    }
    if command -v sha256sum > /dev/null; then
        digest=$(sha256sum < "${self}") || digest='' # producer-status: allow the regex test below refuses an empty digest
    else
        digest=$(shasum -a 256 < "${self}") || digest='' # producer-status: allow the regex test below refuses an empty digest
    fi
    digest=${digest%% *}
    [[ ${digest} =~ ^[0-9a-f]{64}$ ]] || {
        echo "${name}: refused: cannot hash ${self}" >&2
        exit 2
    }
    [[ ${digest} == "${pin}" ]] || {
        echo "${name}: refused: sha256 ${digest} of ${self} differs from the pin in ${LEVER_MANIFEST}" >&2
        exit 2
    }
}
lever_self_check

# @description Print the refusal on stderr and exit 2: a broken or unreadable root, never the pending step.
# @arg $1 string The reason.
refuse() {
    echo "router-gh: $1" >&2
    exit 2
}

# @description Print the refusal on stderr, the same form, and exit 3: the login is not yet in place, the operator's
#   step (U490e); read by the doctor as an optional warning where exit 2 is a required failure.
# @arg $1 string The reason.
refuse_absent() {
    echo "router-gh: $1" >&2
    exit 3
}

# @description Succeed when `$1` is a clean absolute path, the one grammar every lever holds a path's text to before a
#   file test (regime-cutover U490g; the regular expression of `hcom-seat`'s `clean_path`, copied, not imported, so no
#   other lever is read): `/` followed by components of `[A-Za-z0-9._@+-]` only (no glob metacharacter `*?[]{}`, no
#   whitespace, no quote or backslash), none of them empty, `.` or `..`, and no trailing `/`. The shell resolves a
#   trailing `/` before `[[ -L ]]` tests the entry, so a link spelled `/path/to/link/` is no link to `-L`; on a clean
#   spelling the file tests of the chain judge the entry the text names.
# @arg $1 string The path.
# @exitcode 0 The path is clean.
# @exitcode 1 The path is not clean.
clean_path() {
    [[ $1 =~ ^(/[A-Za-z0-9._@+-]+)+$ ]] || return 1
    [[ /$1/ != */./* && /$1/ != */../* ]] # lint-comparisons: allow a component test on one path, no path compare
}

[[ -O ${root} ]] || refuse "the credential root ${root} is not this user's directory"
root_phys=$(cd "${root}" 2> /dev/null && pwd -P) || refuse "cannot resolve the credential root ${root}" # cd's own message is dropped: the refusal is the one stderr line (U490e)
gh_real=$(type -P gh) || refuse "gh not found on PATH"
gh_dir=${root_phys}/gh
[[ ! -L ${gh_dir} ]] || refuse "${gh_dir} is a symbolic link; the login directory must be a real directory inside the credential root"
[[ -e ${gh_dir} ]] || refuse_absent "no gh login under the credential root: ${gh_dir} is absent; the agent account's login inside the root is the operator's step (docs/engagement-handout.md), and gh runs with no other credential"
[[ -d ${gh_dir} ]] || refuse "${gh_dir} is not a directory; the login directory must be a real directory inside the credential root"
[[ -O ${gh_dir} ]] || refuse "${gh_dir} is not this user's directory"
gh_phys=$(cd "${gh_dir}" 2> /dev/null && pwd -P) || refuse "cannot resolve the login directory ${gh_dir}"
[[ ${gh_phys} == "${root_phys}/gh" ]] || refuse "the login directory ${gh_dir} resolves to ${gh_phys}, outside the credential root" # lint-comparisons: allow both sides are pwd -P forms, the hold of the chain
hosts=${gh_dir}/hosts.yml
[[ ! -L ${hosts} ]] || refuse "${hosts} is a symbolic link; the login must be a regular file inside the credential root"
[[ -e ${hosts} ]] || refuse_absent "no gh login under the credential root: ${hosts} is absent; the agent account's login inside the root is the operator's step (docs/engagement-handout.md), and gh runs with no other credential"
[[ -f ${hosts} ]] || refuse "${hosts} is not a regular file; the login must be a regular file inside the credential root"
[[ -O ${hosts} ]] || refuse "${hosts} is not this user's file"
os=$(/usr/bin/uname -s) || refuse 'cannot read the operating system name (uname -s)'
case ${os} in
Darwin) mode=$(/usr/bin/stat -f %Lp "${hosts}") || refuse "cannot read the mode of ${hosts}" ;;
*) mode=$(/usr/bin/stat -c %a "${hosts}") || refuse "cannot read the mode of ${hosts}" ;;
esac
[[ ${mode} =~ ^[0-7]00$ ]] || refuse "${hosts} has mode ${mode}; the login must be readable by this user alone (0600)"
# The value: the `oauth_token:` row of the `github.com:` block at the block's own depth, exactly one, read by the shell
# alone (no external reader sees it) and held to the grammar gh's tokens use; no message prints it. gh 2.40 and later
# writes the active account's rows at the block's depth and every account's `oauth_token:` again under `users:`,
# deeper (verdict U353b-9c504ad9 P1 `:127`: an indentation-blind match counted both and refused one login), so the
# depth is measured from the first row inside the block and a deeper row is never read.
hosts_text=$(< "${hosts}") || refuse "cannot read ${hosts}"
oauth_value='' oauth_rows=0 in_host=0 depth='' rest=${hosts_text}
while [[ -n ${rest} ]]; do
    line=${rest%%$'\n'*}
    if [[ ${rest} == *$'\n'* ]]; then rest=${rest#*$'\n'}; else rest=''; fi
    trimmed=${line%"${line##*[![:space:]]}"}
    case ${trimmed} in
    '') ;;                             # a blank line is no row of the block
    github.com:) in_host=1 depth='' ;; # lint-comparisons: allow the host key of gh's hosts.yml, a YAML mapping key, not a URL
    [![:space:]]*) in_host=0 ;;
    *)
        ((in_host)) || continue
        indent=${trimmed%%[![:space:]]*}
        [[ -n ${depth} ]] || depth=${indent}
        if [[ ${indent} == "${depth}" ]] && [[ ${trimmed} =~ ^[[:space:]]+oauth_token:[[:space:]]*(.*)$ ]]; then
            value=${BASH_REMATCH[1]}
            case ${value} in
            \"*\" | \'*\') value=${value:1:${#value}-2} ;;
            esac
            oauth_value=${value} oauth_rows=$((oauth_rows + 1))
        fi
        ;;
    esac
done
if ((oauth_rows == 0)); then
    refuse_absent "${hosts} names no active login for github.com: no oauth_token row at the host block's own depth (the rows under users: are not read); the agent account's login inside the root is the operator's step (docs/engagement-handout.md)"
elif ((oauth_rows != 1)); then
    refuse "${hosts} names ${oauth_rows} oauth_token rows for github.com at the host block's own depth; exactly one is read"
fi
[[ ${oauth_value} =~ ^[A-Za-z0-9_]+$ ]] || refuse "the oauth_token of github.com in ${hosts} is empty or outside [A-Za-z0-9_]"
# The account is the credential root's login alone: no token or host of the caller's environment reaches gh, and with
# GH_TOKEN set gh reads no store (`gh help environment`: the variable takes precedence over stored credentials).
unset GITHUB_TOKEN GH_ENTERPRISE_TOKEN GITHUB_ENTERPRISE_TOKEN GH_HOST
GH_TOKEN=${oauth_value} GH_CONFIG_DIR=${root_phys}/gh exec "${gh_real}" "$@"
