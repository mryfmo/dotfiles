## 3. 調査面の不足と対応

| 不足 | 対応（詳細は 02_RESEARCH_AND_DECISIONS.md） |
|---|---|
| PRD の根拠が Atlassian の1件だけ。しかも同資料は簡潔な1ページを勧めており、16節の重いテンプレートと逆 | 必須11節＋任意4節に再編し、小さな変更は必須節だけで済むようにした |
| 要求文の書き方に根拠が無い | EARS（考案者の公式解説）を採用。AI 向けの仕様駆動開発ツールでも標準的に使われていることを確認 |
| ADR が MADR を「参考にした独自拡張」とし、実際の構成と対応していない | MADR 4.0.0 の節構成と front matter に対応させ、Microsoft の指針（追記専用・確信度・状態）を反映 |
| Markdown と Gherkin の関係を独自に定めている | Cucumber 公式の Markdown with Gherkin を調査。JavaScript 実装だけの対応のため不採用とし、理由を記録 |
| Mermaid は 11.12.2 だけで確認。12.0.0 で既定のレイアウトと見た目が変わる | 11.14.0 と 12.0.0 の両方で描画を確認し、注意点を規約に記載 |
| Gherkin のキーワード言語を根拠なく英語に固定 | 日本語キーワード（ルールを含む）が公式 parser で有効なことを確認し、業務側が読む文書として日本語を既定に変更 |

## 4. 元キットの良い点（維持したもの）

「文書がある・構文が通る・実装が動く・課題が解決する」を別の状態として扱う姿勢、架空の承認や実績を書かない方針、BDD と専用検証（NVT）の併用、検査器自身の変異試験、未実施事項の明示。これらは是正版でも維持している。

## 5. このレビューの限界

サンプルの業務内容（FlowApprove）は架空で、実在の業務責任者による妥当性確認は受けていない。意味の十分性（シナリオが業務上足りているか）は機械検査の対象外である。出典のうち今回再確認していないものは 02 に明示した。
