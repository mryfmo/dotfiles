    Seat logins on a remote host¶

    regime-cutover U37. The laptop (macOS: Ghostty, herdr, omp) reaches the Ubuntu host with herdr --remote <ssh-target> over SSH inside the tailnet. omp seats run on Ubuntu, but the Claude and ChatGPT sign-ins end in a browser consent, and the browser is on the laptop. A login is per host: each host signs in once, keeps its own tokens and refreshes them, and nothing copies a token between hosts. SIWC refresh tokens rotate, so one session cannot serve two hosts. The human acts are the consent click and, for Claude, pasting a code.

    Routes¶

    Route Login record on the seat host Browserless flow
    ChatGPT (openai-siwc, the audit profile) ~/.omp/profiles/<profile>/agent/openai-siwc/registration.json (host id and issued client id, no token) and the profile's agent.db (tokens) The callback is a 127.0.0.1 loopback, the only redirect SIWC allows. OPENAI_SIWC_CALLBACK_PORT=1455 pins it, and the laptop's LocalForward 1455 127.0.0.1:1455 carries the browser's redirect to the seat host's listener.
    Claude (claude-bridge, the orchestrator and worker profiles; every seat's bridge child and the dsh role's gateway child run under their login group's CLAUDE_CONFIG_DIR, U318, one directory per group since U498) <seats-root>/.state/claude-<group> (~/.local/state/omp-seats/<slug>/.state/claude-<group>, a 0700 directory the kit makes; the group is the role table's login_group_of_role, the same text in hcom-seat and the pre-flight: worker, orchestrator and audit each their own, router for the dsh and router roles): one claude.ai login per group per host, stored and refreshed by Claude Code itself (the Keychain item keyed to that directory on macOS, its .credentials.json 0600 there on Linux), so two groups rotate no refresh token together; never the operator's ~/.claude, the Keychain item of the default directory or a CLAUDE_CODE_OAUTH_TOKEN (U312: no shell exports one, and a variable in the environment is no input); the legacy shared .state/claude (U318) is read by no seat BROWSER=regime-open-url CLAUDE_CONFIG_DIR=<dir> claude auth login on the seat host, the command the pre-flight prints for the group: the callback port is random, so the laptop browser shows a code to paste at the prompt. Once per running group per host; CLAUDE_CONFIG_DIR=<dir> claude auth logout revokes it.

    The URL reaches the laptop browser through regime-open-url on the seat host. It posts the URL over RemoteForward 127.0.0.1:1456 127.0.0.1:1456 to regime-url-opener, a launchd agent on the laptop, which opens allow-listed sign-in hosts only.

    Pieces¶

    • home/private_dot_ssh/private_config.tmpl: on macOS only, Match tagged seat-host adds the two forwards. The operator's own host entry in ~/.ssh/conf.d/ carries Tag seat-host, so no machine name enters this public repository (README "Private credentials and keys"). A second session to the same host only warns that a port is taken. The Linux render is the old file, byte for byte.
    • regime-url-opener (laptop, ~/Library/LaunchAgents/com.mryfmo.dotfiles.url-opener.plist) and regime-open-url (seat host). launchd opens an agent's output files before the program runs, and a fresh home has no log directory, so the agent's stdout and stderr are /dev/null; the opener creates its log's parent itself and records its start, a failed bind and every request there.
    • seat-login-preflight (scripts/orchestrator/, installed to ~/.local/bin/common/, pinned in claude.levers.sha256). With --check it backs the "Seat logins" section of make doctor from metadata only. Given a seat profile (orchestrator, worker or audit), it checks that a seat can use the login: an openai-siwc login stored in the profile's agent.db, counted by the extension's src/credentials.ts without reading a token, and for Claude, on every host, a claude.ai login under the profile's login group directory <seats-root>/.state/claude-<group> (U498: the group from the one table login_group_of_role, held as the same text by hcom-seat; worker, orchestrator, audit, and router for the dsh overlay, whose gateway child is the Router's), read by one call, CLAUDE_CONFIG_DIR=<dir> claude auth status (its exit status and its JSON authMethod; U318). The seats root is REGIME_SEATS_ROOT when set (hcom-seat passes its resolved one), else the checkout's ~/.local/state/omp-seats/<slug>. A token variable in the environment is no input (U312), and the operator's ~/.claude is never read. An absent login prints the one operator command for the group, with BROWSER=regime-open-url in an SSH session, and names the legacy shared .state/claude (U318) when it exists and the group's directory did not (the kit reads, copies and removes no login, standing order 54); the profile mode makes the group's directory 0700 first. hcom-seat runs it with the seat's role before it creates or starts anything.
    • openai-siwc: OPENAI_SIWC_CALLBACK_PORT and src/seed.ts, which seeds a registration with the laptop's issued client id and a fresh host id, so the ChatGPT account shows one client with one host per machine. The seat host still signs in once.
    • ~/.zshenv and ~/.profile: export nothing of a token (U312). Until then they exported CLAUDE_CODE_OAUTH_TOKEN from a token file into every zsh and every login shell, so on a host that held the file the operator's interactive Claude Code, its hooks and every child process logged in with the seat token instead of the host's claude.ai login and lost the claude.ai connectors (measured on the laptop, 2026-11-06). Since U318 no seat reads a token at all: the seats log in by the shared directory's claude.ai login, which Claude Code refreshes itself, so there is no yearly token and no file to copy between hosts. The managed Claude settings still deny the variable (sandbox.credentials.envVars) and the retired token file (sandbox.credentials.files) to sandboxed commands, as defence in depth (U68).

    Measurements (2026-10-24, this laptop)¶

    • omp 18.11.3 ignores BROWSER. openPath runs open <url> on macOS and xdg-open <url> on Linux (src/utils/open.ts:73-87). omp login prints Open this URL in your browser: and the full URL before it opens anything (src/cli/oauth-terminal.ts:163-176). The CLI login loads extensions from settings only, not from -e: Unknown OAuth provider 'openai-siwc'. A one-command PI_CONFIG_FILES overlay naming the extension works without touching ~/.omp. In a scratch HOME, omp --profile audit login openai-siwc printed an authorize URL with redirect_uri=http%3A%2F%2F127.0.0.1%3A1455%2Fauth%2Fcallback, handed the same URL to the fake open, wrote registration.json with mode 0600, and waited for the callback.
    • Claude Code 2.1.309 honours BROWSER. Three claude auth login runs in scratch CLAUDE_CONFIG_DIRs handed https://claude.com/cai/oauth/authorize?code=true&… to a fake browser, with redirect_uri=http://localhost:50903/callback, then :50915, then :50920. The port is not fixed, so no forward can carry it, and the paste-code flow is the route.
    • The bridge child never runs in bare mode. grep -rn -- '--bare' over the installed bridge src and the five patches prints nothing, and its only extra CLI arguments are model, strict-mcp-config and thinking-display (src/index.ts, extraArgs).
    • Forwards were measured through a scratch sshd on 127.0.0.1:22337 (user-run, keys and config under $TMPDIR). A request to the client's 21455 reached a server-side listener on 1455, and the far end's 127.0.0.1:21456 reached a client-side listener on 1456. Both ports are shifted on the client side, because one host has one loopback. ssh -O check reported Master running. Match tagged seat-host gave the forwards to the tagged host only. A Unix-socket RemoteForward was mode 0600, but the socket outlived its session and the next bind failed, even with StreamLocalBindUnlink yes on macOS sshd (unix_listener: cannot bind … Address already in use). The TCP form survived three sessions in a row, so it is the one used.
    • herdr 0.9.5 has no API request that opens a given URL on the attached client. pane.link.activate takes a pane cell (pane_id, viewport_row, col), and notification show takes a title, a body and a sound. So the opener is a launchd agent, not a herdr call. herdr --remote runs the system ssh, which reads ~/.ssh/config.
    • Not measured, because each would change the live tailnet: Tailscale SSH carrying -L/-R (tailscale/tailscale #6575 and #5091 reported it did not), and tailscale serve for the opener. The forwards therefore go through OpenSSH over the tailnet. The opener stays a loopback agent behind the RemoteForward: tailscale serve would expose it to every tailnet peer until an ACL in the admin console narrowed it.

    Threat table¶

    Path or control Control Disposition
    LocalForward 1455 (SIWC callback) Loopback on both ends; only while an SSH session to the tagged host is open; OPENAI_SIWC_CALLBACK_PORT makes the seat's listener fail closed when the port is taken instead of moving to a random port. residual: any local user on the seat host can bind 127.0.0.1:1455 before the seat does and receive the authorization code. That user would also need the PKCE verifier, which only the seat's own process holds, unless the user started the flow themselves (next row). The design assumes a single-user seat host.
    RemoteForward 1456 and regime-url-opener Loopback only; https only; exact host allow-list; no user info, no port but 443; X-Regime-Open: 1 header (a cross-origin page cannot send it without a CORS preflight, which the server never answers); body of at most 8 KB; open/xdg-open with an argument list, never a shell; a log of every decision with scheme, host and path, never the query. residual: any process on the seat host that reaches 127.0.0.1:1456 while the operator's SSH session is open can make the laptop browser open an allow-listed authorize URL with its own client and challenge. That includes a process of the operator's own account, a yolo omp seat among them (it runs as the operator, and its policy does not stop a loopback POST), as well as a local user on a multi-user seat host. The consent page is the gate, and a returning sign-in may skip it, so such a process could obtain a grant the operator never read (inferred, not exercised); the decision log on the laptop records each opened host and path. Single-user seat host assumed; containing the seats (U85) is what removes the same-account case.
    regime-open-url Posts to 127.0.0.1 only, with proxies disabled; never logs the URL; on failure the caller has already printed the URL. closed: tests/unit/test_remote_host_logins.py (test_the_client_hands_the_url_to_the_opener, test_no_opener_is_a_named_failure…).
    <seats-root>/.state/claude-<group> (the login groups' directories) Made 0700 and empty by hcom-seat (every group's directory of the table's range at every launch of every role, before the seat's settings file is written, U498d) or by the pre-flight's profile mode (the profile's group's), one per login group (U498: worker, orchestrator, audit, router; the group from the one table both levers hold as the same text); a symbolic link, a file or another user's directory at any group's path refuses the launch by name (U318, U498d), so two groups share no refresh token; the login inside is Claude Code's own (the Keychain item keyed to the directory on macOS, .credentials.json 0600 on Linux), written by the operator's claude auth login under it and refreshed by Claude Code. Every seat's srt settings grant its own group's directory for write (the child's state, .claude.json, sessions and its own refresh) and deny its settings.json, settings.local.json, rules, hooks, plugins, skills, commands and agents for write, so no seat changes what another seat's child, or the operator's login command there, would load; the bridge child loads none of them anyway (settingSources: [], --strict-mcp-config). The router group's directory is one process family's: the Router's own bridge children, its dsh gateway child and its ACP subagent workers (acp-broker grants claude-router for read and write with the same eight denies, read from the Router's rendered settings, U498b) all use claude-router, one login. Every seat's settings and every ACP worker's settings deny by name, for read, every other group's directory and the legacy shared .state/claude (U498c), and each group's directory exists before the first render: hcom-seat makes the table's whole range at every launch (U498d; srt 0.0.81's Linux backend mounts nothing for a deny of a path that is not there, so until then the orchestrator's deny of .state/claude-worker bound nothing before the worker group's first launch or login, and its read grant of the seats root reached the credentials made later). No settings grant another group's directory or the legacy one, which no lever reads, grants, copies, makes or removes (standing order 54): its deny binds while it exists, and the operator removes it once every running group is logged in. The operator's ~/.claude and ~/.claude.json stay denied for read and write (U190b). No seat prints, logs or copies a credential; the shim exports the directory and clears CLAUDE_CODE_OAUTH_TOKEN. No seat and no ACP worker may take a claude-* name or claude. closed: test_every_role_gets_its_login_groups_claude_code_directory_whose_configuration_no_seat_can_change, test_every_launch_makes_every_login_groups_directory_before_its_settings_file_so_each_deny_binds (tests/unit/test_hcom_seat.py, U498d), test_the_dsh_and_router_launches_make_every_login_groups_directory_too (tests/unit/test_hcom_seat_dsh.py, U498d), test_the_login_group_table_is_one_text_in_both_levers, test_a_dry_run_names_the_login_groups_directory_in_its_environment_line, test_the_shim_exports_the_shared_directory_and_clears_a_callers_token, test_the_omp_roles_settings_are_byte_identical_to_the_earlier_heads (exactly these rows added), the dsh cases of test_the_dsh_settings_are_the_workers_but_the_named_rows, test_the_environment_reaching_dsh_is_the_listed_names_and_the_shims_exports and test_the_dsh_settings_are_byte_identical_to_the_u318_head (the router group's directory the one change), test_no_lever_or_rc_file_names_the_token_file_or_setup_token, test_the_worker_joins_the_router_login_group_and_a_login_directory_name_is_no_seat and test_the_worker_settings_are_the_dsh_row_but_the_named_rows (tests/unit/test_acp_broker.py, U498b). residual: every seat of a group shares that group's login and its refresh, which is the design (one login per group, U498); the Router's three process kinds (its bridge children, the gateway child and the ACP workers) share the router group's directory by the same design; a seat's child can read its group's .credentials.json, as it must to log in, inside its own srt boundary.
    seat-login-preflight --check and make doctor Metadata only. It reads registration.json (host id and client id, which carry no token), held to the extension's record schema as exactly one JSON document (store.ts reads it with JSON.parse, so concatenated records are unreadable), and never opens agent.db or a credentials file; for Claude it runs claude auth status under the profile's login group directory (one line per deployed profile, so one per running group, U498), without a token name in its environment, and reads one field, authMethod, held to a charset through jq; nothing else of the record reaches the terminal, and an absent directory is reported absent without a call.     seat-login-preflight <profile> (readiness and logins) Accepts the three seat profiles of omp.roles (orchestrator, worker, audit) and refuses any other name, a deployed overlay or not. A seat starts only on a login it can use: an openai-siwc login counted in agent.db (an issued client is saved before the token exchange, so a record alone proves nothing), and for the claude-bridge route, on every host (local included, U190b), a claude.ai login under the profile's login group directory (authMethod of claude auth status; an oauth_token or api_key method, an exit 1 or an absent login is absent, a token variable in the environment is no input, U312). An absent Claude login prints the operator's one command for the group, CLAUDE_CONFIG_DIR=<dir> claude auth login (after BROWSER=regime-open-url in an SSH session), names the legacy shared .state/claude when it exists and the group's directory did not (U498), and refuses (exit 2) in a TTY too: the pre-flight runs no Claude login.
